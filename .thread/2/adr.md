# Issue #2 の設計判断

## 1. 印刷用の表示は本文ドキュメントを最上位で配信する

- 状況: 閲覧画面（P-11 / P-44 / P-45）は本文を sandbox の iframe で表示している。#1 はこの本文を印刷でどう扱うかを未決にしていた
- 検討した案
  - 閲覧画面の iframe をそのまま印刷する（親ページの印刷 CSS で iframe を本文の高さに広げる）
  - 親ページから `iframe.contentWindow.print()` を呼ぶ
  - 本文を Declarative Shadow DOM で親ページに埋め込む
  - 本文ドキュメントそのものを最上位のページとして配信する
- 決定: 本文ドキュメントそのものを最上位のページ（`/notes/{id}/print`、`/p/{publicId}/1/print`、`/s/{token}/print`）として配信し、印刷操作のスクリプトだけを CSP のハッシュで許す
- 理由
  - 親ページの iframe を Chromium で印刷すると、iframe が 1 ページ目から押し出され、ページ境界で行が切断された（`agent-browser pdf` で実測）。最上位のドキュメントでは起きない
  - `contentWindow.print()` は headless で観測できず、P-44 / P-45 には親ページのスクリプトが無い
  - Shadow DOM では本文の `html` / `body` / `:root` のスタイルが当たらず、閲覧画面と見た目が変わる
- 帰結: 本文と同じ文書にスクリプトが載る。`script-src` はハッシュ 1 本に限り、`allow-same-origin` は画像取得の Cookie のために残す

## 2. 既存 DB の PDF データは移行しない

- 状況: Node の libSQL DB に PDF 生成のテーブル・ZIP の PDF 列・PDF 形式の ZIP 依頼の行・実ファイルが残り得る。#1 は libSQL を削除し、本番データを移行しない方針
- 検討した案
  - ZIP テーブルを作り直して PDF の列と CHECK の `'pdf'` まで消し、PDF の行は削除して実ファイルは削除キューで回収する
  - PDF 専用のテーブル・トリガーだけ消し、ZIP テーブルの PDF の列と CHECK は libSQL ごと消えるまで残す
  - 既存データは捨てる前提にし、マイグレーションは PDF のスキーマを消すだけにする
- 決定: 既存データは捨てる前提（ユーザー判断）。マイグレーションは PDF のスキーマ（ZIP テーブルの列と CHECK を含む）を消すだけで、行と実ファイルを回収しない。PDF 形式の ZIP 依頼の行が残る DB ではマイグレーションが失敗してよい
- 理由: Node の DB は作り直す前提で、libSQL 自体が #1 で消える層のため、データ回収に工数をかけない

## 3. 印刷できないときは入口の画面へ戻す（差分の読み 1 回目の反例 6 を受けて変更）

- 変える前: P-11 の印刷用の表示は、未サインイン・権限なし・存在しない・ゴミ箱で独自の「印刷できません」ページ（401 / 404）を返していた。本文が空のときは、ツールバーと「本文が空のため印刷できません」だけの印刷用の表示を返していた
- 変えた後: どちらも入口の画面（P-11 は `/notes/{id}`、P-44 は公開ページ、P-45 は共有リンク画面）へ 303 で戻す。P-44 / P-45 の閲覧不可は、それぞれの画面と同じ応答のまま
- 理由: 独自ページはアプリのシェルと P-46 の表示から外れ、雛形も 1 つ増えていた。入口の画面はサインイン・見つかりません・本文なしの表示をすでに持っている。本文なしの印刷用の表示は、ツールバーだけが全幅に出る崩れた画面になっていた

## 4. 導線は「印刷する」に揃え、同じタブで開き、編集画面には出さない（差分の読み 1 回目の反例 6 を受けて変更）

- 変える前: P-11 / P-12 は書き出し欄の装飾の無い文字リンク「印刷する」（新しいタブ）、P-44 はリンク列の「印刷」（同じタブ）、P-45 は書き出し欄の「印刷する」（同じタブ）
- 変えた後: どの入口もダウンロードの隣に「印刷する」を置き、同じタブで開く。P-11 の書き出し欄はアプリの他の操作と同じ `hollow-button` にする。編集画面（P-12）には出さない
- 理由: 名前・開き方・見た目が入口ごとにばらつき、P-11 の導線は本文と見分けられなかった。新しいタブでは印刷用の表示の「ノートに戻る」が元のタブへ戻らない。同じタブにすると編集画面では入力を失うため、印刷はノート詳細からに限る

## 5. ツールバーの見た目の値は `spec/design/tokens.md` から写す

- 状況: 差分の読み 1 回目が、ツールバーのスタイルがトークンの値を写していて正本が 2 つになると指摘した
- 決定: 値は写したままにする。本文幅だけは `layout.css` の `--content-max` から読む
- 理由
  - アプリにはトークンの CSS 実体が無い。`apps/web/app/styles/tokens.css` はテンプレートの値のままで、アプリの画面（`hollow.css`）も `tokens.md` の値を写している
  - ツールバーは本文の CSS を避けるため Shadow DOM の中にあり、アプリの CSS（`hollow.css` 全体）を持ち込むと本文側の文書に関係のない規則が大量に入る
- 見直す条件: アプリに `tokens.md` の CSS 実体ができたら、そこから読む
