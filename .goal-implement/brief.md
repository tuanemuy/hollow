# Hollow 実装の依頼範囲

## 元の要求

Hollow要件全体を既存テンプレートから設計・実装・独立検証する。品質目標は extremely well。元の指示は2026-09-06の `$goal-implement` と利用者の継続指示である。

要件の正本は [requirements](../spec/requirements.md)、背景は [idea](../spec/idea.md)、操作と異常系は [シナリオ](../spec/scenario/index.md)。[画面案とトークン](../spec/design/index.md)を参照する。

## 完成時の利用者体験

個人とチームがファイルをHTMLノートへ変換し、保存・編集・整理・共有できる。登録・メール確認・認証、三編集モード、タグ/検索、個人/ワークスペースの移動、三公開状態、書き出し、ジョブ履歴、OpenRouter/Drive個人連携、ロール制御を含む。

HTMLを正データとし、元ファイルも保持する。保存結果は再読込後も残り、長時間処理は画面を閉じても継続する。公開を取り下げた情報は公開URLと検索から取得できない。全体完成は必須機能とローカル契約検証・独立統合検証を満たしたときに判定する。実サービス接続の検証はgoalの完了条件に含めない。

## 制約と対象外

- CLAUDE.mdのTypeScript、Hexagonal/DDD、ポート、境界検証、React 19の応答性を守る。
- 日本語 UI。白基調・無彩色・中央一列の画面案は利用者の決定として採用する。
- 既存のユーザー変更を保持する。
- 課金/プラン/決済、多言語UI、本番公開/クラウドデプロイ、実サービスへの接続検証は対象外。
- spec/spec-implementスキルは使用しない。
- Managerが全体goalと管理文書を所有し、Implementerが実装、独立Verifierが検証する。

## 採用する仮定

次は旧 brief でエージェントの採用仮定と明示されていたものとして保持する。利用者が確定した要件には読み替えない。

- 実行基盤は macOS arm64 上の Node 参照配備。Office は DOCX/XLSX/PPTX を対応形式とし、旧 DOC/XLS/PPT を無言で変換成功にしない。
- 月間上限の詳細は UTC 暦月、intent 後の失敗/応答不明も計数、未送信を証明できた場合だけ返却。利用者が確定した月間30回と区別する。

容量・URL・検索・タグ・書き出し・認証・媒体の細かな運用値はエージェントの採用仮定であり、利用者決定とは扱わない。旧 assumptions は archive の必要な箇所だけ参照する。今回の未確定事項は末尾に置く。

## 今回の検証範囲

検証は毎回まっさらなローカル DB・objects・mailbox・鍵で行う。永続データと保全資料を OS の一時領域に置かない。失敗した検証環境は、実行結果と所在を報告に記録してから削除してよい。止めるプロセスは自分が起動したものだけ。秘密値を報告に載せず、対象外の資格情報を利用しない。

2026-10-12の利用者指示により、外部の実サービスへの接続検証はgoalから除外する。製品の連携機能とローカル契約検証は対象に残す。実サービス接続・外部操作・送信・課金・公開は今回実行しない。検証対象は main `ac0894acb78be85f8b10c3c7450fbb00a8c40561`。ブラウザ検証は Darwin arm64 / Node 22.22.3（Unicode 16.0）で行う。P00 では検証済み Node のバージョンを flake.nix に固定する。フェーズ案は利用者の修正つきで承認済み。2026-10-09 の resume.md からの継続指示により P00 から実装を再開する。resume.md は引き続きコミット対象外。

## 検証根拠

各項目は、今回実行したコマンドと結果（テスト成否・終了コード・出力要点）、ブラウザ操作と観測結果、対象のコミット ID で判断する。archive の根拠は確認の手がかりに限る。SOURCE・SHA・バイト数の照合、fence、恒久非操作 root の列挙、PID・fd の照合を通常の受け入れ手続きにしない。完了条件が照合自体を求める場合だけ、その条件に従う。

## 外部依存の検証段階

| 依存 | goal内の契約検証 | goal対象外の実接続 |
| --- | --- | --- |
| Google認証 | 代替アダプターのログイン/紐付け/失効契約 | OAuth設定とテスト利用者による実認証 |
| メール | ローカルmailboxの確認/再設定/招待契約 | 送信サービス設定と承認済み宛先での到達確認 |
| OpenRouter | 認可/モデル選択/変換/取消契約 | PKCE設定・利用者連携・費用承認を得た実変換 |
| Google Drive | 認可/backup/再生成/解除契約 | OAuth/Picker設定と明示共有folderでの実操作 |

外部依存はローカル契約検証で受け入れる。実アダプターの任意実接続コマンドと手順は将来の参考として保持するが、未実行でもgoalの完了を妨げない。契約合格を実接続成功へ読み替えない。音声の製品実装・契約検証は必須であり、実接続検証の除外だけで完了扱いしない。

音声はP11で方式調査・設計・実装・独立検証を進める。専用STT endpoint `/api/v1/audio/transcriptions` を用い、STTは `provider.data_collection=deny` と `provider.zdr=true` を必ず送る。STT schemaに無い `allow_fallbacks` / `require_parameters` は送らない。text/image/PDFのchat経路は `data_collection=deny` / `allow_fallbacks=false` / `require_parameters=true` の3条件を保持する。STTのfallback動作は仕様上未確認であり、禁止や発生無しを保証したとは扱わない。

音声モデルは既存の `stt-transcription` 種別と用途別モデル選択を使い、audio入力対応chatモデルを選択肢へ混ぜない。原本200MBに対する分割方式はmediabunny 1.55.7とFFmpegを比較する。FFmpegは本番依存に採用可能で、採用する場合はflake.nixでバージョン固定、子プロセス隔離、時間・メモリ上限を設計する。STTと本文構造化の2段を同一conversionへ載せる保存・回復契約、既定STTモデルは設計時に根拠つきで決める。旧P5b-3a0の分割プロトタイプは手がかり、STT契約報告のE節は未採用候補として参照する。

実OpenRouterへの認証付き接続・音声送信・生成・課金は行わない。検証はowned loopback providerを使い、実STTリクエストwireのdeny/zdrと、後段chatの既3条件を確認する。公開一次仕様・認証不要のcatalog/endpoints/ZDR一覧のGETは方式調査に使える。

## 利用者が確定した仕様

### 保存先の変更確認

Drive保存先が利用できない場合は、永久削除を含め必ず確認後に再選択/新規作成を案内する。ゴミ箱内と確認できた場合は復元も案内する。404/changes.removedを永久削除の証拠にせず、所在不明・権限喪失・ゴミ箱内を観測できた範囲で区別する。追加scope・自動作成・自動復元を行わない。IN-05の自動再作成よりこの利用者決定を優先する。旧記録: archive/main-ac0894a-rebaseline-20261008/phases/P5c-folder-deletion-proof.md

未完又は成立不明の旧backupは同じfile IDを確認する。確認できない旧backupを新保存先の別IDへ自動再送せず、成功済み記録を付け替えない。Google上のfileを無断で移動/削除しない。

### 確定済みの回答

- 公開handle変更時もnote URLと限定tokenを維持し、プロフィールURLだけを変更する。creator脱退や他人/WSへの移動でも同じとする。SH-07の旧note URL失効よりこの決定を優先する。旧handle再利用は採用仮定に従う。
- Google初回ログインが既存accountと同一メールでGmail/Google Workspace管理外の場合、既存password又は新しい確認メールで追加本人確認する。過去の確認済み状態で省略せず、成功前にIdentity紐付け/サインインを完了しない。旧記録: archive/main-ac0894a-rebaseline-20261008/reviews/P5-feasibility.md
- LLMの初期月間上限はaccountあたり30回。1fileの論理変換/再生成を1回とし、内部分割は非加算、運用設定で変更可能とする。採用仮定はUTC暦月、intent後の失敗/応答不明も計数、証明できた未送信だけ返却。外部request数/費用上限とは別である。
- OpenRouter再連携では影響確認を表示し、新連携の成功時に旧変換を取消す。失敗前に旧鍵を破棄せず、新鍵へ自動付替えしない。実行済み外部費用の取消は保証しない。
- Driveの明示再連携でも影響確認と新成功後の旧backup取消を行う。通常refreshは対象外。取消要求と実通信終了を区別し、実closeまで旧所有を保持する。Googleログインと独立して解除し、既存Drive物を変更しない。

## 利用者が確定した運用と検証方針

- 永続データと保全資料を OS の一時領域に置かない。
- 検証は毎回まっさらな環境で行う。失敗した環境は報告に記録してから消してよい。
- 自分が起動したプロセスだけを止める。
- 白基調・無彩色・中央一列の画面案は利用者の決定。
- OpenRouterのchat経路はdeny/no-fallback/require-parameters、専用STTはdeny/zdrの用途別privacy条件を維持する。

異常系はリポジトリの自動テスト（integration または e2e）で検証する。エージェントのブラウザ操作は各フェーズの主要な正常系と UX 項目に用いる。シナリオの受け入れには、正常系のブラウザ確認と異常系の自動テスト成功の両方が必要。条件が揃った項目をその時点で受け入れ、フェーズ末の一括受け入れを待たない。

P00「テストスイートを緑にする」を最初に実施し、QA-TEST を done にする。unit/Node integration の fixture・migration 期待数・テスト用ディレクトリの衝突・現在の契約との不整合を直し、テストが製品不具合を示す場合は製品を直す。テストを削除・skip して成功扱いにしない。以後、すべてのフェーズで全スイートが緑のままであることを完了条件にする。

P13 は音声以外の UX と主要シナリオの統合検証とし、P11 を依存先にしない。音声に関わる固定項目は未完のまま残す。音声はP11で再開する。実サービス接続の検証はgoal対象外。
