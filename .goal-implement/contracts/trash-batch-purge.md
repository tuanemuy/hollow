# P2d-3 の集合と親子回収

[P2d-3接続案と補足](../phases/P2d-3-contract.md)を採用する。確認時に本人scopeのnote ID・trash世代・titleだけを同UoWのINSERT SELECTで固定する。本文/objectを複製せず、子生成・実行・取消・閲覧はkeyset cursorで分割する。SQL snapshot自体の件数比例コストは501件と追加規模で測定する。empty全体に500件上限を設けず、新trash・復元後の別世代を固定集合へ混ぜない。0件は破壊jobなし、1〜50件も実回収前は処理中、51件以上は永続親1＋子で非同期に進める。

未確認snapshotの受付期限は15分、read pageは50、admissionは一周20を運用値とする。confirm済み親/未完了targetはこの15分で失効させない。501/5001 metadataの各warmup1＋5反復でprepare p50は2.44/21.28ms、最大4.06/28.97ms、返却114/115Bを観測した。heap増分や一周の時間は報告に残し、heap上限・大量処理SLOの保証とはしない。

単一・期限・emptyは同じUoW内beginと一意purge intentを使う。親generationは未開始admissionと操作所有に限り、fence後の完了はtargetのlatestAttempt・purge ID・trash世代で評価する。ある失敗子のretryで別の開始済み子を失効させない。複数親が共有するintentの物理claimは一つとし、latest targetとintentのjoinを正本、summaryはversion付きの有限reconcileで更新する。古いsummaryで成功を断言しない。

利用者の明示retryだけが新しい子jobを作る。自動回復は最新job内の内部attempt回数・最終理由/日時・現在状態へ集約する。自動30秒retryごとに新job行を作る初稿案は採用しない。古い明示jobの終端結果を保ち、latestだけを固定totalの内訳へ数える。取消後の未開始子を復活させず、既fenceの回収は継続する。物理回収を止める新しい試行回数上限は設けない。

親と子結果の90日は元作成日時から数え、retryで旧親や全履歴を延命しない。期限内の新retryには元親の最小headerだけを残す。未回収intent・容量・writer provenanceは表示履歴と別に保持し、最後の表示参照が消えても回収を続ける。長期故障で自動attempt行数が増えないこと、共有親の片方prune、古い親と新retry、A retry中のB成功を実装時に検証する。現在の実装・受入状態はplanのP2d-3-A〜Fで管理する。
