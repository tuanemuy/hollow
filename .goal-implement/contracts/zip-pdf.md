# PDF一括ZIPの接続判断

[P4f-2実装前契約案](../phases/P4f-2-proposal.md)の8条件と最小接続を採用する。既存ZIPの親/run/逐次子/spool/組立を使い、共用PDFの第三需要はzip_attemptsを正本とする。本人/匿名request・delivery・単件履歴を偽装せず、独立した需要表を複製しない。既存attempt.stateを維持しrunning内部のPDF binding/phase（waiting-pdf/copy-ready/copying）を判別型で追加、0031のnullable列とzip_pdf_holds一表で保存する。旧HTML/MD rowはnull互換、旧0030/terminal outcome/期限は書換えない。具体CHECK/FK/trigger/indexは旧全列保全とclone実証を経て接続する。

共通PdfDemand契約を中立なapplication/pdf/demandPortsへ移しzip-childを追加する。ZipPdfRepositoryはUoW内でattach/cache取得・copy claim・close/release・停止待ちbinding・recover/pruneを扱い、repository内に別Txを作らない。ZipContentIdentityとPdfComputeIdentityを別の型/名前で保持し、既存canonical/hashを同一視・上書きしない。ZIPはreadZipSnapshotの現在本人readを通した後にbuildPdfSnapshotを使い、単件PDFのpublic fallbackを使わない。コピー済spool/ZIPの取得は既存ZIP identity/require-determinateで確認し、元PDFcompute/24h/holdへ再依存させない。

cache取得又はPDF publishの同Txで、有効な当該attemptだけへ期限内holdとcopy-readyを確定する。copy-readyはZIP子の成功ではない。held/reading/closingは未openでもartifact/key cleanup・claimDelete・metadata pruneを阻止し、取得側もdelete claimを拒否する。PDF writer実終了を確認したcopy claim後、ZIP側のzip-source/zip-spool所有で期待bytes/hashを64KiBずつ検証copyする。全reader/writer実close・withOwner/実行所有終了・現在認可/内容/世代の再確認後だけ、spool成功/ref・hold released・不要binding切離しを同Txにする。期限内holdによる有限copyでは元PDF24hを再拒否条件にせず、子/親工程期限は守る。unknownならhold/所有/予約を残す。

ZIPの既存子120秒/親30分・逐次1子を維持し、ZipExecutionの中断可能waitForPollをNodeの既存2秒間隔とclock/timerに接続する。短いUoW照会の間だけ待機し、Tx/DB接続の専有・新queue・500タイマーは作らない。PDF pumpは独立して進行する。snapshot/待機/copy/closeを一つの子期限に含め、PDFcompute自体の既存期限を延長しない。

ZIP子のPDF binding取得前も、明示されたPDF_BUSY/PDF_STOPPINGだけは同じ子期限内で有限pollする。直前computeの実終了後にworkspace回収が残る場合を含め、独立PDF pumpの進行を待てるようにする。毎回current run/attempt・閲覧権限・内容・期限を再確認し、UoWを閉じてから待つ。受付時刻や期限を更新せず、異identityのactive computeへ混在させない。通常faultは子失敗とし、単件PDFの即busy応答契約は変更しない。

取消時に正当な本人/匿名/他ZIP需要が残るなら当該ZIP需要だけを外し、共有compute終了をZIP終端の条件にしない。最後の需要なら需要fenceとcompute停止を同Txにし、実compute終了/所有解放を確認するまで停止待ちbindingとrun枠を保持する。未open holdもcopy claimとCASで直列化して解放し、copy中は実close後にだけ解放する。外部取消をfailedに変えず、通常子timeout/生成失敗は正当兄弟を続ける。

zip-sourceと非released holdを物理delete/purge・finishClosed・PDF/ZIP metadata prune・構成欠落guard・boot/recover/drainへ接続する。旧process/監督の実終了証明後にownerと需要/holdを明示順で回復し、全回復Tx完了前にpump/cleanupを走らせない。初期heldを取り残さず、未完copyを自動再開する新holdは作らない。drainで最後のcomputeを待つ間もPDF pumpが動ける順序を保ち、unknownでDB/lockを正常解放しない。PDF実体はPDF予算、copy/spool/組立はZIP予算、holdはpinで二重課算せず、既存6GiB保護/ZIP4GiB・外部delivery2枠を変えない。

PDF受付を構成済みの場合だけ有効化し、listZipの既存items/nextを維持してconfiguredとavailableFormatsを新projectionとして加える。サーバーの実構成から整合した値を返し、actor/contextを照合したGETの表示可否を認可やPOST検査の代用にしない。未構成なら安全な説明と非受理、HTML/MDは継続利用可能。選択後にPDF構成が失われても無言でHTMLへ変更しない。残存PDF依存資源がある未構成bootは回復前に拒否し、released/removedの資源0履歴だけは拒否理由にしない。同command receipt照会は新規生成構成条件と分離する。UI-S1 completion ticketとactor/context/ACK、既存HTML/MD digestを維持する。実PDF入りZIPの全entryと抽出PDF全pageを確認し、小fixtureから500実Chrome/全1GB/全OSの保証を導かない。

PDF artifactのready→cleanupは新規hold/cache/外部取得を止める論理retireとしてhold中も許可し、hold不在をretireの前提にしない。cleanup claim・物理delete・removed/key-null・予約返却は非released holdと実ownerの終了まで禁止する。期限内に取得した既存holdだけは、固定世代/nonnull file-key/bytes/hashを保持したcleanup artifactからもcurrent ZIP read/content/PDF identity/工程期限/取消世代を検査してcopyできる。cleanup→readyや新holdによる復活は認めない。未open holdによって認可失効/trashの同Txが中断される過剰guardを作らない。

通常trash/purgeの新規読取停止は、既存のnote lifecycleとcurrent-readを正本とする。同Txでartifactを即cleanupにする新副作用は加えず、readyが残っても新規取得・hold・copyの現在認可を拒否する。既存holdは実closeまで物理pinを維持し、その後の通常sweep/purgeで回収へ収束させる。直接retireが呼ばれた場合のready→cleanup契約とは検査を分ける。
