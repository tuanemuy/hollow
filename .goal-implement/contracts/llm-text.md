# P5b-2の本文生成と月間枠

[本文生成提案](../phases/P5b-2-proposal.md)の共有境界を採用し、P5b-2aはtext取り込みとtext/HTML/Markdown原本からの明示再生成、月間枠、本人履歴、取消、使用量を一つの縦接続にする。P5b-2bはOffice/文字PDF/単画像の入力成立を確かめて提供を追加する。通常HTML/Markdown取り込みは常に機械処理でLLM回数0、IM-06の明示再生成は別操作である。全page画像PDF/音声はP5b-3、Driveは別phaseに残す。P5b-1の独立受入・環境返却を満たし、P5b-2a固定8条件をplanへ記録して開始する。

既conversion jobと本文commitを再利用し、LLM conversion/dispatch/quota bucket/quota reservation/account admission fenceの5加算表と内向きportを分離する。credential epochの正本は既connectionのままとし、leaseだけで外部送信権限を再取得させない。dispatch UUID/唯一ownerのintentを短Txで確定してから一度送信し、応答は有限検証・実close後に同ownerで保存する。保存済応答の後処理だけを再開でき、intent-only/保存確認不能を自動再発注しない。旧表再構築・別process一括recover・所有不明の期限解放はしない。所有終了と公開履歴90日・response回収の寿命を分ける。

quotaはjob受理時に固定UTC月へ予約し、最初のdurable dispatch intentで論理1回を消費する。全segmentが一度も送信されていない証明と全dispatcherの実終了/送信権限失効がそろう場合だけ返却できる。前segment発注済みなら後segmentの未送信失敗で返却しない。月上限超過は原本/旧本文を保持した失敗jobにし、保存容量超過のupload拒否と混同しない。消費/予約中/予約可能残数/更新時刻/次resetを区分し、80%超警告は消費基準、予約は別表示にする。明示retryは新job/新1回、旧epoch変更時は元モデル/追加指示を初期値にした新変換確認へ進み、非適合/終了は明示変更を求める。旧鍵保持・旧job付替え・default無言復帰をしない。

NodeのLLM所有証明は同領域のprivate .llm-runtimeへ非秘密runtime UUID/PIDと未ACK predecessor UUIDを耐久記録し、専用排他recovery lockを使う。旧PIDのESRCHとrecord再一致がそろった当該runtime UUIDだけをDB回復対象にする。生存/EPERM/確認不能では解放せず、同DBの別storage領域ownerは操作しない。DB短Txでlocal closed・intent-only unknown・response-ready後処理へ冪等収束してからpredecessorをACKし、ACK不明や再crashでも未ACK対応を上書き脱落させない。未解決なら新LLM実行を開始しない。owner record耐久確定前のdispatchを禁止し、通常stopも全execution promise/実close後だけ終了記録を確定する。旧ObjectStorageの全回復責務やlease期限での所有解放は追加しない。

再生成は現在personal owner又はWS owner/editorが本人の連携で受理し、旧本文を読めるまま編集を止める。失敗/取消で旧本文/版を変えず、成功は既commitNoteで本文・版・FTS・素材pin・既存失効hookを原子的に接続する。タグ/公開/共有identityは維持する。直後undoは現在版が当該生成結果に一致する場合だけ元本文を新revisionとして復元し、現在title/style/tag/公開を巻き戻さない。後続編集があれば明示履歴復元へ案内する。通常一括取消の開始済み完了待ち、再生成取消の本文不採用、再連携成功等の外部取消fenceと実abort/closeを区別する。

再連携/解除確認は旧epochのactive件数と単調admission watermarkを照合し、確認後の新需要は再確認する。candidate昇格と旧世代のdispatch/late-result拒否を同Txにし、個別取消と実closeは有限に追跡する。通常logout/画面離脱だけで受理済み処理を止めず、現在account/note/WS/roleは各工程とcommitで照合する。処理中move拒否と、完了後moveでも実行actorのquotaへ計数する境界を維持する。

確認範囲は各認可試行に束縛するため、5新表に加えて既openrouter_attemptsへnullable confirmed_admission_sequenceを1列加算する。旧rowはNULLの未確認のまま保持し、現在active=0を採用Tx内で確認できる場合だけ互換動作を許可する。active>0は現在件数/sequenceの明示再確認が必要。再確認POSTは本人/browser/session/authVersion/expected epoch/元attempt固定期限を保持し、当該値をCAS更新する。保存candidateの再利用はcode再交換や期限延長を伴わず、昇格時にも現在watermarkを照合する。並行attemptと確認後の新需要をaccount共通値だけで混同しないための加算で、旧表再構築はしない。

2aの初期運用値はgeneration全体2/account1・queued account100、job30分/source30秒/dispatch90秒、停止監督60秒、text UTF-8 64KiB×最大16segment、HTTP応答2MiB/content64KiB per segment/max_tokens8192、追加指示8KiB、job response予約2MiB/global256MiB、pump2秒/prune60秒100件とする。成立probe前の保守的設定で、OS硬保証や実token計数の代わりにはしない。原本50MiBと本文800KiBの既上限は別責務、工程上限超過は明示失敗と旧本文保持、無言切詰め/機械fallbackなし。現在model profileのcontext/output/必要parameterを照合し、画像寸法/codec/混合PDF等の2b資源値は成立gateまで未採用とする。

Nodeの通常OpenRouter構成は同じprovider instanceのLlmModelProfilesを返し、server.nodeのtrusted llmFactoryだけを契約検証の差替口にする。本番env/HTTPにfake選択を置かず、通常は固定generator/sourceWorker/result/ownershipを組み立てる。sourceWorkerは既Node build scriptからdist/server/llmへ配備する。HOLLOW_LLM_MONTHLY_LIMITはboot時に非負safe integerとして検査し、未指定30・0は新規予約停止。明示不正値を黙って既定へ戻さず生成の安全な非提供/設定エラーとし、password/既機械を維持する。既予約/消費は設定変更で消さない。

OpenRouter未構成でも同領域ownerの証明付き回復lifecycleは構成するが、新生成受付は有効構成を必須にする。既queuedは現在構成/連携を照合し、未発注なら安全に失敗させる。durable全応答の後処理は鍵復号なしでも、旧epochが今も有効で現在note/source/version/role/取消/期限が成立する場合だけ採用可能。解除や新epochへ付け替えない。停止は新受付→pump停止→LLM全work実終端→他worker/DB終了とし、未構成を実終了証明に使わない。

生成HTMLは未信頼として既sanitizerを通し、新しい媒体URL/CSS参照を自動取得しない。原本由来の検証済みnote-owned media placeholderだけ復元し、通常HTML/MarkdownのIM-05収集は変更しない。既原本からの全文ブロック網羅とowned read/worker terminate/exit、有限responseとrequest/response/socketの実終了を2aの提供前に確かめる。部分出力/tool/refusal/length終端を完成本文へ採用しない。

生成profileは既catalog表示DTOを拡張せず、NodeOpenRouterProviderの正常完全集合cacheへ別メタデータとして保存し、LlmModelProfiles.inspectから読む。context_length/top_provider.max_completion_tokens/supported_parametersを検証し、欠損/不正は一覧選択を壊さず生成profileだけ拒否する。customは15分以内のlive profileを必要とする。既定google/gemini-3.5-flash-liteは[公式モデル頁](https://openrouter.ai/google/gemini-3.5-flash-lite)を2026-09-28に確認したcontext1,048,576/completion65,536・text入出力を静的profile v1として保持し、catalog障害時だけadopted-defaultとして区分する。実送信max_tokensは8192以下、require_parameters=true。最後の正常完全集合で欠落/期限切れ/明示max_tokens非対応を確認した既定は静的値で復活させない。数値は実token計数・品質・永続的なprovider提供の保証ではない。

原本media対応はprepare入力へ有限のsourceUrl/opaque placeholder mapを渡す。現在note/固定original identityと取得済ready note-owned assetを照合したmapだけを使い、相対参照とraw/正規化URLを混同しない。Workerは完全一致srcだけ置換し、prepared metadataへplaceholder別期待出現数を保存する。生成後は全segmentの未知/欠落/過剰出現を拒否し、正当な原本重複は保持して既assetへ復元、commit前にも現在条件を照合する。初期値は最大200map・全出現200・sourceUrl2048 UTF-8 bytes・固定UUID placeholder、超過は明示resource failureと旧本文保持。対応のない媒体はalt/未解釈noticeのままとし、新規取得しない。再準備は同original/mapから決定的placeholderを作り、durable input hash不一致では再発注しない。

owned sourceの終了未証明は内向きapplicationのLlmObjectOwnershipUnprovenErrorで安全なcodeとexact conversion-job IDを示す。CoordinatedObjectStorage.withOwnerは現在ownerのkind/IDと厳格なerror契約が一致した場合、通常finallyによるobject_writes解放を行わず、execution/DB所有とともにpinを保持する。単なる例外名/文字列を証明にせず、Node/RSCの二重loadでも既brand方針と整合させる。既ZIPエラー・通常実close・storage全回復範囲は変更せず、LLM unknown保持と実終了後解放を故障対で確かめる。

libSQL UoWのdriver翻訳境界は、既serialized errorに加えて厳格なisLlmOperationErrorで識別する内向きLLMエラーをそのまま伝播する。現在epoch/権限fenceの業務結果をDB障害/終了不明へ変換しないための局所許可である。raw例外や同名code/偽shapeは許可せず、一般DB translatorやpresentationの公開error unionは広げない。provider I/Oは引き続きUoW外とし、rollback/driver翻訳と真偽のerror識別を小対で確認する。

ノート完全削除は既purge/archiveJobsのjobSnapshotsへ本人用の安全な状態/失敗理由/原本名だけを移す。LLMの非terminal、active/unknown owner、未解放response予算はhasWritersで物理削除を止める。同Txの現在照合で全terminal・実owner終了・budget0・quota予約released又はconsumedが成立した当該noteのdispatch/reservation/conversionだけを回収し、bucket累積consumedは減らさない。削除済noteのresponse/追加指示/receipt/retryを残さず、snapshotの90日期限を延ばさない。trash等の現在note失効は同Tx cancelNoteとpump検知へ接続するが、論理取消だけで実close前にpurgeしない。未精算予約を削除で返却する経路や旧ownerの一括解除は追加しない。

生成HTTPはcontrol HTTPとは別の固定chat endpoint/redirect0/retry0とし、初版は非streamの有限応答を使う。model fallbackなし、provider.allow_fallbacks=false/data_collection=denyを初期方針にする。適合providerがない場合は安全な失敗として説明し、設定を黙って緩めない。これは[公式provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)の選択制御に基づく方針で、ゼロ保持保証ではない。[公式取消説明](https://openrouter.ai/docs/api_reference/streaming)に従い、ローカル通信の終了とprovider処理/課金取消を区別する。実品質/実費用/外部送信は引き続き未許可・未検証で、月30回を金額上限と表示しない。

LLM使用量とノート操作の表示は、同hrefのrouter invalidateでも認証操作ticketが失効することを前提に、各LLM client islandのonResolvedから現在actor/routeへ束縛したGETを再実行する。共有認証hook・POST・OCC契約は変更しない。1inflightと1queuedへ集約し、古いactor/route・unmount後の応答を破棄、subscriptionを解除する。取得で入力中のモデル/追加指示を初期化せず、mutation応答を現在読取の代わりにしない。使用量と最新jobはそれぞれ再読し、予約解消・上限拒否の直後表示を同bundle実UIで確認する。

使用量DTOは同一UoWのclock snapshotでUTC月bucketとresetを選び、remaining=max(0,limit-reserved-consumed)とupdatedAtを返す。updatedAtはquota最終変更時刻ではなく使用量の確認日時であり、利用者timezoneでその意味を表示する。上限引下げでも既消費/予約を減らさず残0とし、消費80%ちょうどでは警告しない。時刻記録の永続列やTTL、金額上限は追加しない。

受付応答を失った操作の同command照会は、GETの成功を業務受付成功として表示しない。現在actor/routeで一致receiptを確認した場合だけ受付済みを表示して未確認状態とcommandを解放し、当該未確認操作の古い通信エラーを消す。job自身の失敗理由と別操作のエラーは消さない。receiptなしは未確認と同commandを保持し、自動POSTをしない。旧ticketの応答はどちらの表示も更新せず、一般mutationや認可・server側POST契約を変更しない。
