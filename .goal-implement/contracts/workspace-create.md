# P3aの入力と移行

WS名は前後trim後1〜100 Unicode code point、説明は0〜2,000 code pointとする。slugは空ならnull、非空は3〜63文字のASCII英小文字/数字/内部hyphenとし、両端は英数字とする。入力時の小文字化を表示し、無言の切詰めはしない。予約語は `admin/api/auth/settings/new/edit/trash/notes/workspaces/assets/static/help` の完全一致集合とし、実routeとの衝突を実装時に照合する。DB一意制約を最終判定とする。

作成20件は、creator本人の現存WS数を同UoWで数える。参加数や生涯累積数へ置き換えない。scope候補と基本note一覧は1page最大50件のmetadata keysetとする。slug空き照会は300ms debounce、本人毎分60回まで、最新応答だけを採用する。通信失敗を空きと判定しない。招待の送信上限値はP3bで採用する。

新規noteのcreatorは実行者を記録する。旧noteは作成記録から確認できる場合だけ人物へ紐付け、不明は型付きunknownと「作成者不明」で表示する。unknownを退会済み人物にしない。元owner・最新編集者・uploaderだけから作者を推定しない。

同梱素材はnote作成前の受付chargeから最初の保持chargeへ移すときに二重加算しない。失敗/未bind/cleanupの既存個人容量も移行時に照合する。P3aのtyped initiatorはsystem期限回収と利用者要求を区別し、creatorや最初のownerをsystemの代役にしない。

新しい期限回収intentはsystem initiator、手動回収は人物必須のuser initiatorとし、現在scopeも保持する。旧行の全旧列は保持し、causeから由来を判定する。旧人物欄はsystem処理の認可根拠にしない。

取消済み取り込みを別のWS editorが明示的に取り込み直す場合は、現在note編集権限と原本activeJobを同UoWで確認し、新actorのbatch/jobを作る。旧jobの読取/再試行/取消は旧本人限定を維持する。note作者と原本upload人物は変更しない。

P3aのmobile scopeメニューは、headerを配置基準として幅と左右位置を同時に制限する。summaryの幅・位置だけを基準にして画面左へはみ出させない。長い名前はdesktop/mobileのsummaryを一行の省略表示にし、aria-labelとメニュー内の全名を保持する。mobile navは折り返さず、scopeだけを利用可能幅へ縮めてaccount操作を同じ行に残す。scope iconは20×20pxの明示枠とobject-fit:containで自然比を保持し、global img規則を変更しない。desktopの既存配置、scope/request/navigationの状態管理は保持する。可視性は各選択肢の矩形・画像・通常操作で確認し、document.scrollWidthだけでは判定しない。詳細は [P3a-V1の局所修正案](../phases/P3a-revision-plan.md)。
