# P4b のHTML・Markdown単件書き出し

[接続案と22:30補足](../phases/P4b-contract.md)を採用し、EX-01/04のアプリ内現在閲覧者と限定リンクだけへHTML/Markdownを接続する。PDF/ZIP/public/handleは後続に残す。同期操作を仮job・履歴・ティッカー・PDF ticketに置換しない。clientはnote IDと形式だけを指定し、serverが保存済み正本と現在媒体を取得する。未保存本文は送信・保存・破棄しない。

現在session/accountと元link/browserのauthorityを排他的に扱い、prepare・生成採用・取得直前に同じ根拠を再認可する。元linkを後から別account/public根拠へ付け替えない。認可fenceとcontentIdentityは分け、出力に効く本文/title/filename/style・正確な媒体bytes/digest/MIME・変換profileと外部許可集合から内容を識別する。同内容の移動は現在閲覧可能なら成功でき、失効は共通404、閲覧可能な内容変更は明示やり直しへ戻す。I/O中にDB Txを保持せず、途中の異なる版を混ぜない。

HTMLは安全なanchorを保持する専用serializerを使い、iframe表示のanchor→span表現を流用しない。現在styleとready画像を同一documentへ埋め、SVGは安全化済みbytesだけを使う。正本中の小data URIはasset行の有無だけで拒否せず、既存inlineMedia.inspectの実内容検査を行う。入力800KiB・小inline decoded32KiB/最大200件の既存有限処理を用い、媒体から出力する大きなbase64を再parseしない。超過・検査不能は成功や黙った画像欠落にせず、安全な理由と修正導線を返す。

MarkdownはASTから構文別にescapeして機械変換し、表現できない要素をsafe HTMLで保持する。通常画像は衝突しないdata URI参照定義、寸法等が必要な要素はsafe HTML内の埋込で単一fileへ収める。data URIやHTMLを禁止する閲覧器まで表示一致は保証しない。既に正本にある利用者の通常anchor/textをtoken風文字列で無差別に削除せず、アプリが付与する認可secretや内部媒体URLを新規挿入・残存させないことと区別する。

匿名の303取得でも生成時のnoticeを失わないよう、file末尾の「書き出しについて」に元本文と区別した定型説明を含める。HTMLは安全なaside、Markdownはblockquoteを使い、参照元URL・内部識別子・secretを説明へ追加しない。追加部分も変換profile・出力上界・実bytes検査の対象とし、アプリ画面にもnoticeを表示する。一般的な閲覧器/外部参照の限界と、当該変換で生じた除去等を区別する。

serializerのAST node数・深さ・segment数・manifest URL量には、補助実装の固定値を新しい業務上限として採用しない。800KiBの入力と現在媒体集合から保守的な出力上界を求め、深い木の走査・変換は再帰依存を避け、隔離heapと共通期限で制御する。外部inspect最大200件と小inline最大200件はそれぞれの検査境界であり、全current asset数の上限へ流用しない。資源超過時は部分成功にせず安全な失敗と実close・回収を行う。

外部媒体は明示したinspect-onlyを使う。最大200候補・同時8・検査全体5秒をprepare共通30秒以内で実行し、生成採用前と遅れたGETでも同じ有限方式で許可集合を再確認する。未検査/blocked/private DNS/timeout/上限超過の能動参照や未取得stylesheet、内部/history/draft/原本の媒体URLへfallbackしない。許可済みで埋込不能な正当な外部媒体だけ原URLを保持し、新body fetchや再取り込みはしない。通常anchorは媒体検査と分ける。後日fileを開く際のDNS/外部内容変化は保証外とする。

出力はrequest-lifetimeの短命spoolに完全生成し、再認可・内容照合後だけnative attachmentへ渡す。operation IDは単独bearer認可ではなく現在sessionまたは元link/browserへ束縛する。最初は取得GETだけを提供し、未提供methodを明示拒否する。タイトル由来filenameは制御文字/CRLF/path/予約名等を処理し、空ならnote ID、拡張子は形式固定。attachment・正しいMIME・no-store/private・no-referrer・nosniffを使い、不許可応答にfilename/bytesを出さない。限定native POSTのOrigin:null対応はunlockの全体規則を緩めず、専用入口に厳密Fetch Metadata全一致を適用して実証する。

spoolのwrite owner・cleanup世代・固定期限・物理負債だけを永続追跡し、account/WS使用量やupload quotaには課算しない。最小の新表はexport_operationsと専用export_download_ratesとし、operationはnoteへのrestrict参照とpreparing/ready/sending/cleanupの状態・世代・固定期限・必要な認可束縛・出力metadata/予約を持つ。export-operationのwriterを追加して既存write/delete調停へ接続する。これはservice所有の読取出力であり、既存note/resource writerの所有世代fenceは緩めず、新kind自身のop世代・現在認可/lifecycle/contentで守る。同内容かつ現在読取可能な移動を、旧scope/ownershipGenerationだけで一律retryへ落とさない。

元媒体は新holdを置かず、manifestのsha/bytesとstreamを照合し、途中消失/改変なら出力全体を不採用にする。専用read-only SourceReader portをDIで同じFileObjectStorageのraw streamへ接続し、現在認可済みmanifest由来keyだけを渡す。元媒体readをcoordinated writerへ登録しない。Node stream/crypto/provider例外を内側へ漏らさず、有限abortと実closeを守る。出力spoolだけをcoordinated writerで追跡する。

purge/WS削除は現在所有を確認して新受付/登録/採用/取得を止め、未終端writer/readerとspool回収を収束させる。先移出を元WSだけで止めない。実close・remove・同世代確定前に物理負債や予約を消さず、crash/boot/取消/削除失敗からも回収する。任意tmpの全走査削除や、note cascadeによる未回収owner消失は認めない。

ExportLifetimeは保持中IDを最大2件だけ列挙し、export runnerがDBのoperation正本と照合する。purgeが先にoperationを回収した場合もruntimeだけの待機を残さず取消へ収束させる。DB照合失敗を正本消失とみなさず、実行中taskはabort要求だけで枠を解放しない。

初期運用値は専用download rateがbrowser+noteで6回/60秒、note全体30回/60秒。最初の予約から固定し、成功返金・block中延長・token再発行resetをしない。現在link/password通過確認後だけ予約し、再起動で保持、429/Retry-After、60秒ごと100行の期限掃引とする。password rateは変更しない。

Node全体の実行slotはprepareからready/送信の終了まで最大2操作、待機列なし。生成30秒、受付から操作有効期限120秒を固定し、期限でabortしても実終了確認は別に行う。送信claimは同operationの多重readerを無制限に許さない。streamは目安64KiB/各high-water256KiB、ASTは隔離worker heap128MiBと親の期限監督を用い、native全メモリの上限証明とは混同しない。本文・媒体manifestから出力上界を予約し実bytesでも検査する。service全体の一時disk枠は設定可能な2GiBを初期値とし、cleanup debtを含めて実removeまで予約保持する。これは単件1GB制限ではない。設定上界を恒常的に超える場合は単なるretryでなく運用枠不足/設定調整が必要と説明する。最大規模や配信済bytesの回収を小fixtureで実証したと主張しない。

アプリUIはactor/epoch/note/操作世代で旧success/catch/finallyを拒否し、pending・取消・失敗と明示再実行を備える。ACK不明で成功や自動再送を表示せず、native GET開始を利用者端末への保存完了としない。匿名はno-JS formと安全なerror/戻り導線を使う。新port/schemaはこの同期sliceだけに限定し、将来artifact/job全体を先行実装しない。
