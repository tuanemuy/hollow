# 本人PDFの永続接続

[本人単件PDFの詳細提案](../phases/P4d-2-proposal.md)の責務と所有分離を採用する。実装開始はP4d-1の独立受入後とし、未解消のclose中取消を製品へ移植しない。本人とはjobの実行者であり、現在閲覧できるowner/editor/viewerを含む。匿名・ZIPは後続とする。

新しいapplication/pdfの内向きportにrequest/compute/artifact/deliveryのrepository、binary source reader、workspace、renderer supervisor、service capacityを分ける。DB repositoryはHollow UoW、process/fileはNode adapter、HTTP境界はpresentationへ置く。既存短期HTML/MDの型・寿命をPDFへ流用せず、framework/Node型・ambient timeを内側へ入れない。[正式開始提案](../phases/P4d-2.md)の新0028・4表の状態/索引/CHECKを採用する。requestはaccount/command一意、computeはnoteごと非closed一意、artifactはwriting/ready/cleanup/removed、deliveryはready/sending/closing/closedとlive request一意を持つ。live-note FKはRESTRICTとし、active/debt中にnull化せず、実回収後だけ最小shellへ切り離す。succeededが参照するexpired/removed artifactと履歴pruneの整合を維持する。追加resource表が必要なら改めて提案する。

private pack/Chrome profile/tempはcompute専有workspaceと永続所有に置き、別rootのCoordinatedObjectStorageを増設しない。完成PDFのcopyと配信readerは既存単一storageの専用ownerへ接続する。recoverWritesより前に旧監督・copy・readerの所有と実終了を確認し、未知/壊れたledgerを推測修復しない。purgeはartifactに加えてprivate workspace・未close reader/writer・回収負債も確認し、それらをFK cascadeで消して完了にしない。旧scopeではなく現在note所有を基準とする。

本人の要求はaccountIdに永続所有させ、API入口は現在session、workerは内部専用resolverで現在account/read/contentを確認する。メンバー降格・除名・脱退ではPDF専用の現在所有に基づくindexed取消を同Txに置く。owner→editorとviewer→脱退も含め、既存編集jobの取消条件を無関係に変更しない。終端要求・別actor・先移出note・有効な兄弟demandは保持する。取消/最後の需要消失/公開の競合をDBで直列化し、rendererのfile renameだけを製品公開の確定点にしない。

要求とartifact/deliveryの寿命は独立させる。履歴90日・PDF24時間の期限と現在権限/内容一致を入口とworkerで確認する。物理fileの回収後も必要な期限切れ・削除済み履歴の最小shellを表現し、succeeded参照やpruneが未close/負債の所有を壊さないよう具体schemaを決める。配信は全fileをJSに保持せず、実体の所有とbytes/hash・送信前の現在snapshotを確認する。期限/lease切れだけで使用中readerを終了済みにしない。

PDF transfers portはhold(id, expiresAt)でAbortSignalを返し、release/cancel/最大2件のids/実完了を待つstopを持つ。本人deliveryの初期参照値はprepareから120秒とartifact.expiresAtの早い方を期限にする。匿名ticketの10分とは別定数・責務であり、再prepareでartifact24時間を延長しない。内側にNode型やambient clockを持たず、同ID二重readerも拒否する。GETは現在session/read/content、DB claim、pdf-delivery owner、stat/stream、応答前再照合を順に行い、readerの実closeとwithOwner終了後だけDB closedとruntime枠解放を確定する。workerは保持IDの期限と現在readを再照合して取消し、purgeはactive writer終了を待つ。既存HTMLMD lifetimeとは分け、close未証明をtimeoutだけで解放しない。

今回の検証対象はmacOS arm64上のNode参照配備とし、将来本番OSを利用者に代わって決定しない。固定Chrome/Puppeteer/font/license manifest、明示Python absolute executable/version/POSIX self-check、起動時downloadなし・sandbox必須・private workspaceを接続する。未構成は明示し、虚偽の生成成功やno-sandbox fallbackをしない。旧監督/copy/readerの実終了が不明なら共通storageのrecoverWrites自体をfail-closedにし、PDF受付だけ停止して回復を続行しない。単なるPDF未構成でHTMLMDが使える状態とは区別する。

参照配備の初期設定はPDF生成1、異note待機列なし、同noteの一致要求は合流、配信2/同request1とする。生成全体120秒、render30秒、TERM後3秒の既知group停止、lease60秒、wake2秒/最大20step、回収再試行5秒。channelは4reader/slot4回/64KiBを初期値とし、slot数は現在入力から導出する。leaseやタイマーだけを実終了の証明にせず、実closeまで枠を保持する。通常資料で十分性を測り、不足は有限値の変更案として扱う。

byte枠は明示設定必須で、今回の参照設定はservice6GiBをHTMLMD2GiB/PDF4GiBへ分割する。computeは正確pack/HTML/manifestとoutput256MiB・native-temp128MiB、artifactは完成copy256MiBを一度ずつ予約する。制御できるwriteは実byte上界を検査し、完成readyは実bytesへ縮約、未回収は負債を残す。native tempは検知間隔内の超過を防ぐOS硬上限ではないため、実測と未保証を記録し、超過検知時に既知生成を止め、実超過を負債へ計上して回収まで新PDF予約を止める。HTMLMD保護は予約partitionであり、OS全diskの硬保証とは呼ばない。恒常不足/一時混雑/実生成の資源超過/timeoutを区別し、ノート業務上限や権限拒否へすり替えない。合法最大入力・native hard RAM/CPUの成功保証は置かない。

PDF専用document plannerは既存の安全segment/CSS規則を再利用し、型付きHTMLと登録slotだけを返す。base64を作らず、videoは現在poster又は定型notice、外部fetchの許可集合は空とする。安全な利用者記述のリンク/文字列とrenderer付加origin/slot/headerを区別し、本文を一律除去しない。既存ExportFormatはHTML/MDのまま維持する。failed retryは明示export形式/オプションを保持し、noteの本文/title/保存styleは現在snapshotから新identityとして取得する。

本人PDFパネルのpending commandは親がactor/note別の最小識別子を保持し、送信前に保存する。再読込用の保存に失敗した未送信要求は新POSTをせず理由を示し、既存の照会/取消まで止めない。unknown/throw/照会nullは未受理の証明とせず、明示GET照会だけを案内する。accepted queued/runningは2秒の非重複照会とし、同actor/note/commandの終端確定か明確なrejectedだけが該当pendingを消せる。別commandを消さない。再mountでは残pendingを照会し、自動POSTしない。自動native取得は当該mountの新requestが成功した一回だけとし、unknown照会や再mountで見つけた成功は明示取得にする。availableかつsucceededだけを対象に、ticket取得後も現在actor/epoch/note/opと厳密な自サービス配信URLを確認する。編集内容やrouteに触らず、native取得開始を端末保存完了と表示しない。

本人PDFのsummaryは本人/90日/active条件の全件countと代表するactive ID/titleを返し、履歴先頭50件に依存させない。activeは別の50件keysetで走査し、観測済みID/versionだけを保持、最大50件ずつの公平なround-robin照会で終端を通知して除く。50を同時jobの業務上限や全追跡上限にしない。個別activeを取得した時点または明示受付receiptから観測を開始し、取得前に終端化した初回対象は履歴として扱う。初回terminalの一斉通知、永続exactly-once通知や全初回時点の厳密snapshotを追加要件にしない。明示受理は即追跡し、当該新操作のcached terminalも通知可能とする。actor/epoch変更で破棄し、再訪は現在activeを再走査する。既存import/batchと独立dismissを維持し、tickerは全active件数を合算、0なら表示しない。

参照配備は非秘密の `HOLLOW_PDF_CONFIG` 厳密JSONにPython/Chrome/固定fontのpath・既知hash・技術値を置き、監督rootを共有storage配下の `.pdf-runtime` に固定する。通常object key/公開readの名前空間から予約除外し、既存object走査/回収を中へ入れない。storage constructor/recoverWritesより前に旧監督を検査し、旧ledger確認前にruntime.jsonを上書きしない。既存PDF root/ledgerがあるのにconfig/Pythonが不明なら共通bootを拒否する。新規で構成がない場合だけPDF未構成としてHTMLMDを維持し、root切替で旧所有確認を迂回しない。

監督CLIは `check root` と `run root workspaceUUID deadlineMs termGraceMs` とし、deadlineは監督開始monotonicからの相対残時間、整数1〜3,600,000ms、TERM猶予は1〜30,000msで受ける。広いCLI上界を業務上限にせず今回の120秒/3秒設定を別に守る。root直下のruntime.json・generation.lock・generation.jsonと専有workspaces/UUID/nativeをowner/mode/nofollowで検査する。ledger fsync後の明示GOより前にengineは処理せず、最小環境と有限JSON protocolだけを使う。stage・完了shape・codeを限定し、未知fieldや不完全closeを成功へしない。`identifier` は残留識別子検出を示す固定codeで、検出値をevent/logへ含めない。

監督の直接子をwaitid/WNOWAITで終了観測し、groupの終了確認までreapしないことで連続するPID所有を保持する。version1 ledgerのownerはunreaped-child-v1とsupervisor/child/session/spawnMonotonicNsを持つ。macOSではzombieのgetpgid/getsidがESRCHになるため、生存時のgroup/session確認済みと同じ直接子のWNOWAIT保持、psの親/group/Z状態の一致を組み合わせる。生存時の証明欠落や観測不一致は拒否する。旧ledger・reap後・出生/系譜が不明なgroupにはsignalしない。秒精度psだけでPID再利用を否定しない。明示PythonのAPI実在確認と、owned-child/固定Chromeの実終了対を区別する。固定engine/Chromeが同groupを保つ参照配備であり、敵対的setsid子孫までのOS隔離を保証しない。詳細protocolと静的移植結果は [監督補助報告](../phases/P4d-2-supervisor.md) に置き、実行検証は主担当へ集約する。
