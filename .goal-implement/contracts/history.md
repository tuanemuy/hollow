# P2c-1: 20版と復元

[接続契約案](../phases/P2c-1-contract.md)を採用する。安全化・参照解決後のtitle/html/displayStyleを比較し、意味のある保存だけを版にする。由来・初回処理・進捗だけの更新は空版を作らず、Dの手動優先とworker guardを維持する。同値の過去版は「現在と同じ内容」とし、復元操作を無効にする。

revisionNoは1から始まる正数連番とし、worker用note.versionと分ける。current asset refの0と保持版の正数pinを混同しない。既存noteは移行時の正本をbaseline1版として保持し、旧本文/title/version/updatedAtと現在の初回状態を変えない。過去のactorや履歴を推測しない。backup/cloneで旧値・pinの整合を確認してから本体へ移行する。

共通commitは同じUoW内で正本・版・pin・20版pruneを整合させる。認可と個別job guardは各usecaseに残し、DNS/内容検査/storageはUoW外で行う。manual/autosave/import/reference/style/restoreの全経路を接続する。最後のcurrent/保持版pinが外れた時点から7日を数え、保持中はGCせず、同じobjectを版数分の容量へ数えない。

履歴previewはserverがnoteと保持revisionから読み出し、専用asset経路で現在の閲覧権限・revision所属と存在・正確なpin・readyを毎回確認する。現在asset URLのcurrent ref必須条件は緩めない。厳密route/Fetch Metadata/認可先行HEAD・Range・416、sandbox/CSP/inertlinkは履歴にも適用する。

復元は選択版のHTML/title/styleと型付き取得情報を使い、現在のCSS再利用で古い装飾を置換しない。小さいdata URIは既存の内容検査と制限を通し、過去版であることだけを安全性の根拠にしない。保持pinによる復元は7日以上でも許可するが、別note/prune済み/deletingは拒否する。現在の参照on/off・原本/bundle・恒久台帳・job履歴は巻き戻さない。

本文同値の小data検査完了では過去版の取得情報を更新しない。復元時の再検査で安全性を確認した結果だけを現在の取得情報へ反映する。履歴表示準備の検査/admission/DNSへ共通の30秒signalを伝え、個々の検査制限とは別に連続占有を抑える。既存呼出の制限やキャンセル条件は緩めない。

復元後の表示設定は利用者が選んだ値としてuser/completeにする。過去のpending/jobを復活させない。reference実行中は厳密なversion/generation/lease条件で旧結果を退け、必要な未取得分だけを新jobへ渡す。conversion中は既存本文編集と同様に復元を拒否し、完了待ちまたは既存取消を案内する。

人間actorの最新異なる2名と各最終mutation versionを小さいmetadataとして保持し、20版から削除された他人の変更もbase以後なら検出する。systemは人間の更新記録を進めない。actorはsessionから決定する。移行前の不明baseは再読込/再確認し、上書き確認は現在versionに結び付ける。個人段階は純粋policy/永続化/同一owner2tabを検証し、共有本体の別利用者認可はP3へ残す。

履歴は最大20件の日時/原因/実行者区分と現在版を示し、preview/取消/確認付き復元/失敗からの再操作を提供する。dirtyをsave/discard/cancelで解決し、選択だけで古い本文をautosaveしない。V5の同note ID・最新入力・mode付き退避を維持する。C2/C3の編集機能はここに含めない。
