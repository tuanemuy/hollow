# P5b-3a1 全ページPDFの受付・分類・製品接続

[独立gate](../reviews/P5b-3a0.md)を根拠に、[分類protocol案](../phases/P5b-3a1-proposal.md)のB案を採用する。uploadは既conversionの明示未分類枝で即時に空note/job/月間予約を作り、背景処理で用途を一度だけ確定する。IM06は本文lockなしの短命previewで用途を先に示し、本人のmodel選択と本文置換確認後にconversionを受理する。同期分類をupload応答やUoWへ持ち込まない。AIoff/未連携・他形式は既経路を維持し、音声の製品接続は含めない。

未分類PDFは既NULL recipe1と別の判別枝にする。受理時にtext/image候補model・設定version・epochを固定し、既予約月・job・ownerを維持する。strict全文成功は既recipe2/prompt1と正常byte/hashを保持する。正常なVISUAL_REQUIRED/ORDER_UNPROVENだけが全頁描画検査へ進み、全頁健全・policy成立・実close後にpdf-pages/recipe4/prompt3/chat-imageをsealする。途中CORRUPT/暗号/資源超過/unknownを画像fallbackで隠さず、全白紙NO_TEXTも維持する。既保存recipe2の付替え・完成note自動書換えは行わない。pendingは発注/response-ready/succeeded不可、fixedはimmutable、sealは現在owner/CAS/取消世代/原本・版・権限/epochを確認する専用操作に限る。

conversionにnullableなsource_ownership_generationを追加し、新pendingと分類由来fixedは原本所属世代を必須としてseal後に固定する。値域は既Noteの世代契約と一致させる。旧fixedはNULLのまま移行・更新し、現在の世代を過去の受理値として補完しない。preview側の必須世代と分類manifest/新fixedの合法性を同時に検証する。

previewは新llm_pdf_previewsを単一正本とする。begin/status/cancel/confirmは現在actorと編集権限を照合し、GET/pollで分類を開始しない。actor+commandの同内容は同receipt、異内容は拒否する。用途/recipe/hashはclientから採用しない。本文編集は許可し、編集・移動・原本・epochの差はready/confirmで拒否する。consumeとconversion/予約/既本文版保存は同Tx、ACK不明はreceipt照会のみで自動再POSTしない。previewの有限失敗値には既LLM_UNAVAILABLEを含め、中断や利用不能をSOURCE_CHANGED/TIMEOUTへ偽装しない。失敗値の保存と物理終了証明は別の条件とし、unknownのownerを値だけで解放しない。

preview全寿命は作成から5分固定、分類は残時間以内かつ120秒まで。未消費note全体1/actor1、終端receiptはactor100件/10分を初期運用値にする。unknownを期限や件数で削除しない。既physical poolのglobal2/account1とaccount単位queued合算100をconversion/previewで共有し、conversionを優先する。queued read-pinとrunningの専用ownerをpurgeへ接続し、実close前のpin/枠解放を禁止する。ready後は実pinを解放でき、confirmで現在原本を再照合する。期限・trash・失権・revokeはfence/取消要求、旧runtimeの実終了証明後だけunknownを解決する。通常logoutは受理済conversionを取消さず、previewは本文/生成に作用しないまま有限期限へ収束する。

previewの表示用GETは現在の原本/所属世代/epoch/本文版/期限を純読取で照合し、古いreadyを確認可能として示さない。reloadでは現在本人・同noteのlive receiptだけを再発見できるprojectionを返し、他actorのID/用途/commandを開示しない。用途確定後のmodel候補と既定値は対応用途から取得し、前回本人選択やdirtyな入力をpollで上書きしない。GETで分類開始・取消・再作成を行わず、新しい保存正本や確認APIは追加しない。既React操作ownerへpreview/生成の別commandと直列読取を接続し、旧応答が現在の確認・入力を復活させることを防ぐ。詳細は[UI接続案](../phases/P5b-3a1-ui-contract.md)に従う。

一括trashの処理確認は、単一trashが取消対象にするlive previewの種別とIDもfingerprintへ含める。確認後の新規・別IDへの入替は再確認を要求し、同IDの進捗・state/version・owner tokenは集合変更として扱わない。unknownの同一previewを進捗扱いで保持しても、物理owner/pinを先に解放しない。本文版を変更しないpreviewでも、後発処理の無断取消を許さない既P3e契約を維持する。

全頁manifestはsource identity・renderer/policy・総頁/連続ordinal・寸法/bytes/hashを束縛する。表示policyは144dpi/白背景/CropBox/既定rotation/display intent/検査済annotation appearance。未知feature/form/action/OCG等は省略成功ではなく拒否する。初期運用上限は長辺1728px、PNG4MiB/頁、32頁、総PNG64MiB、頁10秒/全準備120秒、全JSON6MiBとする。3Mpxは長辺制約に包摂され独立保証ではない。既PDF原本上限を維持し、巨大原本のnative peak/RSS・全PDF互換・実認識品質は未実証。低解像度化/頁省略で上限を回避しない。context/token収容非保証を利用者へ表示する。

全N頁準備後だけ逐次再描画/hash照合して発注する。pagesは基本2N render、preview manifestの再利用もsource/policy/current一致が条件であり、任意cache命中とはしない。途中再描画失敗は残発注停止・旧本文保持、先行送信の消費1を維持する。全required応答の双方向一致だけ後処理回復、一部応答/unknownは自動再送なし。全jobの権威あるpersisted dispatchを照合して全未送信/実closeの場合だけ返却し、pure入力の前提を正式DB対で確認する。

正式移行0037/ledger38の設計範囲をllm_conversions・llm_dispatchesの限定再構築とllm_pdf_previews加算一表に限って許可する。旧全列値/NULL/PK/FK/index/trigger/ledgerを保持し、旧ordinal0..15、新pagesだけ0..31、pending発注禁止をDBでも強制する。既quota・job・note・original・object_writesの構造再構築は許可せず、必要なguard/pin/削除順の直接差を明示する。normal/SQL中断/末尾FK失敗/旧CAS/全応答回復を検証する。実fresh移行・保全・fixture・自己回収はexact申告後の別実行許可とし、設計採用を本番/外部操作許可にしない。

取り込み前の案内は、PDFの方式が全頁検査まで未確定であること、有効な連携・構成のもとで文字用または対応全頁画像用へ確定すること、有限資源内でも認識品質やモデル収容を保証しないことを示す。AI不使用時は機械文字抽出と失敗時の原本保持を案内する。静止画像の条件付き提供と音声未提供を分け、画像・音声の合算件数を全件未提供とは表現しない。[表示限定案](../phases/P5b-3a1-v1.md)のImportUpload説明と直接testのみを採用し、表示のために新DTOや連携判定を追加しない。

正式成果は[固定A〜H](../plan.md#p5b-3a1-全ページpdfの製品接続)で判定する。新port/DTOは提案を基点に内向き依存・型付きunion/境界検証・React pending/receipt導線へ接続する。実変更が完了条件へ届く既IDだけを実装前のpath対応で再openし、無変更の全認証/codec/書出しを一律再試験しない。実LLM・料金・認識品質は契約検証と別に残す。
