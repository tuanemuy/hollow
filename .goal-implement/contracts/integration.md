# P5 の成立条件

[独立した一次資料調査](../reviews/P5-feasibility.md)を後続実装の入力にする。APIの成立経路と実接続成功は区別する。OpenRouterはPKCEで得る利用者keyを暗号化して保存し、モデル生成を発注しないkey情報取得で初回疎通を確認する。callback試行の本人・ブラウザ・期限・一回限り性を検証し、資料にないstate往復を推測しない。

OpenRouter解除とDrive解除は、それぞれのHollow内credentialを破棄し、連携epoch・job取消・遅い結果の反映拒否へ接続する。provider側の全権限撤回を実行済みとは表示しない。Drive解除とGoogleのログインIdentity解除は独立し、片方の解除で他方を失効させない。

Driveは通常領域の専用folderと `drive.file` を使い、既存folder選択はPickerによる明示共有を候補とする。非表示の `appDataFolder` へ置き換えない。backupは利用者・Google sub・fileId・folderId・原本hashに紐づける。IN-07の移動時中止はfileId取得の404に依存せず、記録folderと現在parentsを照合する。

Hollowの受理上限を外部APIの一回のrequest上限と同一視しない。モデル能力に応じて画像PDFのページ処理、音声の実変換・分割・結合を設計し、欠落した内容を完全取得として表示しない。処理単位・失敗・課金と月間実行枠の数え方はP5詳細設計で確定する。

AC-03は2026-09-19の利用者決定に従い、Google初回ログインで一致する既存アカウントがあり、そのメールがGmail/Google Workspace管理外なら追加本人確認を必須とする。既存パスワードまたは新しい確認メールが成功するまでIdentityを紐付けず、既存アカウントのsessionも確立しない。過去のメール確認済みflagだけを追加確認の代替にしない。確認は元のGoogle認可試行・対象アカウント・現在browserへ束縛し、完了時に現在条件を再確認する。期限/一回限り性/再試行の初期契約は下記に従い、残る詳細は正式実装時に固定する。既存Google Identityによる通常再ログインを初回連携と混同しない。
