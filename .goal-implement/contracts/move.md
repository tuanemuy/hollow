# P3d-2の有限確認と所有移管

[単一move接続案と末尾補足](../phases/P3d-2-plan.md)の縮小案を採用する。既存notesを所有の基点とし、ownershipGenerationとresourceRevisionを追加する。現purgeの資源捕捉・writer/最後bundle確認・実回収確定後に子行とnotesを同Tx削除する順を保ち、note固有負債のための別anchor tableは作らない。draftId/sourceNoteId/reference jobIdから存続noteIdへのprovenanceをcleanupまで保持し、pin解除と所有参照の消去を混同しない。明示personalとnote不存在を区別し、不整合時に旧actor/受付WSへfallbackしない。

確認値はnote/version/所有世代、両scope ID/name/membership revision、最大50tagのID/key/name対応と正規化版、note固有resourceRevision/固定種類別count・bytes、現schemaで最大1bundleのcontentRevision/bytes/source・destination holdingに分ける。全資源ID/本文/全memberの配列や使用量snapshotを返さない。membershipの実INSERT/DELETE/role変更は同Txでrevisionを進める。管理用tag mutation_revisionは対応比較へ流用せず、別noteのdetachだけで同名対応を無効にしない。現在quotaは確定時に再算出する。

bundle_scope_holdingsはbundle/scopeごとのnote・受付・cleanupの保持理由とrevisionを元provenanceと同Txで維持する。未作成と作成後0保持を分け、bundle存続中は0保持へ戻ってもrevisionをリセットしない。0保持だけならcharge0、cleanup理由が残る場合は実回収まで課算する。companion実体/bytesは元の正本を使い、全操作履歴や全scope quota revisionを追加しない。note固有の実集合/bytes/課算状態/bind/回収変化はresourceRevisionで追跡し、時刻に依存する内訳も固定集計の再算出で照合する。移行で旧全列/chargeを保持し、初期revisionを過去操作数としない。

旧writerは取得noteId/所有世代をregister/publish guardと最終metadata/本文採用で照合し、moveの同Txで対象bound媒体の未完旧試行を終端化する。accepted/readyの既存資源は所有移管と課算を保つ。正当な初回bindだけでは一律失効させない。既存排他write/registerと上書きしないlinkを維持し、guard後にmoveが入りlate linkが生じても、最終世代/state検査でreadable metadata/本文採用を拒否する。未採用key/予約/active writerは追跡と現在scopeのchargeを保持して既存回収へ渡す。物理link自体を線形化する新gateやstream全体のUoW保持は加えない。guard→move→late link、移動ABA、cleanup失敗、bind順序、prune/purge待ちの実証は正式実装に残す。

実装の入口はapplication/moveの`NoteMoveRepository`とし、UoW内の`destinations`/`inspect`/`audiencePage`/`apply`が有限DTOを返す。SQL/driver型はadapter内に置く。新0021でnotesの`ownership_generation`/`resource_revision`、workspacesの`membership_revision`、source_bundlesの`content_revision`、`bundle_scope_holdings`の理由別count/revisionを追加する。元provenanceの実変化を同Txで追跡し、通常notes.saveはownerを変更しない。`object_writes`に取得noteId/generationを持ち、未bindの両nullとboundの対を区別する。初回bindの同Txだけで未bound文脈を確定し、移動後の世代を旧試行へ再取得しない。cleanupのcleaned限定更新は既存claim・writer終了・実removeの条件と現在provenanceを維持する。

移動で終端化する同noteのqueued/running参照jobと現在の初回表示initialization.jobIdが一致する場合だけ、同Txでinitializationをcomplete/interruptedへ収束する。job取消後も準備中を残さない。本文・style/source/hint・日時・版/pinは変えず、既完了・別job・参照なしは対象外とする。decorated時にstyleを変更する汎用interruptDisplayは使わない。失敗rollbackと遅い旧結果でも既存の本文/表示設定を保つ。
