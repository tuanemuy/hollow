# P3bの招待・メンバー・設定

[P3b接続案](../phases/P3b-contract.md)を入力とし、P3b-1の招待/認証復帰/参加/役割/退出/一般設定と、P3b-2のアイコンを分けて実装・検証する。WS-07はアイコンとP4の公開中slug警告を含むため、一般設定フォームだけで全体完了にしない。

招待を再送すると同じ招待の世代/tokenを更新し、新たな14日期限を設定する。旧リンクと旧deliveryは失効する。発行者がowner権限を失った未使用招待は無効化し、権限復帰や再参加だけでは復活しない。残ownerの明示再送で新世代を発行する。取消と配送が競合して既に送られたメールは回収できないが、そのtokenは無効である。

招待は1要求10宛先、WSのrolling24時間100送信、実行者のrolling1時間20送信、同宛先の明示再送60秒間隔とする。受理した新送信/明示再送を同UoWで数える。重複宛先と既memberへの非送信、内部再配信を追加計上せず、送信失敗でも受理枠は返さない。同request同内容の再送信は二重受付せず、枠不足は全体を変更せず拒否する。

招待権限とメールdeliveryを別状態にする。配送はDB正本、outbox wakeとboot/sweepで回復する。一般event/logには生tokenを載せない。token検索はhash、ownerの明示copy/配送は暗号化secret envelopeを使う。TokenProtectorの永続キーはDB・コードと分離し、平文fallbackを許さない。正式実装でローカルの専用キーを生成・保護してよいが、値をログ/報告/コマンド出力/コミットへ出さない。配置と起動設定は実装前の接続案で確定する。

同deliveryの内部再試行は同payloadを再現する。世代発行時に宛先/subject/token前後の本文partsを固定し、WS改名・APP_URL・表示値・文言の変更で送信内容を組み替えない。復号した現世代tokenを一箇所で連結し、WS名に含まれる任意placeholderの置換や一般event/logへの複製をしない。旧snapshotなしの未試行は初回前に固定し、attemptを永続化してからI/Oへ進む。試行済み未終端の復元不能な旧配送は現在値を旧payloadと偽らず、専用理由で停止しcopy/明示新世代再送へ案内する。宛先エラー・未配送確定・送信済み成功とは説明しない。既送信/terminalの結果とNULL snapshotは変更しない。

有効tokenのGETは参加させず、参加/辞退は明示POSTで確定する。既memberの明示参加はroleを上書きせずtokenを消費する。同メール招待による確認省略は新規signupだけに適用し、既存accountへtokenだけでsessionを発行しない。異メール登録は通常確認、異メールでの参加は明示確認とする。認証復帰先はnote/invitationの限定unionとし、任意URLへ緩めない。

招待の明示操作と招待付き認証は、画面が保持する非秘密のinvite ID/generationをvalidated expected selectorとして渡す。selector自体は認可に使わず、現在のbrowser-bound continuationと照合する。不一致では両招待とmembershipを変更せず、対象の招待メールからの再開を案内する。同じbrowserで別招待を開いてcookieが変わっても、古い画面の参加/辞退を別招待へ適用しない。招待付きsignupの確認省略はpassword hash後の同UoWでも元selectorを照合する。認証後returnも元対象を保持し、自動参加しない。通常のaccountメール確認は独立して維持し、元対象を保持できないreturnで別招待を同一対象として説明しない。通常認証、30日session、既定のcontinuation寿命は変えない。P3b-1-B/F・P1-Aの検証では、同browser A→B→旧Aの拒否とBの明示成功、再送旧世代、登録確認省略と認証復帰を確認する。

辞退の成功応答はroot Outlet外の小さい通知hostへ渡す。通知は1件の非永続React stateで「招待を辞退しました」と閉じる操作だけを持ち、秘密・本文・メール・権限を保持しない。認証済なら/notes、匿名なら/へ通常navigateした後、プロジェクト規約のrouter.invalidateを行う。既存TrashProviderと同形の表示責務に限定する。直接visit/reloadの通知初期stateはnullとし、元の招待再訪は既定の終端拒否を表示する。現在のterminal routeだけを除くfilterとinvalidate自体の省略は採用しない。失敗・応答喪失で完了表示を推定せず、terminal情報のreadや秘密の保持期間を拡張しない。通常メール確認の完了時に招待returnを設ける場合は、その時点の認可済selectorを固定し、確認画面で実際の招待対象を示す。登録開始時の対象と同じと保証できなければ、同じ対象へ戻るとは説明しない。

raw tokenを含む招待入口は準備statusを表示し、秘密URL除去とselector付きtokenless確認画面への遷移後に認証・参加・辞退を表示する。準備失敗には再試行または元メールからの再開を提示し、準備中表示に閉じ込めない。用意済みtokenless画面の通常操作はこの準備のために再ロックしない。

member表示名未設定はemailを代替表示する。joinedAtは正当な作成/参加記録だけを使い、不明を移行日で補わない。最後owner・自role変更禁止を同UoWで守る。編集権限を失う変更と同UoWのindexed SQLで、当該actor/scopeの旧conversion/reference jobを不可逆に終端化し、再参加で旧leaseを復活させない。別actor/scope・同値role更新・編集権限を保つowner→editorをnote job取消へ巻き込まない。発行者owner喪失による招待失効は別に実行する。初回displayの対象job一致時だけnotes.versionを制御guardとして進め、本文/title/style/updatedAt/revisionNo/保持版version/pin/creator/uploaderと保持originは変更しない。既fence purgeは回収を続ける。

`/workspaces/$workspaceId/settings` は型付きGET loader bridgeからWorkspaceSettings clientへ直接seedする。RSC fragmentのclient islandが同bundle通常再起動/new hard openで無反応となり、static参照追加後にも再発したため、このrouteだけを例外にする。getWorkspaceSettingsとowner時のlistInvitations（page50）を現在policy・外部入力validation境界で取得する。serverDataのinternal-only契約、各mutation/次pageの現在認可、親optimistic/rollback/invalidate/cursorを維持する。fragment streamingの代わりに設定向けroute-level pendingとerror/retryを使い、他routeのRSCを変えない。一般的なframework根本原因の特定や全画面の方式変更ではない。

P3b-2のアイコンは5×1024² bytes以内のPNG/JPEG/WebPを専用portで安全化し、最大512px内・512KiB以内の静止WebPを正本とする。動画像は先頭フレームを使うことを表示する。画像metadataを除きorientationを補正する。入力検査と変換の処理全体は30秒以内とし、既存40Mpixel/1000frames/160MBのdecode上限を緩めない。先頭frame変換だけの部分測定と、最終adapterの全内容検査を含む測定を区別する。専用provenanceの実体/予約/cleanupをWS容量に含め、交換失敗は旧表示を保持する。配信は現在member、または当該有効pending招待のcookie/selector認可に限定し、当該WSのcurrent iconだけを返す。note媒体/未保存draftの認可例外を作らない。public配信とWS削除は後続へ接続する。

WorkspaceIconRepositoryとUoW、専用workspace_icons表、workspaces.currentIconIdを使う。成功時だけ既存settingsVersionを進め、一般name/slugとnote本文/日時/版/pinは変更しない。入力実bytesを予約し、入力tempの除去確認後に最終WebP実bytesへ再課算してquotaを再照合する。派生物put後の同UoWでも現在owner/対象/期待settingsVersionを照合し、現iconを交換する。awaiting未送信予約は10分、processing/writingは操作開始から30秒の処理abortを持つ。cleanup sweepは30秒ごと20件を初期値とし、失敗時は行/bytes/理由/nextAttemptを保持して30秒後に再試行する。固定回数で未回収物を放棄しない。既存physical key claim/write ownershipへ専用icon種を接続し、失敗/旧物をcleanupへfenceした後も全active writer終了・実remove・同token確認までchargeを解放しない。予約期限や論理終端をlive writer終了の証拠にしない。crashは既存の確認済み旧process終了によるwriter回復後、deadline経過かつactive writer0の未完了行だけを回収する。入力tempをfilesystemへ置く場合もcrash後の実在/除去を追い、未記録tempを残したまま予約解放しない。boot/sweep/drainをNode既存ライフサイクルへ接続する。

membershipのowner→non-owner（降格/除名/脱退）と同UoWで、当該actor/WSのawaiting/processing/writing icon行だけを不可逆にcleanupへfenceする。notejobのedit-loss条件とは分け、owner→editorでも旧icon更新を失効する。ownerActive(icon-upload)はprocessing/writingだけを認める。権限復帰や再参加で旧行を戻さず、新予約だけを正常に処理する。採用済みcurrent iconの表示/所有を元upload actorの失効へ巻き込まない。

icon入力は5MiB以内のbounded memoryで受け取りworkerへtransferし、raw filesystem tempを作らない。既存mediaWorkerの画像検査へadapter内部のBuffer Readerを追加し、fileReader経路と全frame/40Mpixel/160MB/末尾構造検査を共通で維持する。512KiB以内の出力もメモリで返し、最終bytesへのquota再検証後だけstorage.putする。未記録のrawfileを残すcrash経路を作らない。共通画像検査の正常/破損/上限と全処理deadlineを狭く再検証し、他codec方式を変更しない。

保護keyは専用の本人用directory0700/file0600へ排他的新規作成し、パスだけを `HOLLOW_INVITATION_KEY_FILE` 相当の設定で渡す。今回のlocal永続pathは `/Users/hikaru/.local/share/hollow/keys/invitation-local-20260910.key` とし、OS清掃対象の一時dirには置かない。既存pathのtype/owner/symlink/権限を確認し、既存keyを上書きしない。同DBの再起動では同じkeyを使う。鍵なし/誤keyを明示的な構成エラーとし、通常authや秘密不要の取消は止めない。設定回復は通常再起動で確認し、hot reload/KMS/rotation UIを追加条件にしない。暗号方式はNode公式資料で確認し、envelopeを用途・invite ID・世代へ束縛する。

AuthContinuationは発行24時間とinvite期限の早い方まで、非sliding/browser-boundとする。明示request receiptはactor/request ID/正規化payload digestを24時間保持する。世代ごとのterminal最小metadataは終端から90日、秘密envelopeはterminal/supersession時に同Txで失効させる。期限後は全readで拒否し、bounded sweepで秘密を削除する。再送で過去世代の保持期間を延長しない。

deliveryは初回I/O試行から24時間以内、最大6回とする。初回後の待ち時間は前の失敗確定から1/5/15/60/240分。I/O deadlineは30秒、leaseは90秒を初期値として異常対で確認する。構成待ちはI/O attemptを消費せず、invite期限は延長しない。上限後はfailedとしてcopy/明示再送へ案内する。外部到達のexactly-onceは保証しない。rate行は24時間の窓外だけをbounded cleanupし、履歴削除で枠を回復させない。

実メール到達はP5の実接続待ちとし、P3bはlocal mailboxの契約検証で進める。
