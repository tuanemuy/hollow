# P4の接続判断

[P4原文準備](../reviews/P4-prep.md)と[共有契約案](../phases/P4-shared-contract.md)は実行時未検証の設計入力である。以下はOR-12/SH-07/WS-07とEX-01〜04に接続する共有契約であり、P3bへ公開・書き出し実装を前倒ししない。

P4-Q1は所有namespaceから独立したnote公開identityとURL世代を使う。移動で公開identity・URL世代・限定token・creatorを変えず、現在scopeとtimeline所属だけを更新する。個人/WS公開ページは現在handle/slugで解決し、変更前のページURLから元の対象へ転送しない。未割当の旧URLはnot foundとする。WS-07のslug変更による失効はWS公開ページに限定し、noteの中立URLや限定tokenは失効させない。元所有者/WSが削除されても、移動済みの存続noteを巻き込まない。

SH-07は2026-09-19の利用者決定を優先し、creatorの公開handle変更でも既存noteの公開identity/URL世代/限定tokenを維持する。脱退したcreatorの変更で他人/WS所有noteを失効させない。変更するのは本人プロフィールのURLと著者リンク先だけで、旧URLから元プロフィールへ転送しない。初回handle設定も既存noteのURLを変更する理由にしない。unknown/退会済みcreatorを現在owner・uploader・handle文字列の再利用者へ付け替えない。具体routeと公開前提の接続は正式フェーズで確定する。

[公開接続の読取案](../phases/P4-public-contract.md)に基づき、旧handleの再利用はP21画面案どおり許す。変更後の未割当URLは404、別人が再取得すればその人の現在プロフィールを返す。note著者はaccount IDから現在handleへ結び、旧文字列による逆引きをしない。恒久tombstoneや独自保留期間は加えず、設定解除・退会後の扱いは後続の詳細判断へ残す。

再publicでは既存note公開identity/URL世代を復活させる。private/link中はcanonical入口を404とし、SH-04の再発行は限定tokenだけを変えてcanonicalは維持する。public導入時は現schemaのtoken必須CHECK、publicでのpassword禁止、SH-02のtokenリンク取得と現在token readerを整合させる。新identityの初回発行方法・具体route・schemaは正式sliceで決め、準備案の別表や世代初期値を未検証のまま採用済みにしない。

公開済みnoteの移動は新たな公開操作とみなさない。移動先handle/slug未設定による追加拒否や自動非公開化をせず、OR-12の状態/URL維持を守る。その後の公開操作には現在所有scopeのSH-01前提を適用する。この原文未指定部分の読み分けはbriefの仮定として明示する。

P4-Q2は生成入力snapshot、実artifact、要求/job、閲覧根拠を分離する。入力identityはnote IDと出力に含むHTML/title/filename/styleMode/style/正確な媒体内容・metadataで決まり、note.versionやupdatedAtだけには依存しない。内容不変の移動で無用な再生成をせず、移動後の現在認可を別に確認する。生成中に異なる版の本文・素材を混ぜない。

現在内容と一致し、現在閲覧が許可され、保持期限内の同artifactだけを再生成せず返す。PDF24時間/ZIP7日を再取得で延長しない。内容不一致の旧artifactは渡さず、閲覧可能な本人には更新と「最新の内容で作成」を示して明示的な新要求へ案内する。閲覧不可なら内容変更を漏らさずnot foundとする。旧private本文のPDFが、編集後publicになったnoteの現在認可だけで匿名へ漏れる経路を防ぐ。アプリ内も同じ内容一致を適用し、export独自の過去版閲覧権限を増やさない。

同noteのPDF実生成中は並列生成を追加せず終端を待つ。生成中に内容が変わった場合は旧結果を渡さず更新/やり直しを案内し、新要求を最新snapshotの生成・一致cacheへ接続する。計算結果を共有しても要求者ごとのjob所有と現在認可を分離し、匿名は自分の短期ticketと画面内進捗だけを使う。旧token・URL世代・password通過状態を、新たなpublic根拠へ無言で付け替えない。

ZIP生成中の削除/失効/内容変更は対象別に除外または失敗とし、正当な兄弟と失敗一覧を残す。完成後の一部失効/内容変更では旧ZIP全体を配らず、現在取得可能な対象で新しく作成する明示確認へ案内する。完成済みjobを無言で書き換えたり失敗子retryへ偽装したりしない。本人jobの取得は本人認証に加えて全含有noteの現在閲覧と内容一致を要求し、現在publicの独立根拠も評価する。membership失効者のblacklistは作らない。失効対象の現在titleや本文を回復画面用に新取得せず、最小の元job metadata/対象順/理由で説明する。

PDF24時間・ZIP7日・job90日・匿名ticketは別寿命として維持する。PDF/ZIPの期限は実体の保存が完了し、同Txで取得可能にしたpublishedAtからそれぞれ24時間/7日とする。nowがexpiresAt以上なら取得不可で、再取得やticket再発行で延長しない。組立用holdによる内部の実体保持は、期限切れ単件PDFの取得許可を延ばさない。

[履歴起点の読取補足](../phases/P4-export-feasibility.md#追補-job-履歴90日の起点)に基づき、新exportの本人request/jobは受理時のcreatedAtから固定90日とする。終端時刻・閲覧・再取得では延長せず、失敗子retryも親のcreatedAtを維持して新attemptだけに新日時を付ける。nowが各履歴のexpiresAt以上なら旧titleや詳細を表示しない。進行中処理、新しい子履歴、artifactの取得対応、物理回収に必要な最小shellは別寿命で保持し、期限外の全履歴を残す理由にしない。旧job各種の既存方式は変更しない。期限外親から必要な新子・処理へ到達する具体DTO/schemaは正式実装時に確定する。

ticket/rate/resource値、renderer/schemaはP4正式詳細化へ残す。取得済みbytesの回収や無制限の配信途中監視は保証しない。

P4-Q3はSH-01の所有scope別公開前提を一括にも適用する。個人所有は公開handle、WS所有はWS slugを使う。現在scopeの公開前提が不足する場合は、一括処理を開始せず設定へ誘導する。開始後に対象の権限や本文状態が変わった場合は対象別に結果を残し、正当な兄弟を継続する。
