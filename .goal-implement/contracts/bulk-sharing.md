# 一括公開範囲変更の接続判断

[一括共有の読取案](../phases/P4e-batch-sharing-contract.md)を次の限定で採用する。実装は正式フェーズ委譲後とし、P4d-0中に並行開始しない。既存batchの固定source/最大500対象、親受理、子attempt、現在actor、同UoWの変更と結果を再利用する。親の不変intentは目標visibilityだけとし、password設定・token再発行・一括リンク取得を加えない。

publicの開始前に現在所有scopeのhandle/slugを検査し、不足ならOR-09どおり設定を促して全体を中止する。設定画面への導線は提供するが、一覧離脱後の選択自動復元・専用継続ticketは追加しない。SH-01の単件設定復帰は既存どおり維持する。設定後の一括操作は現在一覧で選び直し、新previewと明示確認から行う。WS editorにownerの設定権限を与えない。

公開確認は保存済み本文の一般公開と検索対象化を説明し、privateで準備済みのものを含む各保護対象について解除同意を得る。同意はnote IDと現在shareVersionに束縛して子attemptへ保存し、親の永久booleanにしない。再試行の同じ設定は同じ目標visibilityを意味し、現在previewと保護への新しい同意を必須にする。snapshotの厳密一致と利用者の同意は別々に検証し、両方を受理の同内容判定に含める。

同visibilityの子は現在認可・共有/本文/所有/membershipの確認値と、その状態に必要な業務条件を検証した後に限り変更不要の成功とする。単件APIの再適用の意味は変更せず、一括では不要なshareVersion/grantEpoch更新やtoken生成を行わない。結果表示で変更済みと変更不要を区別する。preview後にpassword/token/grantを含む共有版が変化した子を、目標文字列の一致だけで成功にしない。public前提や不正状態も変更不要を理由に迂回しない。

認可された空本文はpreviewに理由を示し、public/linkへの変更条件を満たさない子として受理後に理由付き失敗を残す。権限外対象の非開示除外とは区別し、正当な兄弟を継続する。本文が用意された後は同じ目標の失敗子を新previewで再試行できる。EXの空本文除外規則を共有へ流用しない。private化には公開用本文条件を足さない。

単件共有のTx内coreを抽出し、現在認可・OCC・token/grant/public identity/accessEpochの既存契約を一括にも適用する。移動ABA、外部取消、WS削除、ACK不明、90日履歴は既存batch契約を維持する。UIの不明時の明示同ID再送を読取専用照会と呼ばず、新ID自動送信や現在visibilityからの成功推定を行わない。

[P4e詳細案](../phases/P4e-proposal.md)の共有core・型境界を採用する。visibilityだけをapplicationの同Tx関数へ抽出し、single-reapplyとbatch-convergeを型で区別する。現在認可・厳密expected・業務条件を照合してから、一括同値だけを変更不要として返す。単件password/再発行の意味は維持し、workerはsessionではなく現在actorを検査する。共有mutationと子finishは同UoWで確定し、finish失敗で両方rollbackする。

previewの共有snapshotと利用者の解除同意を別型にし、検証後の両者を永続子attemptへ束縛する。共有専用のcanonical inputは固定key順・対象順序・snapshot・同意・retry識別を含み、旧tag/trash/moveのdigestやlegacy補完を変えない。未知ACKの再送では新previewへ同payloadをすり替えない。

成功resultは旧操作とsharingの判別可能な型を使う。sharingには変更済み/変更不要と目標visibility・変更前後の共有版を保存し、本人履歴DTOは保存済み結果から投影する。旧result JSONは書き換えず、検証後に内部existing枝へ投影する。旧結果や後日の現在visibilityから共有結果を補完しない。unknown kind/不正shapeは整合性エラーとして拒否する。既存JSON列とguardを使う最小構成とし、schema追加不要の成立は正式実装の互換試験で確認する。

UIは現在actor/context/mount/操作世代を照合してsuccess/catch/finally/focusを適用する。未実証の静的懸念を既存不具合と断定せず、変更する経路だけを検証する。7条件案と実影響候補は正式フェーズ委譲時に固定し、独立検証中のP4d-3や未変更の既受入条件を先行再開しない。
