# P3cの検索・日付・タグ共有契約

[共有契約案とタグ補足](../phases/P3c-shared-contract.md)を入力とし、以下の意味と境界を採用する。索引方式・実行資源・初期値は後述の方式採用に従う。P3b-2へ検索実装を前倒ししない。

検索はtrim後の入力が2 Unicode code point以上のときだけ実行する。未入力は通常一覧、1文字は入力案内、記号だけでtermがない入力は検索可能な語の案内とし、全件検索へ化けさせない。比較用projectionはNFKCとlocale非依存の小文字化を使い、連続ASCII英数字を一語として語頭一致、日本語など非分かち書きの連続termを部分一致とする。空白/句読点と日本語・ASCII英数字の境目でtermを分け、全termをAND、各termのtitleまたは本文一致を認める。Cloudflareをcamel case分割しない。分割後の1文字termを黙って捨てず、raw queryをSQL/FTS構文として解釈しない。

現在HTMLから構造上の本文textを投影し、原本/履歴/draft/属性/URL/CSS sourceを検索対象にしない。parserでentity・block/cell境界・inline連結を扱い、script/style/head/template/commentを除く。任意CSSや端末幅によるpixel可視性は保証せず、hidden/明示inline非表示の細部は正式projection規則で固定する。表示textと比較textのoffsetを対応させ、highlightはtext/rangeまたはsegment DTOからtext node/markで描く。本文HTMLやFTS highlight文字列をアプリへ直挿入しない。

関連度はtitle完全一致、全termがtitle、titleと本文に分散、本文のみの段階とし、同順位はupdatedAt/ID降順とする。別scope/private corpus頻度を公開順位へ混ぜない。title順は永続NFKC/小文字化比較keyのbinary順＋IDとし、page内JS sortで全体順を装わない。かな読み/自然数順や全言語検索同値は追加しない。

索引は候補限定であり、現在note/scope/lifecycle/membershipまたは公開eligibilityのSQL joinを認可の正本とする。正確なterm照合後の集合へorder/keysetを適用し、最後にLIMIT51、最大50件のmetadataと有限抜粋を返す。候補先頭N件の打切り後にJS照合して一致を欠落させない。件数/tag/calendar集計も同じ認可集合に限定する。現在HTML/title/eligibility/所有/tagとprojectionは同UoWで確定し、outbox遅延だけへ正確性を依存させない。事前解析は投影元identity/versionをcommitで照合する。backfillはbounded keysetと版照合で再開可能にし、空索引を完成検索として見せず、失敗しても原noteのHTML/title/日時/版を変えない。

前処理したASCII英数字tokenとencoded1/2-gramを標準FTS5へ入れる。標準trigramだけで2文字要件を満たしたとせず、全HTMLのJS配列化/無言全文scanへfallbackしない。期限はUI timerだけでなくDB実行の停止または隔離資源の確実な終了で成立させ、未確認driver private APIや既存FD対策の解除を前提にしない。派生索引bytesを利用者のobject quotaへ加える新会計は設けない。隔離成立の範囲と正式実装の残条件は後述する。

日付条件はcivil month/dayと検証済IANA zoneからUTC半開区間へ変換するportに置く。OR-02/05はcreatedAt、P4公開検索期間はupdatedAtとする。月30日/日24時間/固定offsetを仮定しない。存在しない/重なる境界はcivil date開始の最初の有効instant、存在しないdayは空区間とする。URLの有効zoneを優先し、なければbrowser zoneを月確定前にURLへ反映する。SSR未判明中は日付部分を準備中とし、失敗時はUTCを明記して検出再試行/zone変更へ回復できる。プロフィール設定を先行実装しない。

view/通常sort/zoneをpreference、query/tag/monthをscope filterとしてURLを正本にする。calendarは同じmonth/filter、dayごとの件数と有限初期項目・createdAt/IDの独立cursorを使う。月全noteをJSへ集めない。calendar中sortを無効にして通常sortを保持し、月解除はlistへ切替える。scope切替はfilter/cursor/day展開を解除し、calendar時だけ新scopeの現在月を設定する。検索適用は関連度を既定、解除は検索前の通常sortへ戻す。cursorは検索面/意味version/scope/全条件/比較tupleに束縛し、旧成功/失敗を新画面へ適用しない。live keysetはrequestを跨ぐ全件snapshotを保証せず、既知変更後invalidateと重複ID排除で扱う。全選択集合固定はP3eへ残す。

タグはscope別immutable ID・trim後表示名・比較keyを分ける。比較keyの意味は幅decompositionのwide/narrow mapping Wとdefault full case folding CFによるNFD(CF(NFD(W(name))))とする。C/F mappingとcanonical normalizerは製品の同じUnicode版へ固定し、locale固有T mapping・かな変換・アクセント除去・内部空白圧縮・不可視文字除去を加えない。NFKCの互換文字全体の折畳みはタグには採用しない。意味/versionは内側、必要な固定mappingの同期純粋normalizer portを内側へ置く。版変更時に異なるIDを自動mergeしない。表示名50code point・note50一意tag ID、scope+keyのDB一意性を最終判定とする。

OR-04は現在scopeのactive可視note使用件数で頻度順、同数は比較key/ID順とする。query/monthによるfacet連動は追加せず、使用0件は管理用queryに分ける。tag検索/pageは認可済SQLで有限に取得する。URLはscope内tag ID、renameはID維持。削除/不明/他scopeの選択IDは存在情報を出さず0件と条件解除を示し、条件を捨てて全件へ広げない。P3d merge/delete後の旧IDを自動aliasにしない。OR12同名付替えとP4横断tag-name検索は同じkey契約を使う。P3cは実reader/relation/AND filterまでを実装し、空配列固定で完了とせず、実tag作成/管理/移動のend-to-endはP3dへ残す。
