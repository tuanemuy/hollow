# P2b-C の永続化と資源境界

P2b-Cの参照設定・現在対象集合・恒久台帳はnoteに属するtyped tableへ保存する。reference jobはconversion jobとは別のtyped tableとし、同じUoW/outboxと処理履歴へ接続する。参照assetはorigin note/jobのprovenanceを持ち、draft stagingを経由せず現在note参照を必要とする。同じnoteへの保存再添付とready/7日猶予は維持する。候補URLとstylesheet markerは利用者入力であり、他noteの台帳やasset認可を借用する根拠にしない。

参照jobのcommitはactive generation・note version・現在所有権・leaseを条件にする。古い結果のobjectは予約容量を維持したcleanup対象にする。companionはrole/pathを持つ予約と原本recordで管理し、batchをsealする。off/失敗から後で取り込めるよう、bundle原本とnoteの関係を現在の画像refだけで破棄しない。

外部取得の追加運用境界はHTTP(S)の80/443、redirect最大5、1取得30秒、binary100MiB、画像検査20MiB。参照集合200件/100MiBと合算容量を別に適用する。CSSは1stylesheet1MiB・埋込合計512KiB、最終HTML800KiB、DOM1万/AST10万/照合200万stepとする。参照worker同時2、個別取得は逐次、lease60秒/heartbeat10秒、起動時と5秒sweepを用いる。これらを原要求の上限と混同せず、超過理由を台帳に示し、CSS超過で元本文を消さない。

reference jobの実行期限はclaim後5分、claim最大3回とし、queued待機を期限へ含めない。期限時は検証済み部分を条件付き保存し、残りを未試行/時間上限として台帳に残す。jobは理由付き失敗とし、新jobのretryで未取得分だけを再開する。通常取消は現在の1取得の完了を待ち、未開始対象を取り消して完了分を保持する。cancelledに失敗理由を持たせない。権限喪失や古い版によるhard取消は結果不採用とobject cleanupへ進む。

companion-only batchは入口で明確に拒否する。bundleと本文noteの関係を保持し、off/失敗でも最後の関連noteの完全削除までcompanion原本を保持する。sealed batchで関連noteがなく、未完了の本文受理とも競合しない孤立companionは回収する。回収中の受理を防ぎ、storageの実削除または不存在を確認してから行と予約容量を解放する。削除失敗は容量を保持して再試行する。完全削除への回収接続は後続P2dで確認する。

CSS再利用は現在同note本文の利用可能snapshotを必要とし、参照除去後の再追加は新しく取得する。正常な空stylesheetは再取得loopにしない。[独立再検証](../reviews/P2b-references.md)で、旧候補のbase付き空CSSと取得済み台帳が残る状態は正常な空CSSと区別できないため、自動修復の対象外とする制限を採用した。明示的にstyle参照を除去して保存し、元linkを再追加すれば回復する。baseなし空placeholderの回復を、旧状態全体の自動修復と説明しない。
