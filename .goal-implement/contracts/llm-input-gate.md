# P5b-2b の提供前gate

技術資料の原本24個/20MiBを保ち、既派生PDF1件を独立writer由来の日本語正例、原本由来の派生Office正例2件（各64KiB以下）を非text媒体notice/group/table用に追加検証する。負形4件はin-memoryだけとし、独立検証の2列2行PDF反例1件を加え、総入力例は最大32。純粋な配置判定の境界対は保存原本数と区分する。派生render/資料保存全体64MiB以下、工具2GiBは別。手製PDFの表示不合格と初期判定の履歴は保持し、抽出一致と描画成功を別判定にする。CFB header負対を正規Office暗号文の全対応と称さず、実資産と合成形の限界を区分する。

Office正例のvisual検証に必要な工具は、新probe root/toolsへ隔離したLibreOffice公式macOS arm64版のheadless実行だけを条件付きで使う。公式HTTPS URL/版/公開checksum・署名/空き容量を照合し、工具とその派生は合計2GiB以下（確認済み仮想volume全量1,572,864,000B＋DMG297,798,926Bを保守計上し、profile等も加える。実disk占有とは区分）。取得前に具体対象を報告する。通常app/prefsや製品依存を変更せず、GUI/admin/Gatekeeper回避/remote template0。自己合成資料・専用profile・allowlist envと自己PID実終了を守り、readonly/noautoopen mountを使う場合も自己exact対象とhandle0を確認して解放する。条件不成立は工具導入を止め、構造検査をvisual成功に読み替えない。

[P5b-2b提案](../phases/P5b-2b-proposal.md)に基づき、製品非変更のP5b-2b0でOffice/文字PDF/単画像・保存拡張・実終了を先に検証する。これは対応形式の最終受入ではなく、原文IMの未対応を除外する決定でもない。製品変更と通常freshへの移行はgateの独立受入後に別委譲する。既受入commit3650ec6を保ち、proof専用のprototype・合成資料・synthetic DBだけを作る。

Officeは全対象文字/構造とpackage単位順の網羅を検査し、非text媒体だけが未解釈と判定できる場合は固定notice付き構造化を許す。原文は抽出結果の構造化であり、図の意味の解釈まで成功と表示しない。文字欠落・未知の文字bearing part・壊れた関係は発注前失敗にする。DOCXの本文/table/notes等、XLSXの全sheet/座標/結合/式と保存結果、PPTXのslide/表/group/notes/継承文字を代表資料と明示inventoryで照合する。未知の文書まで全文保証と拡張しない。既機械parserは変更しない。

文字PDFは全頁をtext-covered/proven-blank/needs-visual/indeterminateへ分類するstrict gateを初期方式とする。同頁の文字＋画像、OCR層＋下絵、画像頁・不明頁を黙って捨てない。2bの配置許可集合は水平LTR・単純な左揃え単列・上から下へ非重複な行・幾何的に連続する行内断片に限定する。大きな行内空隙、左端の変動、複数列、逆順、重複、回転、不正な寸法は不明として拒否し、文字の並べ替え・削除で成功に変えない。純文字の順序と描画operatorの許可境界はprobe根拠で固定し、複雑な図や順序不明は2bで提供しない。中央見出し・字下げ・logo入り等の正常資料も拒否し得る限定方式であることを表示し、これらはP5b-3の画像/混在PDF対応へ必須残件として引き継ぐ。全PDF完成・万能な読み順推定とは扱わない。

単画像のprobe候補は既受付の静止JPEG/PNG/WebP/GIF。単frame完全decode・EXIF向き補正・sRGB・metadata除去・白背景alpha合成・PNG派生を使い、原本は変更しない。縮小/切抜きなし、向き補正後長辺4096px/16Mpixel、派生PNG8MiB、全JSON12MiBを検証候補とする。APNG/animated GIF-WebP/MPO等の先頭だけを使わず、未提供範囲を明示する。数値・白背景の可読性・全codec提供はprobe後の判断であり、採用済み品質保証ではない。

text-blocks/single-rasterとchat-text/chat-imageを対応する内向き判別unionとして詳細化する。画像profileのprototypeは、版/期限付きadopted-default又は15分live customのimage入力/text出力/chat/max_tokens能力、画像寸法/PNG bytes/JSON上限、text指示とoutputの事前制約を検査するresource-only方式を採用する。画像tokenをbase64/UTF-8 bytesやGoogle直接APIの式から推測せず、画像込みcontext適合保証とは型・表示・報告で区分する。現能力不明/鮮度不足/最後の完全集合で明示否定は拒否するが、未確認customを恒久的な非対応へ変えない。provider context拒否はsafe failure・旧本文保持・fallback0/自動再送0とし、送信intent後なら既quotaどおり計数する。境界対の独立受入後に製品採用を別判断し、実LLM品質・費用は未検証のまま区分する。

保存は提案Cのllm_conversionsだけの限定再構築をsynthetic DBで検証する。旧表再構築禁止の例外はこのprobe内だけで、製品0034の編集・新migration追加・現fresh DB適用は許可しない。全旧列/PK/期限/owner/response予算、関連dispatch/reservation/bucket/FK/trigger/index/ledgerと回復意味を保持し、正常・途中SQL失敗・末尾FK失敗を確かめる。active/unknownを終了へ変更しない。別表群の二重正本を避ける利点と、一回のDDLリスクを実証後に判断する。

実終了はowned source FDとWorker exit、native codecで必要なら固定専用childのexit/全pipe closeまで確認する。新childはprobe内の自己所有だけで、allowlist env/固定entry/有限I/O・TERM後の終了未証明はunknown保持とする。時間経過だけの枠解放・未知PID操作・SIGKILLは行わない。技術資料は新private rootの最大24個・合計20MiB、app account/note/runtime/browser/fresh移行は0。実資産の形式検証には適用docx/pptx/pdf skillを読み、利用可能な手段と未実行の限界を報告する。xlsxは利用者向け表成果物ではなく入力抽出の試験資料であり、故障fixtureを正しい完成表へ修復して試験を消さない。
