# P5aの保存・実行・検証境界

詳細案の4表（google_identities、auth_browser_contexts、google_auth_attempts、account_auth_challenges）と4専用repository、nullable session browser binding、Account保存のinsert-only化、限定verify更新を採用する。認証の現在確認・方法更新・challenge消費・必要なsession遷移はUoW内の短い同一Txで確定する。Google-only新規の方法0はTx内部だけに限り、外へ公開・commitしない。既存sessionは移行時に一括書換えせず、既存hash・account・固定expiryを保持する。

0032は停止下の専用connectionだけでFK OFFをTx外設定し、accounts再構築と移行記録・Tx内foreign_key_check assertionを一つの原子的移行として扱う。既存Drizzleの呼出先である固定libSQL client.migrate公開APIが単一接続・Tx外FK設定・SQLとledgerの原子的commitを担う既存経路を使い、独自の危険なPRAGMA runnerを重ねない。正常・失敗ともFK ONへ戻し、再確認してから利用を許可する。他の移行への新たな無条件FK OFFや旧migration編集はしない。実libSQL cloneで旧全列値・FK・index・trigger・FTS・objectsの保持と、途中失敗/末尾FK違反時のschema・data・ledger rollbackおよび接続状態復帰が成立した後だけfreshへ適用する。rename参照やmigration runnerの原子性が成立しなければ適用を止め、具体差を再提案する。

新しいHttpOnly browser cookieはbootstrap応答で確立し、次の同origin POSTで返送を確かめるまで認証を進めない。browser epochは単調CASとし、session発行・旧session削除・epoch更新・attempt完了を同Txへ束ねる。既存bound session/attemptのあるcontextをensure/pruneで削除再作成し世代を戻さない。cookie/context不一致のattemptを新contextへ移植しない。並行bootstrap・legacy sessionの初回接続・cookie喪失・遅いSet-Cookieは実HTTP契約で確認し、成立しない境界をUI guardだけで隠さない。sessionの共通readが現在epochを照合する。Node共通fetch入口は全ページ/RSC/serverFn/resource/callbackに対し、bound sessionのbrowser hashと現在HttpOnly cookieの一致も確認する。不一致では当該Requestのsession cookieだけを下流へ渡さず、他browserのDB sessionを削除しない。legacy NULL bindingの互換は保持する。通常の未認証拒否・Origin/CSRF・callback stateを弱めず、認証付き操作を別公開根拠へ自動fallbackさせない。一般認可の全呼出へbrowser cookieを追加しない。

GoogleOidcと専用AuthenticationSecretProtectorを内向きportにし、PKCEは専用AES-256-GCM鍵とattempt/mode/browser epochのAADで保護する。既存google-auth-library 9.15.1の公開APIは認可URLと署名検証に使い、固定Google token/証明書2URLのHTTPだけはnative https.requestの専用transportとする。gaxios/node-fetchのサイズ超過reject＋abortだけでは所有bodyのcloseを確認できないため、汎用応答へのcastや新依存を加えず所有を追える経路を採用する。内向きGoogleOidcの契約は変えない。

交換と鍵照合は合計10秒、retry0、redirect拒否、同時HTTP4・queue0。callback/code4KiB、ID token16KiB、token応答64KiB、鍵応答256KiB/32keysの上限をbody消費段階で契約確認する。通常transportは固定https host/path/portとagent:falseで、任意URLを本番入力から選ばせない。request/response/自己socketのcloseを開始時から監視し、正常・上限・abort・接続失敗の全経路でfinally destroy後の実終端を待ち、枠を先に解放しない。外側signal/deadlineを伝播する。bounded unknown JSONと許可headerだけを境界へ返し、圧縮応答は展開後上限も守るか未対応として安全に拒否する。人工応答だけで終了を保証せず、trusted test request factoryからの自己動的loopbackでrejectと3所有closeを別観測する。JWKS cacheは公式期限と6hの短い方、unknown kidのrefreshは一操作一回・同時共有とする。不成立なら実装案を戻し、未確認の終了を成功扱いしない。

password hash/verifyは専用実行portの全体2・queue0でTx外計算し、確定Txで現在hash/authVersionを照合する。既存hash方式・強度は変えない。OAuth開始はbrowser5回/10分・非terminal3、password proofは対象accountに既存同等の段階待機/8失敗15分lock、mailは既存宛先60秒制限を共有する。pruneは100行/60秒、秘密は終端で即scrubする。browserのretain_untilは生存browser cookieの寿命も覆い、認証試行やsessionの固定期限自体を延長しない。authBrowsers.pruneは新bound sessionのexpiresAt<=nowだけを先に回収し、現参照0かつretain_until経過後のcontextへ進む。同呼出のsession/context削除合計はlimit以内とし、旧NULL legacy session・active session・固定expiryは変更しない。停止は新受付を閉じ、HTTPをabortし実promise終端を待つ。Google未設定でもpassword認証を起動できる。

現在のruntime排他はstorageDirectory単位であり、同DBを別storageDirectoryから使う生存processの不存在までは証明しない。認証attemptにも実行owner対応がないため、bootで全exchangingを一括recoverするportは接続しない。終了証明のない試行を保持し、元の固定10分期限で秘密をscrub/pruneする。同code再交換・新期限・新状態・本件だけのDB排他拡張は追加しない。UIは処理中/結果未確認を失敗確定やIO終了済みと混同せず、明示やり直しを提供する。旧結果は現在epoch/actor/authVersion/固定期限で封じ、実IO枠の解放は実execution終端まで待つ。

通常Node bootはHOLLOW_GOOGLE_CONFIGで明示した専用設定ファイルだけを読み、設定値を探索しない。16KiB以下の厳格JSONにclientId/clientSecret/pkceKeyFileだけを許可し、0600・親0700・O_NOFOLLOWと別32B PKCE鍵を要求する。redirect URIはAPP_URLと固定/auth/google/callbackから算出する。未設定・不正・鍵不足ではGoogleを非提供の安全な状態として投影し、値/path/原因chainを出力せずpassword・通常メール・resetを維持する。期限pruneは鍵復号を必要としない。trusted bootのauthenticationFactory?/mailer?引数だけを契約launcherの組立口とし、通常構成は固定実adapterを選ぶ。認証runner受付停止→HTTP execution/hashの実終端待機→後段終了の順を守る。

契約UIは同bundleのtrusted server constructorへ型付きportを注入する専用launcherと、新0700領域の空DB・objects・local mail・自己専用鍵を使う。本番のenv/route/queryにfake providerや署名検証無効flagを作らない。最大6自己account・WS1・小note2を初期集合とし、fresh既存11accountの認証方法を変更しない。実Google adapterの暗号・有限HTTP契約と、Google portを代替するブラウザ契約を別根拠とする。未提供の退会経路をfixture削除のために追加せず、通常UIで回収できない自己account/専用DB/鍵は保護された証跡として保持する。回収は対象量通知・停止下保全後に既存正規経路で行い、領域全削除を既定にしない。

同bundleの遅いSetCookie対では、専用proof launcherだけで次のsession応答1件を30秒以下保留し、通常の別tab signout後にreleaseする故障注入を許容する。自己loopback制御・自動release・teardown解除を必須にし、製品handler/本文/判定/header値は変えず、cookie値を出力しない。実serverFnの確定・通常signout・遅い応答後のcurrentUser/resource拒否を観測し、fixture直呼びHTTP対や非hold UIとは別根拠にする。
