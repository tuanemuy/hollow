# 一括ZIPの接続判断

[ZIP接続準備](../phases/P4f-zip-contract.md)を以下の限定で採用する。正式実装はPDFの永続接続後とし、現HTML/MDの120秒・一回配信operationや編集権限を要求するbatch workerを、そのまま7日保持のZIPへ拡張しない。固定500以下の選択、本人accountIdの親、子attempt、専有assembler、artifact、短期delivery/holdを分ける。viewerを含む現在閲覧権限で処理し、元scopeは恒久認可や内容不変moveの拒否条件にしない。匿名ZIPは提供しない。

EX-02の1GBは1,000,000,000 bytesとし、格納する生成済みnote entryの圧縮前bytesと失敗一覧のUTF-8 bytesを合計する。等号は許可し、超過は子失敗による部分成功にすり替えず、親全体の分割案内と未公開中間物の回収にする。原本サイズや圧縮率だけで可否を決めない。未生成PDFの上限見積りだけで業務超過と断定せず、技術容量不足を別理由にする。ZIP headerと圧縮後実bytesは別の有限技術予約・検査へ含めるが、最終ZIPにも二重の1GB業務上限を追加しない。共用PDFでは当該ZIP demandだけを外し、他の正当な単件要求へこの上限を波及させない。

公開前に削除・失効・変更された子は既決Q2に従い分類し、正当な兄弟を残す。組立済みentryを外す必要がある場合は未公開ZIPを破棄し、対象集合を単調に減らして残る検証済み実体で再組立する。対象追加・新版への無言置換・除外対象の復活はしない。工程の有限期限と資源を超えれば運用上の親失敗とし、完成公開後の不一致は内部再組立で隠さず明示新要求へ案内する。配信時は全含有対象の現在認可・内容一致を確認する。

本人の取得認可後に現在read又は内容の不一致を観測した完成artifactはretire/fenceし、その後readを得ても旧artifactを復活させない。内容不変move後も現在readを維持する本人は旧ZIPを取得できる。未認証・別actorの要求や一時的なI/O失敗を失効根拠にせず、未観測の過去失権を調べるための全移動履歴は追加しない。現在本人/対象artifactの判定とretireを同UoWで確定し、非開示の取得拒否は確定後に返す。成功履歴を変更せず、物理removeは既存delivery/ownerの実close後に行う。UIは利用不可の取得結果から、現在利用可能なノートを選び直す新ZIP要求へ案内する。履歴一覧のartifact state/期限だけによる候補表示を、現在認可が保証された表示とは扱わない。

外部媒体のinspectionは、ZIPでは判定不能と確定拒否を分ける。inspectExportSourcesの明示policyを既定best-effortとZIP用require-determinateに分け、SafeReferenceFetcherのport/adapterは変えない。ZIPはallowed=falseのREFERENCE_URL/REFERENCE_PRIVATEだけを確定拒否として従来のexternal配列/hashへ投影する。DNS/TIMEOUT/CANCELLED/RESOURCE_LIMIT・未知/nullの拒否reasonは運用失敗とし、signal abortは元reasonを優先する。生成・組立・retry・取得のすべてでrequire-determinateを指定し、判定不能を内容変更・対象除外・artifact retire・retry新受理へ変換しない。組立の通常失敗では既存の正当なretry用spool参照を維持する。単件HTML/Markdown/PDFの既定呼出・確定配列/hash/digestは不変更とし、P4b-Aの影響範囲で回帰確認する。

本人の同時一括1件はaccountIdごとにscope/formatを跨ぎ、受付から生成・組立・stoppingの実closeまでを対象にする。別ZIPの待機列は作らず、同commandの照会は新件数に数えない。pure cleanup負債はdisk計上を維持するが、実処理終了後も本人枠を永久占有する理由にしない。global技術容量、子spool・組立中・7日実体・配信hold・回収負債の実容量は別管理とし、保持期限前の実体を空き確保のため削除しない。

失敗子retryは最新failedだけを現在確認し、成功子を無言で再生成しない。assembly/closing中は全件拒否する。成功子の変更・失効や実体の期限切れは新現在集合の新要求と区別する。成功spool、未完成の失敗、全件除外の表示と期限跨ぎは以下の採用方針に従う。7日を過ぎた未完成組立失敗を根拠なくretry不可にしない。元PDFの24時間期限は完成ZIPの7日保持を短縮せず、組立holdは期限切れ単件取得を復活させない。

writerはsafeなflat entry名と所有された遅延readerを受け、bytes/hash・全source/出力の実close後にだけ完了する。archiveのfinalize/abort返却だけをclose証拠にしない。ファイル名は既存の安全化と固定順の連番を使い、元からあるsuffix名・大文字小文字/Unicode正規化の衝突・予約manifest名を同じ表で検査する。失敗一覧は元ordinalと定型理由を基本とし、失効対象の現在title/URLや内部pathを新取得・記載しない。具体的Unicode比較・manifest・依存版・共有契約と配備値は以下の採用判断に従い、製品実証はP4f-1で行う。

[ZIP未決事項の具体案](../phases/P4f-zip-proposal.md)から、次の保持・再試行・表示方針を限定採用する。全子spoolを一律90日保持せず、再試行を支える検証済み成功bytesと最小参照だけを保持する。全成功ZIPは公開と実close後に子spoolを解放できる。一部失敗ZIPは現artifact期限内の失敗子再試行に必要な実体を保持し、期限内に受理した再試行は元artifact期限を跨いでも完了/失敗まで保持を継ぐ。一度もZIPが完成していない組立失敗へ7日を流用せず、有効な失敗履歴/新attemptからの再試行に必要な実体を保持する。元親の90日期限を延長せず、期限跨ぎの最小親shell・子履歴・保持参照の具体形と容量値は正式担当が提案する。容量不足を理由に約束済みの保持を早期終了しない。

PDFを再試行用に長期保持する代わりに、期限内に当該ZIP子の内部holdを取得し、bytes/hashを検証して専用child spoolへcopyする。元readerの実close後にPDF holdを解放し、単件24hの取得期限は変えない。期限切れ実体へ新holdを付ける迂回は認めない。本人/匿名の要求を偽装して子500件の単件履歴を作らず、正式段階でzip-child需要とzip-source owner/holdを既存共通契約へ提案する。

失敗子だけのretryは同親を再開し、純粋なassembly失敗の再試行は明示操作による新親/retryOfで同target/optionsと検証済み成功bytesを引き継ぐ。成功子の新内容への無言置換はしない。全件除外/全件生成失敗は空又はmanifestだけのZIPを成功公開せず、取得可能ファイルなしと内訳を表示する。実failed子があればretryを残し、明示/外部取消をfailureへ書き換えない。preview時点の全件空はjobを登録せず案内する。これらは未指定表示と記録形の可逆的な仮定である。

flat名はNFC表示、安全化・拡張子/suffix長確保・元ordinal順を基本とする。全元候補名とmanifest名を先に予約し、既存suffix名を連番で奪わない。比較は既存Unicode16の幅限定mapping→NFD→full case fold→NFDを中立adapter helperで共有し、browse/tagの結果を変えない。失敗/除外がある場合のmanifestはUTF-8 plain textの `hollow-export-report.txt`、元ordinal・定型code/理由だけを固定順に載せ、現在title/URL/内部path/秘密は含めない。実bytesを1GB合計に含める。writerは逐次owned sourceのbytes/hashと全source/sink実closeを確認する。依存採用は以下の独立probe根拠によるもので、local sourceの読取だけを動作成功にしない。

[期限跨ぎとPDF需要の最小案](../phases/P4f-retention-proposal.md)を採用する。旧親のcreatedAt+90日と旧title/詳細を延長せず、期限内に正当に受理したretry generation/new attemptの最小receiptだけで進行と結果を追跡する。新attemptの履歴はそのcreatedAt+90日とし、旧親をそのまま履歴へ復活させない。poll・同ID同digest再送・空retry・最新failedのないretryは新期限や保持根拠を作らない。完成partial ZIPのretryはartifact期限と有効失敗履歴の両方を要し、期限後の新receiptで旧artifactを復活させない。新生成物の7日取得は現在認可/内容一致を別検査し、旧親履歴期限だけで拒否しない。これは原文未指定の期限跨ぎ表示を補う採用解釈である。

成功spoolの保持はactive run/assembly、有効retry support、実reader/writerからの最小参照に限定する。retry受理とref引継ぎは同UoWでpruneと競合させない。今回generationのnever-published失敗を親の過去完成ZIPと混同せず、新親への引継ぎでは自分の固定target/options/refを所有する。retryOfは来歴IDであり祖先全履歴の永久保持条件にしない。不要ref消失と実close後にcleanupをclaimし、実remove確認後だけ容量を戻す。table配置/DDL/index/具体資源値は正式実装前の詳細確認に残す。

共用PDFにzip-childの第3需要を明示し、正本はZIP子attemptとする。本人/匿名request・履歴・配信を偽装せず、独立の需要表を複製しない。waiting-pdfからcopy-readyへの遷移と内部holdをpublish又はcache取得の同Txで確定する。PDF readyをZIP子成功とは数えず、検証copy・全reader/writer実close・現在認可/内容/世代再確認後にspoolを確定する。holdは期限内だけ取得し、既存holdによる有限copy中の期限跨ぎと、新用途への取得を分ける。

ZIP内部copyはZIP工程ownerで監督し、本人/匿名の実配信2枠へ混ぜない。需要claim/renew/publish/recover、artifact cleanup/physical delete、request/compute pruneとstorage ownerの全境界へZIP参照を接続する。取消は当該需要だけを外し、正当な兄弟を止めない。実close/withOwner終了とruntime所有解放の後にDB holdをreleasedとし、解放失敗/所有不明は容量と負債を保持する。具体型名・port signature・配備値は正式担当が提案し、今回の準備で製品の成立や既受入への影響を先行確定しない。

[保存構造と内部holdの案](../phases/P4f-storage-contract-proposal.md)から責務の分離を採用する。明示受理のrunと内部再組立世代を分け、artifact参照を回収した後も必要なrunにpublished済みの事実を保持する。期限切れpartialをnever-published失敗へ読み替えない。成功結果の履歴とrun/ordinalの生存spool参照を分け、正当な実体解放で成功履歴を失敗へ変えない。attempt単位のPDF holdは内部所有であって第三の需要正本ではなく、共通需要portは中立なapplication位置へ置く。

未openのholdも物理削除を止めるため、active reader/writerの確認だけに依存せず、artifact cleanupとkey単位claimDelete・purge・recover・metadata pruneへ同じ参照条件を接続する。retireによる新取得停止と既存holdのclose/回収を分離し、実deleteの完了確認より前にkey/bytesを解放しない。提案の表名・列・CHECK・索引・signatureは正式実装前の詳細候補であり、migration・競合・実close・query planの成立は未検証。新しい資源値や受入条件は追加しない。

[writer候補と成立確認案](../phases/P4f-writer-proposal.md)の初期STORE方式を採用する。ZIP形式による一括取得は提供するが圧縮率は保証せず、生成entryの合計と固定版のheader/extraから出力予約を導く。最終ZIPへ別の1GB業務上限を加えず、既存PDF/HTMLMDのslot・容量は流用しない。圧縮CPU・平均圧縮率に頼らない初期方式とし、圧縮可能なHTML/MDの転送量が減らない制約を明記する。

正式成立確認の依存候補はcore Node adapterの直接固定`archiver@8.0.0`と型`@types/archiver@8.0.0`とする。対応型の公開とnamed入口はregistry/配布物の読取で確認済み。実採用は推移lock/notice、Node22/strict型、owned source/sinkの実closeと小合成ZIPの読取一致を確認してから行う。旧5.3.2の推移依存を暗黙利用せず、型不明をanyやcastで隠さない。finalize/abortをclose証拠にせず、取消・短読/過読・hash不一致・出力失敗は未公開と所有保持で収束させる。1GB±算術と小stream境界、逐次source/遅いsink、固定版STORE上界を限定probeとし、小fixtureから全1GB資源や全OSの成立を外挿しない。具体配備値・Unicode比較helper抽出は未採用のまま正式担当へ残す。

[製品接続の縦スライス案](../phases/P4f-slicing-proposal.md)を採用し、HTML/Markdownの受付から生成・7日取得・本人履歴/通知・取消/retry/回収までを先行し、PDF第三需要/内部holdを後続にする。先行でも500/1GB/本人1active、親90日非延長と新attempt記録、current-read/内容確認、実close/負債の条件を省略しない。PDF一括はUIとPOSTで未提供を明示し、全形式ZIPの完成とはしない。ZIP専用保存formatは三形式を表せる形、先行受付型は実装済みHTML/Markdownだけとし、既存単件ExportFormatやdigestを変更しない。PDF専用state/holdは後続の型/移行で追加し、偽compute値や無言fallbackを保存しない。

[P4f-0独立結果](../reviews/P4f-0.md)に基づき、固定archiver8.0.0/@types8.0.0のSTORE Node adapterを製品接続に採用する。Node22.22.3でのstrict型と19項目、固定zip-stream7.0.5/compress-commons7.0.1の出力式とnoticeを限定実証済み。製品lockでの解決版と実adapterの差は接続時に確認する。通常file・empty extra/comment・501entry以下・UTF-8名65535B以下・payload1GB以下での出力予約はpayload＋各entryの92＋UTF-8名bytes×2＋末尾22、小forceZip64は末尾76B追加とする。新しいnote上限ではなく形式/依存の技術前提であり、製品の安全名上限は別に定める。中断可能なowned close契約を製品ObjectStorageへ接続し、prototypeの同期renameを製品publish Txの代用にしない。全Unicode/全1GB資源/製品回復は未実証のまま扱う。

ZIP workerはsessionを持たず、本人accountと現在のノート閲覧権限を確認する専用snapshot入口を使う。単件prepareExportを500回呼ばず、PDF構成必須のsnapshotをHTML/MDの前提にしない。公開/匿名の別authorityへ失権後に切り替える根拠として今回の分割案を使わない。選択UIだけを再利用し、edit/source固定のbatch mutation workerへZIPを追加しない。共有storage/purgeに必要なZIP owner追加は先行から扱い、PDF compute需要への変更は後続へ限定する。

JB-03の外部取消はZIPにも適用し、owner→editor/viewer・editor→viewer等の降格でも当該actorの現在関連noteの未終端需要を同Txで取消/fenceする。viewerが新規ZIPを実行できることを旧job継続の根拠にしない。先移出note・無関係scope・別actor・正当兄弟を保ち、取消をfailure/retryへ変換しない。既完了jobを遡って取消せず、readを維持する降格だけで完成artifactを一律失効させない。完成後は現在read/内容と既採用の失効契約を適用する。

外部取消は現在run.exclusionsにZIP_CANCELLEDを固定し、queued子はcancelled、実行中は実close後にcancelledへ収束する。元成功attemptを書換えず、run最小結果でもfailure/retryへ変換しない。trash/purgeは対象noteの未終端需要を同様に取消し、完成artifactも失効させる。保存済title/html/styleの実変更だけはZIP_CONTENT_CHANGEDで現在runから除外し、完成artifactを失効させる。タグ/内容不変moveではこの内容変更hookを呼ばず、単なる現在read不可の観測はNOTE_UNAVAILABLEとする。

readを失う離脱/除名は、当該actorの現在WS noteを含む完成artifactもretire/fenceする。read維持の降格と区別し、再参加だけで失効した旧ZIPを復活させない。成功履歴をcancelledへ書換えず、別actor/先移出noteは保ち、物理removeは全delivery/ownerの実close後に行う。

cancelWorkspaceMember(workspaceId, accountId, cause, now)のcauseはrole-downgrade/membership-endedとし、membershipのrank低下/next=nullから同Txで渡す。invalidateNote(noteId, now, reason)はZIP_CANCELLEDを既定、実内容変更時だけZIP_CONTENT_CHANGEDを渡す。commitNoteではpreviousがある場合のsameNoteContent実差分に限定する。

trashのhasProcessingにactive ZIPを含め、一括trashのprocessingFingerprintにも対象noteの現在active ZIPのkind/requestId/generation/ordinalを加える。lease/run versionの更新は含めず、確認後の後発/入替/新generationをpreview/accept/workerの同関数で検出する。既保存operation/digestの形式を変えず、新処理を確認なく取り消さない。既存PDFの集合未包含は今回ZIP差分と別の追加観察として扱う。

[P4f-1詳細案](../phases/P4f-1-proposal.md)の10表と5repositoryを採用する。requests/runs/targets/attempts/spools/spool_refs/assemblies/artifacts/artifact_entries/deliveriesを0030で追加し、固定対象・受理世代・内部組立世代・成功履歴・生存参照を分離する。UoWで受理/再試行のref引継ぎ、spoolと子結果、artifactと公開結果をそれぞれ原子的に確定する。FK/状態guard/一意索引・旧全列の移行保全は実装検証で確認する。PDF hold/compute列と第三需要はP4f-2へ残す。具体列名の局所調整は担当に任せるが、共有責務/portの変更は再提案する。

durable snapshotは本人account/current-readを入口にし、単件の認可から独立した共通content構築部分を抽出する。既存identityの値/順序・単件ExportFormat・digestは変えない。source identityに加え現在の安全inspectionで得るexternalIdentityもspool/entryへ保持し、生成・公開・取得で照合する。URL本文・session・cookieは履歴へ保存しない。共有ObjectStorageにはowned-read能力を追加でき、configured ZIPはbody/closed/cancelを持つ実装を必須にする。既存stream契約は維持する。FileExportSourceReaderのclosePromise共有とzip-spool/zip-assembly/zip-delivery所有を採用し、全native close/withOwner終了前にDB所有や予約を解放しない。close不明は失敗fenceと所有保持に分ける。

ZIP平坦名は既存安全化/180byte stemを再利用し、suffixと拡張子を含む200UTF-8byte以内の出力名とする。利用者のtitle上限は変更しない。原候補とmanifestの全keyを先に予約し、固定ordinal順で衝突を解消する。full fold helperの中立化は既存正規化結果の同値性を確認する。

ZIPの保存options.styleは各ノートの保存styleを使う固定policy `saved` とし、EX-02の形式選択へ追加style選択を増やさない。初回確認から生成まで対象style/内容identityを照合する。最新failedの明示再確認だけは現在内容/styleを採用できるが、成功spoolの変更は無言再生成せず新要求へ案内する。単件style/digestは変更しない。

公開前の現在runの単調除外はrun.exclusionsに固定ordinalと定型reasonだけを最大500件保持し、再利用元の成功attempt結果を書き換えない。元固定target集合内・重複なしとし、同run世代で除外を復活させない。manifestと再組立はこの現在除外を参照し、過去の成功履歴と現在取得可否を混同しない。

新runの最小結果は終端Txでimmutableなrun.resultsへ最大500件固定できる。ordinal/元attempt参照/今回試行か成功再利用か・定型結果と必要な最小format/profile/identity/bytes/hashに限定し、成功attemptを偽造しない。旧成功titleや詳細を複製して新run90日へ延命しない。旧parent期限内は旧保存情報を表示でき、期限後はordinalと最小receipt/結果で追跡する。新しい明示再確認で作るattempt自身の表示情報はその新期限で扱えるが、現在noteや最新attemptから過去結果を補完しない。成果物のentry名と7日取得は履歴期限と別に扱う。

履歴projectionはZipRequestRepository.attemptsByIdsで、認可済run.resultsが指す元attemptだけを最大500件読む。結果正本はrun.resultsのままとし、title表示は各元attempt自身のhistoryExpiresAt内に限る。UIの任意ID入力や兄弟runの最新結果をこの取得元にしない。

JB-01の各処理の所要時間はrun固有のacceptedAt/finishedAtから示す。ZipRun.finishedAtは終端Txの注入nowで固定し、terminalでは必須、nonterminalではnullとする。stopping/所有未証明を終端として記録しない。終端時刻は不変とし、retryは新runだけを作る。親updatedAtや後続retryで過去の所要時間を変えず、publishedAt起点7日と各90日期限も変更しない。ZipJobViewはISO日時又はnullで投影する。保存先は本体未適用の0030 zip_runs.finished_atとし、終端制約/不変guardと最新cloneで確認する。

ZipWriterはname/bytes/sha256と遅延open(signal)を持つentry、AsyncIterable chunks＋close()のsource、write/finish/closeのsinkを受ける。close()は共有された冪等Promiseでpending I/Oの中断と実closeまで待ち、前sourceのclose後だけ次sourceを開く。全close完了後のbytes/hashだけを成功とする。close未証明は他の失敗より優先するZIP_CLOSE_UNPROVENに区分し、外側のwithOwnerはこれを所有終了としてfinally解放しない。STORE上界の不正/技術予約超過と、実payload1GB超過を別理由にする。

実close未証明を永続所有へ接続するため、applicationの共有契約ObjectOwnershipUnprovenErrorをZIP外側が明示生成する。CoordinatedObjectStorage.withOwnerはZIP ownerに対応するこの契約だけendWriteを省略して再throwし、通常例外/既存ownerの終了意味は変えない。単なるcode文字列で所有判断せず、open済resourceのclose結果を集約して変換する。実行側はruntime unknownと永続active owner/予約を保持し、UI failure表示とrequest terminal/枠解放を分離する。人工的な未解決Promiseを保存手段にせず、stop失敗を正常全停止としない。次bootのrecoverWritesは旧processと関連実行の終了証明後だけ許可し、lease満了や監督precheck単独を証明にしない。

ZipExecutionはworkからの型付き未証明Errorを保持し、work Promiseを持たない配信側はZipTransfers.retain(id, ObjectOwnershipUnprovenError)で同じ現在ownerのunknownを記録する。releaseや期限でunknownを消さず、MapとDB非closedの保持をstop失敗へ反映する。これは実所有の通知契約であり、新しい利用者向け期限ではない。

ZipExecution.within(deadlineAt, parentSignal, work)は工程期限を実装する。Node adapterだけが注入Clockとtimerを持ち、工程専用signalを中止してもwork/実close結果まで待つ。子期限は正当兄弟を無条件取消せず、親取消/総期限は伝播する。新しい枠や待機列は作らず、期限後の遅い成功を採用せず、所有未証明を通常timeoutへ置換しない。publish/finishでも現在時刻・signal・世代を確認する。

ZipWorkRepository.active()はglobal非terminalの現在1件だけをworker用に取得する。現在runの世代/state/runtime/lease/deadlineを扱う最小projectionを基本とし、履歴90日filterやtitle表示に依存させない。親履歴期限を跨いだactive runも追跡する。2秒tickで期限・自runtime更新・stopping/実closeを処理し、claimはqueued→running取得だけ、未知runtimeはleaseだけで回復しない。

ZIP用media sourcesはExportSourceReaderにopenOwned(source, signal):Promise<OwnedObjectRead>を加え、bodyのread失敗とnative close結果を分離する。FileExportSourceReaderの内部構築を共有し、既存openはbodyだけを返す署名/認可/bytes/hash/逐次base64を維持する。errored Web streamのcancel拒否だけをFD未closeの証拠にせず、ZIP外側は実closed結果から所有未証明を分類する。

ZIPのobject媒体は専用Node sources adapterからCoordinatedObjectStorage.openOwnedReadを通し、object_write_keys登録後に開く。直接FileExportSourceReaderから物理objectを開いて登録を迂回しない。読んだbytesのhash/base64は逐次変換し、実close証拠を同じZipSourceReader契約へ返す。inlineだけ既存readerへ委譲し、新しい外部fetchや単件署名の変更は行わない。

ZIP出力はoptional ObjectStorage.putOwnedBoundedをconfigured ZIPの必須能力とする。署名はputBoundedと同じだが、NodeはFileHandleの逐次writeと共有closePromiseを明示し、実write FDのclose後だけrename/成功に進む。通常body/write失敗とclose未証明を分け、後者は内向きObjectWriteCloseUnprovenErrorをZIP外側で同ownerのObjectOwnershipUnprovenErrorへ変換する。既put/putBounded・他ownerは変更しない。未証明のstaging.part/key/予約/ownerを保持し、終了証明後に既存removeClaimedの正確なkey-prefix回収へ接続する。sink.finishや汎用put Promise終了だけを実close証拠にしない。

参照配備はZIP専用4GiB、既存HTML/Markdown2GiB＋PDF4GiBと設定合計10GiB、global run1・ZIP delivery2を採用する。run枠は受付からactive/assembling/stoppingの実closeまでDBの定数partial UNIQUEで保持し、assembly guardだけに依存しない。run総30分、子120秒（既存plan30秒を含む）、assembly120秒、delivery600秒、cleanup試行30秒、lease60秒/renew2秒、tick20遷移・prune100候補、source同時1/64KiB bufferを調整可能な初期技術値とする。500/1GB/7日/90日の業務条件を置換せず、最大合法入力での十分性やOS hardquotaを保証しない。

共有diskの保護はZIP容量受付を直列化し、新物理予約前のstatfs.availableから既存2poolの設定区画全量（参照6GiB）とZIP未実体化予約を差し引く保守的方式とする。同UoWでZIP4GiB上限・現在予約を再確認して取得し、sample→予約→write開始を重複させない。既存実体分にもheadroomを残すため、10GiBちょうどのvolumeで全枠を使えるとは説明しない。このheadroomは物理keyの二重課算ではなく、既存予約/未使用区画を保護する受付条件である。外部process・note等の増加、native超過は別の限界として扱う。

ZipDiskAdmission.reserveはnewBytesと未実体化予約を読む非同期callback、予約を確定するcommit callbackを受ける。Node mutex取得後に現在予約→statfsを読み、同mutex内のcommitで現在世代と4GiB上限を再照合する。mutex待機前の古い予約値を入力しない。I/OはTx外、確定はUoW内とし、失敗時に新物理writeを開始しない。

spoolはplanの有限上界、assemblyは実entry/manifestと固定STORE式で予約し、同じkeyのassembly→artifact移管は一回課算、配信はpinだけとする。実close/remove確認後だけ余剰/負債を返す。推定上界や技術予約不足を業務1GB超過とせず、実生成entry＋manifest UTF-8が1,000,000,001Bに達した場合だけ全体業務超過とする。短読/hash不一致/容量不足/期限/close不明は別理由にする。新HOLLOW_ZIP_CONFIG未設定はZIP未構成とし、残存所有不明の回復を飛ばして起動しない。後続PDF生成自体は既存compute枠へ合流し、ZIP組立/copy/配信は既存PDF/HTMLMD枠へ偽装しない。

HOLLOW_ZIP_CONFIGは非秘密のstrict version:1 JSONとし、capacityのdiskBytes/protectedDiskBytes/totalMs/childMs/assemblyMs/deliveryMs/leaseMs/cleanupMsを明示する。安全整数/timer範囲を検査し、protectedDiskBytesはmax(6GiB,既存HTMLMDとPDFの設定区画合計)以上とする。初期値は上記採用値、設定合計は必要volume容量の保証ではない。HTMLMD ZIPのためにPDF/Python/Chrome構成を要求せず、既存PDF所有/構成に必要な監督checkだけを行う。

ZIP未構成でも、非terminal run/非closed delivery/active owner・未回収spool/artifact・非closed assembly又はそのkey/予約・生存spool refがあれば回復前の読取検査でbootを拒否する。資源0の履歴shellやclosed assembly履歴だけは拒否理由にしない。configured bootは必要な既存PDF監督checkとexclusive runtimeの旧Node終了証明、common recoverOwners完了の後でだけZIP work/deliveryを回復する。残存検査だけで枠/予約を変更しない。

Node ZIP runnerは2秒の単一pumpと有限sweepを持ち、stopは新claim停止→進行tick回収→execution/transfers実stopを既存DB/lock終了より先にawaitする。unknownを成功へ変換せず、stop失敗後に正常終了のDB/lock解放へ進まない。別途OS終了が証明された次bootの回復と区別する。

ZIP document planには専用Node adapterを使い、既存worker path/plan検証を共有して単件adapterは変更しない。object spool予約前のworker実exit未証明はZipExecutionUnprovenErrorとし、object ownerを偽造しない。terminate APIの返却だけでなく実exitを確認し、NodeZipExecution/withinは未証明を保持、run stopping/global枠を残してstop失敗を伝える。遅いworker結果は採用しない。実exitが確認できた通常失敗は未知所有と区別する。
