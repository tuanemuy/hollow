# S2の実取得・入力終了契約

[S2独立静的レビュー](../reviews/P5c-3-s2-plan.md)のM1/M2と[S2補正版](../phases/P5c-3-s2-plan.md)138行24,177Bを採用する。既binding/attempt/consumerの保存から実取得・text準備・active consumerの入力解放までを隔離integrationで接続する。通常runner/DI/UI/本文採用は後続。0043は3consumerのnullable source_input_receipt各1列、既9source triggerの限定更新、source claim/backup相互の2guardだけ。旧0042/0037/旧全列/ledgerは変更せず、資源・完了条件はplanのS2を正本とする。

source providerの各wire前に必須checkCurrentを呼び、applicationがexact input lease/binding、記録資格ownerのsub/epoch/connection版、attempt active/cancel、実行者の現在編集権限をread-only UoWで確認する。metadata取得後に失権した場合もdownloadを送らない。確認callbackにbytesや可変所有権を渡さず、HTTPはTx外で実行する。拒否後も取得済み資源の実終了とACK証拠保持を省略しない。記録者のWS所属・current folder/headを追加条件にせず、追加HTTP/refreshなしで同じ要求上限を維持する。

sourceのheld集合はactive/unknown又はclosedかつcaller未終了/未ACKとし、DB claim・backup相互data guard・control集計・scan/reconcile・predecessor empty判定で一致させる。bounded scanのoverflowはemptyにしない。source専用のACK証拠はDB acknowledged CAS確定まで保持し、DB失敗/応答不明ではbufferを返さず同じproofを再照合する。DBが既にexact acknowledgedの場合だけ同値確定する。再起動の証拠欠測は保守保持し、正式前任終了証明なしにclaimを開けない。

source ACK保存の応答不明は、既adapter共有保存エラーの境界で一度だけread-only再照合できる。保留中の同readが保持するbytesと未消費proofを使い、exact target/attempt/owner/proof/callerEnded/acknowledged・terminal結果全値の一致後だけconfirmして返す。domainやプログラミング例外を成功へ変換しない。CAS false・未保存・不一致・再照合失敗は保持して失敗を返し、追加wireや放棄済みbufferの復活をしない。通常backup/controlのACK契約は変えない。

input receiptはconsumer runtime/token/generationを持つactive/unknown/closedのstrict union。旧receipt NULL/memory50だけはS1のconsumer closed AND attemptsafe経路を残し、新stageを後付けしない。新receipt有りの50→0はexact adapter終了proofとattemptsafeによるclosed+memory0の同Tx/CASを必須とし、consumer.closedだけでactive/unknownを迂回しない。proofはCAS確定前に消費せず、失敗時は新readを開けない。JSON proofIdだけで実終了を推定しない。input終了と業務consumer終了は独立であり、redactionのterminal/ownerclosed/attemptsafeとDrive限定・consumed raw結果保持を維持する。

同consumerの未消費proof又は開いたlocal leaseがある間は、新beginがDB世代・予約量を進める前に拒否する。[S2-F1修正案](../phases/P5c-3-s2-fix-plan.md)97行12,499B SHA02d95d6b6ecace77b72a73163c76dc308e12db6581421745957279c01445da59を採用する。既input境界のreserveBeginでconsumerと50MiB枠を同期排他予約し、同UoW内のwrite前bindBeginでexact receiptを固定、確定成功後commitBeginだけがleaseを返す。holdBeginは実registry stateで失敗を区分し、一度もboundでないreservedだけwrite未到達の証拠として枠を返す。一度でもboundならexact intentをunknown-beginとして保持し、CAS false/例外/応答不明をrollbackと推定しない。偽handle・二重settle・commit後settleは別枠/leaseを解放しない。全intentとleaseを合算100MiB/最大2に抑え、未回復beginの自動再開は提供しない。既finishのexact再照合→proof消費を維持し、旧proof消費や次世代作成への迂回を許さない。単なるopenの順序反転や非排他的な事前照会ではこの契約を満たさない。

同consumerの逐次readは一つのgeneration/50MiB予約内で行い、前readのadapter終端・親参照解除後だけ次へ進む。text workerは結果message・実exit/terminate完了・両pipe end・参照解除を区別する。GCやRSS即時減少の保証は追加しない。source attempt runtime/tokenとinput consumer runtime/tokenのproofは相互流用しない。consumed previewの入力終了保存は、S1 source-redactionとは排他的に、同source/binding・他typed全値/raw結果を保ち、同owner/generationのactive又はunknown50→closed0とversion/updatedAtだけをCASする限定枝とする。実proof確認を省略せず、将来PDF readyの待機前入力解放契約を変えない。通常PDF/機械再生成/全取消・purge・UIの成立へ拡張しない。
