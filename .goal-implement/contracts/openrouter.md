# OpenRouterの連携境界

[OpenRouter読取案](../phases/P5-openrouter-contract.md)から秘密・試行・世代の分離を採用する。報告の使用量参照はAC-09ではなく原文AC-10と読み替える。現在の具体化は[P5b提案](../phases/P5b-proposal.md)と下記契約に従う。P5aの独立受入・環境返却までは製品実装を開始しない。現在のHollow本人sessionを前提にし、OpenRouter認可でHollowへログインさせない。専用purpose/keyring/AADでkeyとverifierを保護し、note共有鍵・Google/Drive資格情報を流用しない。

認可attemptは元account/session/browser世代・expected connection epoch・固定continuationに束縛し、S256と一回限りCASを使う。初期ローカル期限は開始から10分固定とし、providerコードの期限と起点を混同しない。state echoやcallback相関値の往復を資料だけで成立済みとせず、条件付き実接続で確認する。相関不明を最新attemptへ割り当てず、別browser/actor/ABAは拒否する。code交換中にDB Txを保持せず、交換応答不明を自動再交換で回復しない。暗号化candidateが永続化済みの場合だけ同一metadata GETの再確認を可能にし、鍵受領不明なら明示新認可へ戻す。provider側の孤立鍵がないとは保証しない。

生成を伴わないmetadata確認後、現在本人/attempt/epochを再照合して昇格する。再連携が成功する前に既存の有効な鍵を破棄せず、古い鍵の遅い401で新接続を失効させない。2026-09-28の利用者決定に従い、再連携では取消確認を表示し、新接続の採用成功時に本人旧世代LLM jobを取消し、遅い結果の反映を拒否する。新鍵へ無言で付け替えない。解除は旧attempt/candidateを封じ、credential破棄と本人旧世代LLM jobの取消・late result拒否を永続化する。機械変換・他人の連携・完成ノートは保ち、provider側の権限撤回や既発生課金の取消とは表示しない。

モデル能力とendpoint種別を型で区分し、音声chatと専用STTをモデルIDだけで混同しない。一覧障害時は採用済み既定集合と再試行案内を示すが、保存済み設定を無断変更せず、実行時の提供終了を別モデルへの無言fallbackで隠さない。モデル候補の価格・能力は実装時に再確認し、今回の候補を既定採用や品質保証としない。初回のneeds_ai案内は現在閲覧可能な対象がある場合だけで、連携後の自動生成・upload再送は行わない。

2026-09-28の利用者回答に従い、月間枠の初期上限はaccountあたり30回、1fileの論理変換/再生成を1回とし、内部ページ分割では加算しない。上限値は運用設定で変更できるようにする。月境界・失敗/応答不明の計数は、下記の固定UTC暦月・durable intent・未送信証明の採用契約に従う。枠はHollow accountに属し、鍵交換や解除でリセットしない。外部API呼出回数/費用と利用者向けの変換回数を混同しない。API資料の認証要否の差、callback往復、metadata疎通とモデル実行は別々に検証し、利用者認可と費用承認を得るまで実接続しない。
