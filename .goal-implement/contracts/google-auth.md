# Google認証の接続契約

[P5認証の読取案](../phases/P5-auth-contract.md)と[P5a詳細案](../phases/P5a-proposal.md)を本節の限定で採用し、P5aでAC-01〜06/08の残認証を接続する。Googleとメールは先にローカル契約検証を行い、実接続は設定と明示同意を待つ。Identityは検証済みissuer/subを主キーとし、emailは初回の既存候補照合にだけ使う。linked subを先に解決し、email変更から別accountへ付け替えない。email_verifiedはtrueを必須とし、Gmailの正確なdomainか署名検証済みhdをGoogleの管理根拠とする。既存unverifiedには自動linkせず、通常メール確認を先に案内する。第三者メールの新規accountまで追加challengeを拡大しない。外部交換後・proof後の現在account/sub競合を同Txで再照合し、新規登録競合を無条件signInへ変換しない。

既存passwordHashを保持したnullable credentialとauthVersion、accountあたり一つのGoogle Identityを採用する。認証方法はpassword-only/Google-only/bothの型にし、古いAccount全体upsertでcredentialを復活させない。専用CASで同時解除を直列化し、最後の方法を消さない。password変更は現在sessionの固定期限を維持して他sessionを失効、resetは旧session全失効。Google Identity解除はDriveや既存Hollow sessionの一括失効を兼ねない。authVersionは未完了の認証・proof・resetを失効させる版であり、方法変更のたびに全sessionを失効させる値にはしない。

OAuthはlogin/link/reauthを型で分け、state/nonce/S256・browser・現在認証context・許可戻り先・期限・一回性を固定する。署名/issuer/audience/azp/nonce/期限を検証し、raw tokenやPKCE verifierをDTO/logに出さない。原文の基本プロフィールにはopenid/email/profileだけを要求し、Drive/offline scopeを混ぜず、既存公開profileをGoogle値で上書きしない。linkは現在sessionを維持、reauthは限定proofだけを発行し、loginだけが新sessionを確立する。匿名→別actor→匿名のABAや遅いSet-Cookieでも認証が復活しないserver側のbrowser世代/発行session fenceを必須にする。具体保存形は正式実装案で固定し、client epochだけで代替しない。

google-linkのメールchallengeは通常AC-02/resetと別purposeにする。元attempt/sub/target account/現在email/authVersion/browserに束縛し、元browserでメールリンクを開いた明示POSTだけが消費・link・sessionを同Tx確定する。GETは消費しない。別browserではlink/session/proof-readyを成立させず、開始したbrowserで同リンクを開くよう案内する。別browserで立てた確認flagをpollして元試行を完成させない。通常AC-02の別browser確認成立・非ログインは変更しない。既存passwordによるproofもsignInを直接呼ばず、現在hash/versionと同じ対象を再確認する。

Google-onlyへのpassword追加は、新しいnonce付きGoogle code flowで現在linked subを確認した一回限りproofを使う。Googleで毎回passwordを再入力したという保証は加えない。原文未指定の初期値としてOAuth attemptは開始から10分固定、link mailは親期限以下で最大10分・再送60秒、reauth proofはcallbackから5分かつ親期限以下とする。元ID token期限が先なら採用を拒否し、poll/再送で親期限を延ばさない。code交換の応答喪失では未検証claimsを採用せず、新しいGoogle試行への明示導線を出す。完了receiptをbearer login credentialにせず、cookie喪失は現在cookieでの完了確認か明示再ログインとする。

招待からの認証は元continuation/selector/世代とbrowserを保持し、callback時の別招待へ付け替えない。membership作成は既存の明示参加だけとし、招待tokenで既存accountのGoogle link proofを省略しない。契約検証と条件付き実Google/実メールの確認は区分し、実接続待ちを成功扱いしない。
