# P4a の限定共有と表示名

[限定共有契約案](../phases/P4a-contract.md)を以下の補足とともに採用する。着手はP3f独立受入後とする。対象はprivateと限定公開、リンク取得・再発行、password、匿名の現在本文とcurrent媒体、著者表示と本人表示名設定。public、公開ページ・検索、handle、EX、プロフィールの他項目は後続に残す。SH-07とAC-03にはbriefの利用者決定を適用し、P4aの範囲へは追加しない。

noteと1対1のsharing rowを共有設定の唯一の正本にする。既存noteはprivateで移行し、新noteと初期rowは同UoWで作る。初期private rowはnote INSERT triggerで生成し、全writerの一意性・rollbackを同じDB契約で守る。通常保存・変換・復元・移動は共有設定を書き戻さない。共有変更は本文版・更新日時を進めない。row欠落をprivateとして隠さず整合性エラーにする。public identityとURL世代はこの段階で発行しない。

限定入口は `/s/{token}`、同配下のunlockとasset取得とする。32ランダムbytesのtokenはindexed hashと再表示用の専用AEAD envelopeで保持する。秘密値は現在編集者への共有panelだけに返し、通常DTO・ログ・jobに含めない。専用key ringを使い、招待keyは変更しない。rotationはURL・token・grantを変えず、明示した有限保守処理でenvelopeだけを再保護する。GETによる暗黙の再暗号化は行わない。旧keyの廃棄は現参照と保全世代の復元要件を確認して行う。本作業で既存keyは廃棄しない。key欠損時は明示した運用エラーとし、private化と既存hashによる認可を妨げない。

passwordは8 Unicode code points以上、UTF-8で1024B以下、trim・正規化なし。既存scrypt primitiveを使い、accountの強度規則は流用しない。匿名browserとnote・token世代・password epochに束縛したgrantを、認証成功から固定24時間とする。readや媒体取得で延長しない。private化はgrantを失効させ、再限定では同tokenとpasswordを使うが再入力を求める。明示再発行はpasswordを保持する。発行済みならprivate中も再発行でき、privateのまま旧リンクの復活を止める。trashは現在lifecycleで停止し、復元時は同tokenと期限内grantを使える。

password試行の初期運用値は契約案のbrowser別失敗制限・link全体60検証/15分・計算同時2/待機8/3秒とする。link全体の15分は最初の予約からの固定windowで、攻撃の継続で期限を延ばさない。browserの8回目失敗による15分blockも固定し、block中の要求では延長しない。成功は当該browserの失敗状態だけをresetし、全体予約数を戻さない。予約と失敗反映の並行性、再起動、満杯時の回復を検証する。上限が正当な新規閲覧も一時停止させ得る限界を明記し、既存の有効grantはpassword試行制限で停止しない。

表示名だけをAC-07から先行接続する。本人設定はtrim後0〜50 Unicode code points、制御文字・改行を拒否し、空は未設定とする。著者DTOはnamed/unset/deleted/unknownを区別する。既知の存続creatorに表示名がなければ「表示名未設定」と表示し、emailや現在ownerで補わない。未設定を限定公開の禁止条件にはしない。設定後は検証済みnote IDと固定共有再開指定で戻り、古い共有操作を自動再実行しない。

外部readはserverが保存済み正本から作る。現在token・grant・lifecycle・現在ownerの存続を同snapshotで確認し、Tx外描画後の応答採用前にも認可とsourceを照合する。媒体は当該noteのcurrent refかつreadyに限定し、GET/HEAD/Rangeの応答前に再確認する。原本・履歴・draftへの昇格は認めない。応答済みbytesの回収は保証しない。限定応答はnoindex/no-store/no-referrer、gateと404はtitle・著者・本文断片を含めない。

共有変更と解除・再発行の確認は現在の編集権限、共有版、noteと所有の確認版へ束縛する。移動確認にも共有状態を含め、membership由来の閲覧喪失と有効リンクの独立した閲覧根拠を分けて説明する。ACK不明は現在設定の再取得へ戻し、tokenやpassword操作を自動再送しない。UIはactor・note・画面の操作世代で旧success/catch/finallyを拒否する。P3f削除後の匿名入口も同じ現在owner判定で直ちに拒否し、先に移出したnoteを巻き込まない。

移動の確認値に共有版・visibility・password有無を追加する。新transportと新previewでは必須とし、tokenやpassword hashは含めない。P4a以前の保存済みattempt JSONでsharing field自体がない場合だけ、adapterでprivate/version0/passwordなしへ読み替える。旧実装がprivate固定で、新移行もprivate0へ初期化することを根拠とする。不完全な新fieldを旧形式として補わない。旧DB行・request同内容識別の正本/hashは書き換えず、正規化前後の重複受理とretryを検証する。共有を一度変更したnoteでは旧確認を版不一致で拒否する。

旧一括移動のACK再照会では、本人の同requestに既存priorがある場合だけlegacy digest比較を許す。通常digestが不一致でも、全move確認のsharingが厳密private/version0/passwordなしなら、そのfieldだけ除いた旧正規形digestを照合して同じ既存receiptを返せる。新親受理・新mutation・retryの実行には使わない。元digest/旧行を変更せず、新transportでsharing欠落を受け付けない。現在共有状態が変わっていても過去の受理結果の照会は再実行ではない。異actor・設定・対象順・新共有版の差を正規化で隠さない。

初回privateでpasswordを設定するときは、専用tokenの初回発行・保護とpassword保存を同Txで確定する。visibilityはprivate、URLは非表示のままとし、限定化すると同token/passwordを使う。保護の準備に無保護の限定公開を経由させない。鍵・hash・確認版の失敗で部分発行や限定化をせず、ACK不明は現在設定の明示照会へ戻す。通常の初期rowは未発行を維持する。

限定gateのnative unlock POSTはno-referrerを維持する。[FetchのOrigin規則](https://fetch.spec.whatwg.org/#append-a-request-origin-header)では非cors/no-referrerのPOSTが文字列nullになるため、通常のOrigin一致に加え、Originが文字列nullかつ `Sec-Fetch-Site=same-origin`・`Sec-Fetch-Mode=navigate`・`Sec-Fetch-Dest=document` の全一致だけを許す。[Fetch Metadata](https://www.w3.org/TR/fetch-metadata/)のbrowser管理とredirect chain判定に基づく限定例外である。Origin欠落・非null不一致、metadata不足/不正/same-site/cross-site/noneは拒否する。他の共有・profile mutationには広げない。実browser送信のmetadataはserver側の安全なbooleanで確認し、手製header試験と分ける。対応情報を送らないbrowserへ無条件fallbackしない。
