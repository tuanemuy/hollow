# 単件PDFの製品接続

[製品接続案](../phases/P4d-product-contract.md)の責務分離を以下の限定で採用する。P4d-0は実rendererの成立根拠であり、製品PDFや完全なOS隔離の完成ではない。次にbinary packと専用local channelを隔離資料で実証し、その後に本人単件、匿名限定/publicを順に接続する。未成立のchannelをfakeで代替して製品機能を受け入れない。

PDF素材は現在snapshotの検証済みbinaryを逐次packへ保存し、全bytes/hash確認とseal後にregistered slotだけを供給する。既存HTML/MDのdata URI readerは変更せず、別のbinary portを使う。本文800KiB由来のHTML/manifestだけをmaterializeし、全媒体/fontのbase64文字列を作らない。固定fontとcodeのfallbackを配備物に含め、digest/licenseをprofileへ束縛する。専用loopback channelは厳密Host/method/path/世代とcompute内header、CSP/JS無効/許可requestだけの制御を持ち、app cookie・原URL・任意hostfileを使わない。stream/再取得/同時readの有限値は小実験結果から決める。

PDFは静的形式として動画を再生しない。現在取得可能なposterがあれば表示し、なければ動画を含むこととPDFに映像を含まない旨を示す。未取得外部素材を再fetchしたり、原本/draft/historyへfallbackしたりしない。PDF生成失敗やサービス資源不足は理由と再操作を案内する運用上の失敗であり、閲覧のみ許す新権限やノート受理上限に変換しない。単件へZIPの1GBや任意64MiB入力制限を持ち込まない。

永続正本はrequest/compute/artifact/deliveryの4責務を分ける。本文やmanifestを本人90日履歴に複製しない。同noteのactive/stopping生成は一つ、要求者の取消は正当な兄弟へ波及させず、有効demandがなくなればabort後の実closeまでslot/予約を保持する。期限内artifactは画面離脱や容量確保のため早期evictしない。PDF24h/本人90日/匿名ticket/短期deliveryは別寿命とし、既存120秒export操作の意味を変更しない。

監督の所有不明は本人requestを`failed(PDF_OWNERSHIP_UNKNOWN)`へ確定して安全確認が必要と表示するが、computeはstopping・排他/予約/回収負債を保持する。要求の終端は物理終了の証明ではない。対象の遅いpublishは成功へ覆さず、明示retryも旧computeの所有不明を迂回しない。旧groupの確認と共通bootのfail-closedを維持し、実回復だけが物理資源を解放できる。

本人要求はaccountIdに所有させ、通常logoutや元session期限では取消さない。降格/除名/脱退ではJB-03どおり旧未終端要求を同Txの取消又は永続fenceで失効させ、再参加で復活させない。完了artifactの新しい取得は現在本人sessionとscope又は独立current-publicで認可し、過去membership喪失を永久blacklistにしない。匿名は元link/public世代とbrowserに固定し、別の公開根拠へ付け替えない。

匿名ticketは専用32B key ringのHMAC-SHA256とpurpose/binding、最大1KiBのcanonical claimsを使い、受理から固定10分とする。原authority/browser/要求世代と毎回照合し、pollや再送で延長しない。既存/s cookieと6/browser-note・30/noteの固定60秒bucketを再利用し、新明示要求の合流/cache hitも一回予約、同command照会は再予約しない。no-JS進捗は期限内の有限Refreshを第一候補とし、ready時native attachmentへ移る動作を正式匿名フェーズで実証する。未実証の自動取得を完成扱いしない。

Node adapterと固定Chrome/fontに、小さいPOSIX監督を組み合わせる。Python3のflock shimを第一候補とし、必要version/absolute executable/配備手順/self-checkを明示する。NodeだけでPythonが存在すると仮定しない。ledger/世代確定後GO、lock継承、実group終了前の新生成拒否、所有不明/壊れたledger/PID再利用時のfail-closedを維持する。未知processの自動killをしない。既存recoverWritesより前に旧PDF監督を照合し、別rootへ同storageを追加して既存writerをinactive化しない。

短期HTML/MDの2slot/2GiBを保護し、PDFのpack/作業領域・生成予約・24h実体・回収負債・native tempを共通のサービス容量管理へ明示的に含める。初期の具体値は後記の本人PDF参照設定に従う。Chrome nativeのhard RAM/CPU、OS全egress/file隔離、最大合法入力は未実証を保持する。採用するNode配備の実条件だけを確認し、未指定の全OS対応やLinux実環境を新たな自動gateにしない。配備判断で必要となる未検証条件は明示して残す。
