# P3cの方式採用

[隔離成立調査と監視補足](../phases/P3c-feasibility.md)に基づき、Node22.22.3/@libsql/client0.18.0の標準ASCII FTS5・dedup encoded1/2-gram・英数字prefixを候補索引に採用する。検索SQLはFTS起点のCROSS JOINで現在行のPK照合へ進み、正確なterm照合後にorder/keyset/LIMITを適用する。非検索一覧へjoin順固定を広げない。contentless/detailなし方式は旧tokenと意味versionを同Txの置換/削除で正しく保持できる契約として実装する。FTSの位置/phrase/highlightは使わず、本文projectionを表示/一致の正本にする。1100候補後半の真一致と819198B単体の成立値は隔離例であり、全parser/offset/同時負荷の製品合格ではない。

検索実行は内側の型付きport、HTTPが直接所有する監視専用child process、同child内query Workerへ分ける。[runtime接続案](../phases/P3c-runtime-plan.md)の簡素配置を採用する。監視child mainはDB/重いprojectionを実行せず、HTTP mainの同期writeから独立して総deadlineとIPCを監視する。query Workerはpublic transaction('read')の同connection/snapshotで現在session/account/scope・exact SQL・有限DTOを完結し、専用read DIだけを起動する。親の認可済booleanや任意SQL/DB pathを信用せず、session参照はprivate IPCのみでlog/argvへ出さない。queryごとに1child/1Workerとし、孫processは作らない。通常はWorker/client終了→child終了→HTTPのChildProcess close後に結果確定とslot解放、期限/親IPC切断はchild mainが自己process全体を終了する。native SQL中のself SIGKILLを含む実収束とWorker対応は本体冒頭で狭く確認し、未成立なら実装方式を再判断する。queue16/FIFOはHTTP内に有限保持し、active1件だけを送る。同期writeでqueue整理が遅れても残期限を再確認してexpiredをforkしない。受付/queue/startup/SQL/DTO/終了で期限をリセットせず、close未確認時は枠保持/新規拒否を維持する。child自体の異常終了も同process内Workerを含むclose確認後に回復する。通常shutdownは受付停止→検索収束→既存worker/DB終了へ接続する。既存FD方式の解除や全write処理移設は行わない。

初期値はquery trim後最大200 code point・16term、debounce250ms、note/tag page最大50、抜粋最大160 code point、calendar日内初期3件・日別追加page最大50とする。条件を黙って切り詰めず、超過は理由と再入力を案内する。calendarは日数分の集計と日別初期項目を有限に取得し、月全本文を送らない。検索資源は同時read child1・待機最大16、FIFOを初期値とし、満杯は再試行可能な混雑として返す。受付から3秒を総予算とし、終了待ちの余裕を予算内に確保する。OS schedulingを含む厳密な実時間保証や、HTTP main停止中の即時配送は保証しない。期限を過ぎても終了未確認の枠を保持し、無限retry/子増殖を防ぐ。これらは原文未指定部分を補う採用値で、正式実装の代表・異常対で確認する。

Node検索の絶対deadlineは`process.hrtime.bigint()`の同一monotonic基準を使う。実行前提は同host・同boot・同Node22.22.3・同OS clock namespaceの直接childとし、processごとのwall/timeOrigin換算を比較しない。受付時に一度決めた値を最大20桁decimalの内部wireで渡し、queue/startup/SQL/DTO/IPC/親closeまで同じ期限と100msの子終了余裕を維持する。timer用の有限残時間以外でNumber丸めを使わない。[公式sourceと保証範囲](../phases/P3c-runtime-recurrence-plan.md#公式一次資料による時計候補の補足)に従い、全OS/別host/別bootの共通epoch保証へ広げない。adapterのoptional diagnosticは有限stage/code/signal/elapsedだけを扱い、認証・query・本文・path・driver全文を記録しない。診断progressと最終結果は別kindとし、新しい永続ログや管理UIを作らない。旧式の時計差注入による構造欠陥と、元R1で実際に時計差が発生したか不明な点を分け、修正後の限定対と本体を確認する。

タグ正規化はruntimeと整合するUnicode16.0.0を採用し、同版のUnicodeData幅mapping/CaseFolding C・Fを静的に固定する。canonical normalizerの版照合は外側wiringで行い、異なる版で同名keyを無言に生成しない。日付adapterには@js-temporal/polyfill0.5.1の追加を採用する。Node/ICU/tzdataを実行識別に含め、DSTのgap/overlap/skipped dayと月境界を正式検証する。polyfill版固定をhost timezone dataの版固定と同一視しない。

構造textの非表示規則は[runtime接続案](../phases/P3c-runtime-plan.md)を採用する。hidden属性は値によらずsubtree除外し、inlineの有効display:none/content-visibility:hiddenもsubtree除外する。inline visibility:hidden/collapseは継承し、子の明示visibleで戻せるが、subtree除外は戻せない。既存CSS parserで宣言の優先度/後勝ちを解釈し、stylesheet/media/var解決/opacity/clip/位置/pseudo textを評価しない。未解決var等の有効な後続宣言が勝つpropertyはunknownとして扱い、以前のnoneだけで非表示を推定しない。これはpixel可視性ではなく固定した構造規則であり、raw属性/URL/alt/CSS sourceを検索textへ加えない。正本parser/sanitizerを変更せず、別pure projectionを隔離解析側で生成し、source identity/versionを同UoWで照合する。SQLite code point位置とJS UTF-16を分離し、NFKCの結合/展開を保つ区間対応から有限segmentを返す。

public read modeだけでは配置済local driverの書込拒否を保証しない。専用query Workerはpublic transaction('read')が保持する同connection上でtx.execute('PRAGMA query_only=ON')を行い、固定SELECTだけを実行する。このTransactionとclientをfinally closeし、通常write UoWの接続へ状態を共有しない。client.executeで別connectionへ設定する方法、private API、独自BEGIN facadeは使わない。Worker内正常read/INSERT拒否は隔離対で成立したが、全検索製品の合格とは分ける。

親生存中の取消/通常shutdownは所有ChildProcessへのkillまたは明示取消messageからcloseを待つ。child.disconnect()は製品で使わない。隔離試験では明示disconnect直後に実子はSIGKILL/ESRCHとなったが親closeが発火せず、この経路を成功としない。実親死亡は子のIPC断/自律期限で収束し、元親のclose観測とは分ける。close未確認時の枠保持は維持する。
