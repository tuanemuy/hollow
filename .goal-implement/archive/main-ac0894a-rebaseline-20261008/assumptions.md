# 採用する仮定と運用値

個別の対象指定がないため、リポジトリの Hollow 要件全体を今回の対象とする。画面案の局所的な操作やレイアウトは実装時に調整できる。技術方式の決定は実装を成立させるための作業であり、要件書の「技術設計は対象外」は上流文書の範囲を示すものとして扱う。

実行基盤はmacOS arm64上のNode参照配備とする。外部認証・メール・LLM・Drive の実接続は、利用可能な設定とアカウントを確認して検証方法を決める。秘密値は報告に記載しない。

Office の対応形式は DOCX / XLSX / PPTX とする。原文に旧 DOC / XLS / PPT の明記がないため採用した仮定で、任意確認への回答で変更できる。旧形式を無言で変換成功にせず、対応形式を画面と手順に明示する。

ノートの移動先で、移動後の使用量と予約が容量上限を超える場合は移動全体を拒否する。複数の所属先で保持する同梱素材は、各所属先に全量を一度ずつ計上する。実ファイルの共有と所属先別の使用量は分ける。原文に明記のない容量ルールを補う仮定であり、詳細は [所有と容量の設計](design.md#p3-の所有と容量の接続条件) に従う。

招待の再送は新しいリンクを発行し、旧リンクを失効させる。招待者がowner権限を失った未使用招待も失効し、残るownerが再送する。アイコンは5MiB以内のPNG/JPEG/WebPから512px以内の静止WebPを生成し、アニメーション画像は先頭フレームを使う。保存物・予約・回収待ちを所属先の容量に含める。これらは原文未指定部分の安全性・資源制限を補う仮定として採用する。

公開済みnoteの移動は新しい公開操作とみなさず、移動先handle/slug未設定でも公開状態とURLを保持する。WS slug変更で失効するのはWS公開ページのURLであり、note URLは所有namespaceから分離する。公開handle変更時もnote URLを維持することは、後述の利用者決定で確定した。

旧handleは[プロフィール画面案](../spec/design/pages/P21-settings-profile.html)の再利用可能仕様を維持する。旧URLから変更元本人へは転送せず、未割当中は404、他人が再取得した後はその別人のプロフィールを表示する。AC-07/DS-04の旧URL失効を永久予約とは解釈しない。note著者は不変のaccount IDから現在プロフィールへ結び、旧handleの再取得者へ付け替えない。設定解除と退会後の名前保持は正式実装時に確定する。

非公開・限定公開から再び公開に戻す場合も、既存のnote公開identityとURL世代を維持する。SH-04の再発行は秘密の共有tokenだけを対象とし、公開canonical URLを変更しない。現在状態による閲覧可否とURLの寿命を分ける採用解釈である。

公開handleはtrim/ASCII小文字化後3〜63文字の英数字・内部ハイフンとし、本人所有のpublic noteがある間は解除できない。bioは300 Unicode code pointsのplain textとする。個人iconは既存WSと同じ5MiB入力/512px以下static WebPの処理を使い、予約・保存物・回収待ちを個人容量へ含める。これらは原文の入力・画像・容量要件を接続する採用値であり、利用者が個別に数値指定したとは扱わない。

公開・発見は独立SSR本文、有限SQLページ、公開専用の検索実行枠/rate、有限sitemapで接続する。初期運用値と保証範囲は[公開・発見の設計](design.md#p4c-の公開発見とプロフィール)に記録する。公開本文の外部検索エンジンへの実掲載や最大規模の性能を、ローカルHTTP/ブラウザ検証だけで達成済みとは扱わない。

PDF/ZIPは現在内容と一致する生成物だけを期限内に再取得できる。内容変更や完成後の一部権限失効では旧生成物を渡さず、最新の取得可能な対象による新要求へ案内する。生成中の対象別失敗は成功分を残す。保持期間を現在認可や過去版閲覧の代わりにしないための仮定であり、原文未指定の更新後動作を補う。

PDF24時間/ZIP7日の保持は、生成物が完全保存され取得可能になった時点から数える。新exportの本人履歴90日は受理時の作成日時から数え、再試行で元親や古い子の期限を延ばさない。期限と同時刻から取得・履歴詳細表示を停止し、処理追跡や回収に必要な最小対応は別に保持する。原文未指定の起点と境界を補う仮定であり、既存jobの方式は変更しない。

検索の混合語は条件のANDとし、各条件はtitleまたは現在本文で一致すればよい。英数字は語頭、日本語は連続部分一致を維持する。検索比較とtitleの安定順は再構築可能なNFKC/小文字化projectionを使い、原文HTMLと表示名を保持する。タイトル順は読み仮名順ではなく決定的な比較keyとID順とする。混合語の分割・関連度・本文の構造上のtextという原文未指定部分は[検索共有設計](design.md#p3cの検索日付タグ共有契約)に従う。

月とcalendarはURLに利用者のIANA timezoneを固定し、共有/再訪でも同じ月集合を復元する。端末のtimezoneへ変える場合は明示操作とする。calendarで月filterを解除するとlistへ移り、scope切替では旧月を引き継がず新scopeの現在月を選ぶ。利用者timezoneと表示月を一つの条件に保つための仮定である。

タグ同名keyは幅限定変換とcanonical Unicode full case foldingを使う。全半角・大小文字は同一視するが、NFKCによる丸数字/上付き/単位記号の一律統合は加えない。trim後の表示名は保持し、50文字はUnicode code pointで数える。使用0件や無効な選択tagの扱い、後続の同名付替えは[共有設計](design.md#p3cの検索日付タグ共有契約)へ分離する。

タグ付与/解除・rename/merge/deleteは本文と独立した変更とし、本文版・更新日時・変換jobの本文guardを変えない。管理の削除影響はtrash/purgingを含む全tag関係とし、全関係0件だけを未使用cleanup対象とする。0件cleanupは表示した最大50tagの一括確認を繰り返す。移動確認後は現在権限・閲覧者/タグ対応・移管条件を再照合し、移管条件が同じで上限内なら無関係な使用量変化だけで再確認しない。これらはOR-06〜08/12の未指定部分を具体化する仮定で、詳細は[タグと単一移動設計](design.md#p3dのタグ書込管理と単一移動)に従う。

一括操作の選択は最大500の明示note IDに固定する。表示済みと絞り込み結果全体を別操作にし、後から一致したnoteを自動追加しない。適用filter/scope/zone変更で解除し、sort/layoutだけでは保持する。現在権限のない対象は件数を示し、実行できる残りを確認する。公開前提やZIP上限等の全体中止条件は維持する。これはOR-09の選択時点と許容する混在処理を具体化する仮定である。

限定共有では、private化によって既存のpassword通過状態を失効させる。同リンクを再限定してもpasswordは再入力する。発行済みリンクはprivate中も明示再発行できる。表示名が未設定の既存creatorは「表示名未設定」と表示し、限定共有を禁止せず本人の表示名設定を提供する。これらは原文未指定の復活時動作と既存プロフィール未設定を補う仮定であり、[P4a設計](design.md#p4a-の限定共有と表示名)に従う。

初回のpassword保護は非公開のまま準備できる。準備時に共有tokenを発行してもURLを表示せず、限定公開へ切り替えるまで外部閲覧は許可しない。保護を設定するために一度無保護で公開する経路を避けるUX上の仮定である。

HTML/Markdown単件は同期操作の一時fileを使い、利用者/WS保存容量には課算しない。初期運用枠は送信中を含む2操作・生成30秒・操作120秒・サービス一時disk2GiBとし、設定不足は説明する。単件へ一括ZIPの1GB制限を適用しない。Markdownはdata URI画像とsafe HTMLを同じfileに含め、これらを禁止する閲覧器の表示一致は保証しない。未指定の資源管理とportable形式を補う仮定であり、詳細は[P4b設計](design.md#p4b-のhtmlmarkdown単件書き出し)に従う。

一括公開範囲変更は現在の状態を目標へ揃える操作とし、現在認可・確認版・業務条件を通った同状態の子は「変更不要」と区別する。パスワード解除の同意は各子の確認版に束縛し、失敗子の再試行時に取り直す。本文空の公開条件違反は理由付きの子失敗として残す。公開前提不足はOR-09どおり開始を中止して設定を案内し、一覧離脱後の選択自動復元は追加しない。これらは原文未指定部分と単件/一括の違いを補う仮定であり、[接続判断](design.md#一括公開範囲変更の接続判断)に従う。

Google初回連携の追加メール確認は通常のメール確認と別目的にし、開始したbrowserでメールリンクを開き明示確認する。別browserで開いた場合は元browserで開くよう案内し、そのクリックだけで連携を完成させない。Google再認可は新しい認可フローの同一sub確認であり、毎回のGoogleパスワード入力を保証しない。初期運用値はOAuth試行10分、追加メールは親期限以下で最大10分・再送60秒、再認可proofは親期限以下で最大5分とする。利用者が指定した数値ではなく、[認証接続契約](design.md#google認証の接続契約)の安全性と再試行を具体化する仮定である。

PDFは現在snapshotの検証済み素材と固定fontから静的に生成し、動画は現在poster又は未収録の明示にする。生成/要求/保存物/配信を分け、通常logoutで本人の生成を止めず、外部権限変更では旧実行を取消して現在権限による新取得と区別する。匿名ticketは固定10分、再取得でPDF24時間を延長しない。これらは形式と寿命の未指定部分を補う仮定で、[製品接続](design.md#単件pdfの製品接続)に従う。Python3を使う場合はNodeとは別の明示配備要件とし、OS隔離やnative資源上限の未実証を隠さない。

匿名PDFの要求/配信と本人90日履歴は分離し、現在有効な需要を持つ計算/artifactだけを共用する。元共有根拠と元password grant期限を後の再通過・別公開根拠へ付け替えず、共通容量と実closeを守る。公開/共有ページの入口はログイン済みでもbrowserに束縛し、本人履歴へ追加しない。配信はprepare起点120秒・ticket・artifact・元grantの最短期限とする。ACK不明の自動再送/専用照会は設けず、元入口から明示的にやり直す。同commandのnative再送は同receiptへ冪等化する。no-JSの有限2秒Refreshと永続一回性による自動取得、その後の手動再取得を提供する。これらはEX-04の未指定部分を補う可逆的な仮定であり、[匿名PDF接続判断](design.md#匿名pdfの接続判断)に従う。

一括ZIPの1GBはdecimalの1,000,000,000 bytesとし、格納する生成後ファイルと失敗一覧の圧縮前合計に適用する。超過は成功対象だけのZIPへすり替えず、分割を案内する。圧縮後ZIPの実サイズと一時保存容量は別に検査する。再試行に必要な成功bytesだけを保持し、完成全成功の子実体は解放できる。未完成の組立失敗へ完成ZIPの7日期限を流用しない。全件除外は空ZIPの成功ではなく内訳とやり直しを案内する。これらは原文未指定の計数・保持・表示を補う仮定で、[ZIP接続判断](design.md#一括zipの接続判断)に従う。ZIP専用4GiB・全体生成1/配信2を初期運用値とし、既存6GiB区画を保護する保守的空き検査を採用する。設定合計10GiBは必要volume容量やOS硬保証ではなく、最大入力の性能と製品接続は実装検証で分けて確認する。

ZIPの期限内に正当に受理した再試行が旧親の履歴90日を跨ぐ場合、旧親のタイトルや履歴期限は延長せず、新しい試行の最小記録で進行と結果を示す。新試行の履歴はその作成から90日とし、同ID再送・照会・空の再試行で期限を延長しない。完成ZIPが期限切れになった後の新しい再試行で旧成果物を復活させない。これは原文未指定の表示と参照寿命を補う仮定であり、[ZIP接続判断](design.md#一括zipの接続判断)に従う。

本人PDFの参照配備は、明示設定したservice6GiBのうちHTML/Markdown2GiBとPDF4GiBを分け、PDF生成1・配信2、生成全体120秒/render30秒を初期値にする。出力等の予約値は[本人PDF設計](design.md#本人pdfの永続接続)に従う。これは今回の検証配備の調整可能な運用設定であり、利用者指定のノート上限やOSの資源硬保証ではない。将来本番OSは未決で、現在はmacOS arm64上のNode参照配備を検証する。

## LLM・Drive・画像・PDF

OpenRouterは専用の秘密保管・一回限り認可試行・連携世代を分離し、応答不明のcodeを自動再交換しない。月間LLM上限は利用者1人あたり30回とし、1fileの論理変換/再生成を1回、内部ページ分割を非加算とする。上限は運用設定で変更可能にする。再連携は旧変換の取消確認を表示し、新連携の成功時に旧変換をキャンセルする。月は固定UTC暦月を初期方式とし、次回resetを利用者timezoneで表示する。発注記録後の失敗/応答不明も1回に数え、送信前停止が確認できたものだけ返却する。これらは未指定の計数を補う採用仮定で、実API費用とは別である。既定モデルは契約試験用候補として採用し、実日本語品質は未検証とする。詳細は [採用する連携境界](design.md#openrouterの連携境界) に従い、資料調査を実接続成功として扱わない。

Google Driveは連携先subとbackup記録を固定し、Googleログインと独立して解除する。選択folderのserver検証と長期資格情報の秘密保管を必須とする。保存先が見つからず削除/権限喪失を区別できない場合は、利用者確認を求め、保存先の再選択・新規作成へ案内する。Web Pickerの短命browser tokenと実接続前の確認事項は [Drive連携境界](design.md#google-driveの連携境界) に従う。実API操作は許可された検証環境と同意を得てから行う。

未完成または外部での成立が不明なbackupを残して保存先を変更した場合、旧backupの同じfile IDを先に確認する。確認できなければ新保存先へ別IDのfileを自動作成せず、旧結果の確認と明示操作へ案内する。既に成功した記録の保存先を付け替えず、Google上のfileを無断で移動・削除しない。これは重複作成を避けるための未指定部分への安全側の仮定であり、重複の可能性を承認して別fileを作る追加機能は採用しない。

単画像の初期対応は静止JPEG/PNG/WebP/GIFとし、全画素を縮小・切抜きなしで向き補正/sRGB/白背景へ正規化する。生成入力は長辺4096px・16,000,000px・正規化PNG8MiB・全JSON12MiB以内とする。これらは利用者指定ではなく、提供前gateに基づく調整可能な安全側の初期値である。全画素入力は全文字認識や内容の正しさを保証せず、画像token数/モデルcontext収容の保証も加えない。画像主体/混在/順序不明PDFは下記の全頁接続で扱い、音声は未完の必須範囲に残す。詳細は[単画像接続](design.md#p5b-2b2-単画像の製品接続)に従う。

全ページPDFは、健全なstrict文字抽出が成立する場合は既text用途を維持し、正常な混在画像/順序不明等の対象外だけを全頁描画・image用途へ固定する。破損/暗号/資源超過を画像化で隠さず、原本と旧本文を保持する。初期運用値は144dpi・長辺1728px・PNG4MiB/頁・32頁・総64MiB・準備120秒・全JSON6MiBとし、無言の解像度低下/頁省略をしない。これらは小資料gateを基にした調整可能な安全側の値で、利用者が指定した最大頁数や認識品質保証ではない。

uploadは空note/jobの即時受付を維持してbackgroundでPDF用途を一度確定する。IM06の用途確認は本文lockなし・quota0の有限previewとし、本人のmodel選択と置換確認後だけ実行を受理する。previewは固定5分・note1/actor1を初期値にし、既実行枠と共有して実終了不明を期限だけで解放しない。詳細は[PDF製品接続](design.md#p5b-3a1-全ページpdfの受付分類製品接続)に従う。音声をこのPDF実装へ含めたと扱わない。
