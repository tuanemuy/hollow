## 独立コード確認

`contract.ts`、`writer.ts`、`probe.ts`、package/tsconfigを全文読んだ。契約はNode import/I/O/ambient時刻なし、writerは公開named `ZipArchive` のみを使用し、内部API/cast/anyで入口を置換しない。strict、exactOptionalPropertyTypes、noUncheckedIndexedAccess、skipLibCheck=falseの実compile成功を確認した。

- 入力と実readの双方が同 `ByteBudget` を通り、report UTF-8 78Bも合計に入る。entry宣言bytesと実read/hashを検査する。short/over/hash/小stream-limitは全体失敗で、正当な部分ZIPへの読み替えはない。
- 1sourceをopenし、そのbridge closeとsource実closeの後だけ次sourceへ進む。writerに全量buffer化はなく、probeの小fixture/reader比較だけがbufferを使う。sink writeは逐次await、partial write loopをprobeが実装する。
- `Promise.race` のrejectはcleanupへの移行だけ。finallyはabort/destroyに加えarchive/bridge close・owned source.close・consumeの終了・sink.closeを待つ。failure時は中断可能なsource/sink closeを先にscheduleしてpending I/Oを解放する。close拒否は `ZipCloseUnprovenError`/ownership retainedで通常完了にしない。
- 最終修正の `await Promise.race([consume, failed])` はfinalize解決後finish-held中の取消をcleanupへ通す。signalはclose完了まで監視し、最終signal確認後のみwriter結果を返す。probeはさらに外部abortを確認して同期renameする。これは製品publish Txの代用ではない。
- 固定compress-commons7.0.1のstream STORE実装を独立読取。local30＋descriptor16＋central46、nameは各2回UTF-8、empty extra/comment、EOCD22。通常式 `payload + Σ(92 + 2*UTF8(name)) + 22`、forceZip64の末尾56＋20=76追加を確認した。501entry・各name65535B・payload1e9までの採用前提では通常offset/sizeはZIP32内。最大metadata pure上界65712184Bは実最大名/件数生成の証明ではない。
- 最終dependency graph/noticeは個別配布物と一致。52packageの各notice本文がaudit-final連結noticeに存在し、欠落0。isarray README MITとTypeScript第三者noticeを含む最終版を採用し、初回root noticeは採用しない。これはlicense情報保持の照合で、法律助言/セキュリティ監査/製品依存採用の承認ではない。
