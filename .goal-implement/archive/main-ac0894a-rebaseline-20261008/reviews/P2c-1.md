## コードレビュー

`application/note/commitNote.ts`、`domain/note/revision.ts` と port、libSQL revision repository/schema/0007、asset repository/access、history usecase、save/style/settle、import/reference の呼出側を横断で照合した。

- 比較は最終 title/html/display.style。note.version と revisionNo/head を分離し、user の意味ある mutation だけが bounded actor 2 名を進める。metadata-only は actor を偽装せず、必要な D の concurrency 更新を維持する。
- 新 pin→current 差替→snapshot/head→20 件 prune→最後 pin 時刻は既存 caller の同一 UoW。afterCurrent の設定/台帳/job も同じ transaction。新追加の rollback は実 prune と pin 除去を通過した後に失敗させ、各 table の前後一致を検査した。
- `saveNote` の認可/競合/asset 解決、import の owner/verified/version/active job/lease、reference の generation/version/current owner/lease は共通 commit の前に残る。単に共通関数へ移したことで guard を代用していない。
- `history.ts` は保持版を server で取得し、検査 I/O 後にも現在権限・指定版・expectedVersion を確認する。復元は `reuseReferences(currentNote, oldHtml)` を使わない。small data は既存 processor/inline inspector を通し、再検査で確認した結果だけを現在 manifest に使う。
- transport の 30 秒 signal は admission/実検査/DNS に渡る。独立再実行したテストは signal を明示 abort する bounded 試験であり、本体で 30 秒放置する wall-clock 試験を実施したという意味ではない。
- `authorizedHistoryAsset` は現在 note の本人認可→指定版存在→正確な pin→ready。`isReferenced` は current=0 のまま。`mediaHttp.node.ts` は認可後に storage stat/Range を行う。history URL の正整数 parser と strict Fetch Metadata route を確認した。
- `NoteHistory`、`NoteContent`、`NoteEditor`、`editorSave`、`NoteDisplayStyle`、`notes.$noteId.index.tsx`、`hollowRevisions`/schemas を確認。用途別 `display:` / `history:` key、遅い preview の不採用、確認 version、dirty 導線、保存済み ID/退避/必須 download mode を照合した。

レビュー対象外は未変更の認証全体、全 codec、safe fetch 全 IP/socket matrix、全 5 GiB 負荷、将来 WS/C2/C3/public/export。これらを実装済みと推測したり、新しい受入条件へ増やしたりしない。

## 限界・引継ぎ

9 件の追加 DB 試験は境界の独立根拠であって、全条件を本体 UI で故障注入したものではない。GC競合の二順序は、保持中 restore→GC の正常対と deleting 確定後の拒否/rollback、および同一 resource の transaction/fence を組み合わせて評価した。OS 全 scheduler を探索していない。

metadata 欠落、認可失効、移行不整合、30秒 signal、prune 後競合の詳細は一時 DB/handler/source 根拠。全 browser/OS、全 codec/computed CSS、全外部 fetch/容量負荷、初回 POST 応答全喪失の exactly-once、storage 使用不可での再起動復元は追加実施していない。C の旧 base 付き空 CSS 不良状態の限定的移行制限も自動修復済みとはしない。

manual-test の操作・観測とコードレビュー観点を使い、Manager 指定どおり Issue 起票・実装修正・global cleanup は行わなかった。報告は Markdown の判定/証拠/未検証を分離した。全自己 test/helper exec は完了、listenerなし、HAR・Cookie・認証入力の exportなし。browser 終了直前に fetch wrapper は undefined、退避 key0。14:04:17 JST に専用 browser の両 tab を close し、コード/環境/browser 操作を停止した。

production は新 session 3249 / PID 74924 だけを起動維持。DB/storage/mailbox は上記のまま。コード固定と全旧 data 保全を確認し、Manager へ環境所有を返却する。
