公開 source の差分に、実行前に停止を要する別の製品矛盾は認定しなかった。ただし application の未実行部分を静的読解で成功へ置き換えない。

### target / 資格 / session の不変条件

`recovery.ts` は target の旧 folderEpoch と現在資格の epoch を分離し、それぞれの正規 binding で resource key を復号して memory 内で意味比較する。target locator、旧 transfer、record を新資格の ciphertext に付け替えない。current は note/original/actor/sub/folder の一致を要求し、復号失敗は false へ収束する。旧 session は exact `forJob` で 0 / 1 / 複数を区別してから旧 binding で開き、新 transfer の binding で保護する。

`backupReceivedWithinIntent` は safe integer・後退なし・全長未満を確認し、uploading に残る offset/length の範囲内だけを認める。intent がない phase は旧 received と等しい値だけを認め、terminal 化で失った intent を推測しない。Range の末尾到達だけを完成とせず、metadata の同 ID / marker / parent / length / hash 照合へ進む。

### 再所有と復旧

runner は非 terminal / closed を phase・received・intent・deadline を保持して reclaim する。queued / owner:none の入口だけに親の手動取消を適用し、開始済み reclaim まで未開始扱いに戻さない。closure は recoverable intent と session を保持し、既 maintenance / proof ACK gate を経由する。

同 ID の metadata 確認を先行し、保存 session があれば status query を chunk より前に行う。明示 retry の旧 session が明確に expired の場合だけ、同 ID で新 session を開始できる。URI がない starting / Location ACK 不明は metadata 確認で止まり、自動 start / 別 ID 作成へ進めない。現在権限・source hash/pin・folder・外部取消の既検査を維持している。

`prune` は retryOf の新 job が nonterminal、または実 owner / pin / refresh を保持するときに旧 job の物理 prune を延期する。90 日表示と実所有 / 復旧根拠の物理寿命を同一視しない。この条件の source 読解と、前節の test-order 不整合を区別する。

### initial 再受付と公開 retry

既 target が file 未割当のとき、exact target の EXISTS / NOT EXISTS で全旧行の cancelled / owner:none / received0 / session null / statusAttempts0 / readPinned0 / refreshPending0 を確認する。最新 100 行だけの陰性推測で許可しない。新 command / 新 job / retryOf null、旧 cancelled 行不変を保つ。独立 application #1〜7 はこの追加範囲を直接確認した。
