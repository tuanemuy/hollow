## 共有型と責務の具体案（編集前判断）

### 原本・prepared・dispatch

- `LlmSourceFormat` に `image`、`LlmSourceContract` に `{source:LlmSourceIdentity<'image'>; preparationVersion:3; promptVersion:2}` だけ追加する。旧2枝は同一。
- `LlmPrepareInput` の画像枝は原本bytesと上記contractだけ。media指定不可。親 `sourcePreparer` はrecipe3を専用 `NodeLlmImagePreparer` へ委譲し、旧V1/V2へ通さない。
- `LlmImagePreparedSource` は `{kind:'single-raster'; preparationVersion:3; identity:{kind:'prepared-image'; preparationVersion:3; sha256}; inputIdentity:{kind:'prepared-raster'; ordinal:0; sha256}; raster:{mimeType:'image/png'; bytes:Uint8Array; width:number; height:number}; coverage:{kind:'single-frame'; codec:'jpeg'|'png'|'webp'|'gif'; sourceWidth:number; sourceHeight:number; orientation:1|2|3|4|5|6|7|8; frames:1; fullPixels:true; resized:false; cropped:false}; normalization:'srgb-white-v1'}`。
- `segments/html/blocks/textComplete` を画像へ捏造しない。画像のnoticeは既OriginalNoticeへ成功投影する固定 `LLM_IMAGE_NORMALIZED` 一件（向き/色/白背景・認識誤り・原本確認）とする案。既Office notice型とV1mediaは不変更。
- `LlmInputIdentity` は旧prepared-segmentとprepared-raster/ordinal0のunion。DBの既input_sha256/ordinalを使い新列なし。dispatch read時は同jobのconversionをjoinしてsource/recipe/promptの合法枝からkindを復元し、prepare時もその組合せとordinalを照合する。任意のkindをDBから推測しない。
- application workerはprepared.kindで実dispatch入力を組み立てる。textは既segments、rasterは実一入力。共通のintent/response/current fence/commit順序は維持する。all-response照合はkind/ordinal/hashを照合し、PNGは再準備だけで復元、DBに保存しない。

### 固定manifest

childはPNG hashと有限metadataまでを返す。原本identityはchildへ渡さず、最終manifestは親が受信PNGをhashして構成する。JSON配列の固定順は次。

```text
["hollow.prepare",3,
 ["original",originalId,"image",sourceSha256,sourceBytes],
 "srgb-white-v1",
 [codec,sourceWidth,sourceHeight,orientation,1],
 ["image/png",width,height,pngByteLength,pngSha256],
 [true,false,false]]
```

最後はfullPixels/resized/cropped。dispatch inputは `["hollow.raster",3,manifestHash,0]` のSHA256。ハッシュは内部identityであり、raw原本/PNG/hashをログやtest差分へ出さない。decoder/encode版の変化でPNG byteが変われば既SOURCE_CHANGEDで拒否し非再送。旧documentIdentity/segmentHash/prompt1は変更しない。

### profile / generator

- `LlmModelProfile` は現text枝とimage枝のunion。image枝は既共通model/context/output/max_tokens/source/checkedAtに加えて `kind:'chat-image'; budget:{kind:'resource-only'; imageTokens:null; contextGuaranteed:false}`。画像tokenを算出しない。
- `LlmModelProfiles.inspect` は `inspect({modelId,kind:'chat-text'|'chat-image'},signal)` へ明示用途を追加する案。戻りunionのkindが要求と合うことをapplication境界でも確認する。古いinspect名をimage用へ暗黙転用しない。provider cacheは用途別キー、同じ完全catalogを共用するがtext profileをimageへcastしない。
- `LlmGenerateInput` は旧chat-text/prompt1と `{kind:'chat-image';promptVersion:2;dispatchId;credential;model:ImageProfile;instruction;input:{kind:'single-raster';mimeType:'image/png';bytes:Uint8Array;width;height}}` のunion。base64/URL/fileは内向き入力型に持たせない。
- generator adapterだけが受け取ったPNGからdata URIを生成し、固定system2とuser contentのtext→image_url一つを組み立てる。JSON全量は12MiB以下を組立後とsend直前で検査。PNG8MiB/寸法/署名を境界検査する。旧prepare(text)は同wireを維持する。
- image defaultは既採用ID `google/gemini-3.5-flash-lite` を別のversion1画像profileとして記録する。公式FAQでimage入力/text出力・context1,048,576/output65,536を再確認。ローカル採用profileの検証有効期間を確認日から30日とする案（providerの廃止日保証ではない）。期間後は完全live検査が必要。最新完全catalogの欠落/用途非対応/期限/max_tokens否定はstatic復活を禁止する。旧text defaultの期限仕様を本件で変えない。

## binary / native所有の具体案

codec拒否の有限追加code案は `LLM_IMAGE_CORRUPT` / `LLM_IMAGE_UNSUPPORTED` / `LLM_IMAGE_MULTIFRAME`。寸法/byteは既RESOURCE_LIMIT、identity不一致はSOURCE_INVALID、停止は既TIMEOUT/OWNERSHIP_UNKNOWN。container未証明を静止先頭成功にしない。
