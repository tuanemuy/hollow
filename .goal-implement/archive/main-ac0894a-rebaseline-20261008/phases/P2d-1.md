## 対象と変更

開始 HEAD は `b74a8ad0b5586dcbce301ce066ea82731a173738`、製品差分0。開始の582製品ファイルは `8dfe16a5410cbbf7d66fc271f5bd6c0e5724c44053c3b1ff18f992bb545d8aa8`。今回の製品42 pathは [明示manifest](P2d-1-product-paths.txt)。14新規ファイルを含む。管理資料・既存spec・依存・lockは製品変更対象外。

- `NoteLifecycle` は active / trashed の識別共用体。trashed は時刻・30日期限・操作IDを必須とし、永続 CHECK も同じ状態制約を持つ。purging は次段階へ残す。
- 通常の `requirePersonalNote` は本人かつ active を要求する。trash一覧・復元だけが本人専用guardを使用する。ownerなし/別人を見つからないとして扱う既存認可方式は維持する。
- trash / restore は UoW 内の専用状態遷移。version を進め、本文/title/style値/updatedAt/20版/現在参照・履歴pin/原本を保持する。初回表示判定が未終端の場合だけ interrupted に終端化し、手動style値や本文版を変更しない。
- 確認時version、処理取消同意、復元操作IDとサーバー時刻を再検査する。`now >= purgeAfter` で復元を拒否し、旧toastで新しいtrash世代を復元できない。
- queued/running の対象conversion/reference jobを同UoWで cancelled、lease/failureをnullへする。元ファイル状態・現在reference job参照も整合する。復元はjobを再開しない。遅い成功/失敗はlease・現在状態のguardで不採用となる。
- failed retry と cancelled の取り込み直しを分離する。後者は明示操作で新jobを作る。再取り込みの本文編集判定は保持head revisionの記録versionを使い、trash/restoreだけのversion進行を本文編集と誤認しない。
- 原本は attachment / GET のまま。原本の非GET応答も現在noteの認可を先に行う。active時HEADは従前どおり405、trash時は404であり、HEAD機能の追加ではない。
- 一覧所属を変える操作は親client島が optimistic / transition / error / invalidate を所有。詳細確認、同世代undo、50件ずつのmetadata pagination、残日数と復元を接続した。`/trash`だけは型付きloader bridge→直接TrashList seedとし、route-level pendingのLoadingNotesを使う。本文をloaderへ載せず、他routeのRSC/streamingは変更しない。完全削除/emptyの未接続ボタンは出さない。

補助 `p1_ui` はweb UIに限定し、DB/環境/browserは主担当のみが操作した。補助は実装後停止。spec / spec-implement / goal APIは使用していない。
