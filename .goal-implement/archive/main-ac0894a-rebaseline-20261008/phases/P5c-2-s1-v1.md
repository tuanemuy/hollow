## 製品差と永続境界

`DriveBackupRequest.cancelledAt` を同 Tx 内で一回だけ CAS 更新する。未開始は transfer `queued/owner:none`。この場合だけ子 job/transfer を cancelled にし、開始用 wake を通知する。開始済みでは transfer/job/owner/cancelGeneration を変えず abort しない。時刻やメモリの推測ではなく、claim が先に commit した場合の `checking/active` を開始境界としている（job はまだ queued の窓も含む）。

runner の親 cancelledAt 照合は既存の `queued/none` 新規 claim 入口内だけに追加した。通常 current、準備済み/再照会/閉鎖済みの扱いへ親取消条件を広げていない。後段の再開設計は未実装のままで、既存 phase を queued へ巻き戻さない。

外部 `cancelDriveBackups` は親の取消意図とは独立し、同 Tx fence と commit 後 exact abort を維持する。手動取消後の外部取消、unknown owner の遅い実 close、削除 pin 保持/解放を直接確認。手動取消後の quota は failed、close unknown は failed/UNKNOWN + pin 保持のまま、成功 record を作らない。成功時だけ既存の immutable record 経路を使う。

本人 GET の processing に `manualCancellationRequested:boolean` を追加した。UI は「未開始を取り消し、開始済みは中断せず完了を待って結果を残す」と確認前/受付後に表示する。現在 GET で意図を取得した後は二重取消ボタンを出さない。actor/route/late/unmount と mutation 後 reconcile は変更していない。
