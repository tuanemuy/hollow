## 原本200MiBと有限native入力の案

原本上限200MiBと作業memory50MiBを分離する。既SOURCE_MEMORY_BYTES50MiB/共用100MiB、LLM並列2/本人1、30分job deadlineを維持する。全原本Uint8Array化や200MiBのIPC送信はしない。

1. 同じinput leaseの下、既owned object readを64KiBずつ読み、bytes/SHAを検証して専用persistent scratchへ排他保存。seekが必要なM4Aも扱う。private directory/file・no symlink・自身の生成物だけをcleanupする。原本の保存先を変更しない。
2. ffprobeでtrack/codec/rate/channelsを有限検査し、認識対象のtrackを明示mapする。複数audio trackや対応外channelは、先頭だけを無言採用せずtyped unsupportedで全体拒否する。対象は現在受理するWAV/MP3/M4A/Ogg/FLAC。壊れたcontainer/末尾・decoder警告/不完了を正常EOFとしない。
3. FFmpegを1回最後までdecodeし、16kHz/PCM16LE/WAVへ正規化、1〜8channelを維持する案。downmixでchannelを捨てず、packet boundaryで切るのではなく整数sample frame区間を切る。frameの不足・重複・不連続・最終partial frameを拒否し、各chunkのstartFrame/frames/ordinal/bytes/hashを固定する。全準備と実native closeが成功してから最初のSTTを送る。
4. 1chunkは最大120秒かつWAV全体8MiB以下、最大512chunk、decoded PCM合計2GiB、manifest128KiBを候補とする。超過・時間切れは明示resource/timeout失敗で、部分STTや切詰め本文を採用しない。長さはdecode実frame由来、metadata durationだけでcoverageを証明しない。lossyは全decode範囲を証明するもので、元PCM同値や音声認識の完全性を主張しない。
5. scratchは原本200MiB＋PCM2GiB/実行までの有限disk負荷。chunk読取8MiB、base64JSON最大約10.7MiB＋framingで既request12MiB以下。1chunkずつ送る。body/buffer/HTTP/response/planを合わせて50MiB予約内へ収め、同時2実行を超えない。元fileが200MiB以内でもdecode負荷等を超える場合は理由付き失敗とし、無言で短縮しない。

上限値は新たな形式非対応を隠すためでなく、圧縮入力の展開と通信の総負荷を有限にする候補。最大入力・長時間・各codec・最後の区間は新実処理で測定する。上限・channelの最終採用はManagerへ委ねる。60秒upstream処理timeoutは録音60秒上限へ置換しない。

FFmpegは固定argv/no shell、非対話、threads/filter_threads1、固定local入力、format/codec/protocol whitelist。network/playlistのdemuxを許さず、MOV外部dref/absolute path読込は無効のまま維持する。[FFmpeg stream selection](https://ffmpeg.org/ffmpeg.html#Stream-selection)、[formats](https://ffmpeg.org/ffmpeg-formats.html)、[pipe protocol](https://ffmpeg.org/ffmpeg-protocols.html#pipe)。

専用audio launcher案は既native reserve→register→実exit/全pipeclose→closedと結合する。Python resource launcherが所有registerのACKを待ち、同じPIDへFFprobe/FFmpegをexecする（別孫processを作らない）。ffprobeとFFmpegは直列で、runtimeOwnershipの同時未閉鎖birth上限2は増やさない。空env/固定cwd、CPU120秒・wall120秒・最大process memory512MiBの監視、fd/file/出力上限を設定する案。Linuxのaddress-space limitとmacOSの対応limit/RSS監視の差を実測し、監視値を厳密な瞬間peak保証へ読み替えない。abort/limit時もactual child終了とpipecloseを待ち、未証明ならunknownのままlease/予算/必要fileを保持する。OS消失・signal送信・JSON結果だけをclosedとしない。正常sourceはffprobe全frameの有限集計とFFmpeg全PCM EOFを照合し、resampleの整数frame丸めを明示検査する。サンプルレートやchannelが途中で変わる入力は無言補正せず拒否する。
