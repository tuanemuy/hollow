## 実装

Google 同意キャンセルを既存 AuthFailure の `AUTH_CANCELLED` として記録する。callback は既存 state hash、browser epoch、actor/session/authVersion と期限を検証してから pending attempt を一度だけ failed にする。`access_denied` 一個かつ code なしだけをキャンセルとし、安全な固定ローカル URL `/signin?cancelled=<attempt UUID>` へ返す。state / code / provider query を公開 URL へ引き継がない。サインイン画面は同じ本人 context の永続 attempt を取得して表示し、任意 query による表示を許さない。既にサインイン中の Google 追加キャンセルも表示し、現在の session は維持する。

既存 `0032` migration は不変。新規 `0044_authentication_cancelled` は既存 INSERT / UPDATE shape triggers の failure enum だけを更新し、総数を45にする。repository literal と DTO の源となる domain literal を揃える。無効 failure、failed 後の書換、型不整合を拒否する既存制約は維持する。P10 の別 branch にある0044との番号衝突解消は Manager の統合台帳へ残る。

サインアップ / パスワード追加 / 変更 / 再設定は domain の強度条件を共用し、field に強度・確認不一致を表示して送信を抑止する。サインインの既存パスワード入力に強度条件を後付けしない。欠落 / 検索境界で除外された確認 token も無効リンクとして案内し、同じ画面に既存再送フォームを表示する。Google 解除は Drive 連携が独立して維持される説明を確認ダイアログと画面へ表示する。SIGNIN_LOCKED は待機と再設定、RESET_INVALID は再申請、PASSWORD_MISMATCH / AUTH_LAST_METHOD は対応する公開日本語文言を表示する。共通 INVALID_CREDENTIALS の公開情報規約を維持する。サインアウト確定後はトップへ着地する。

Mailer の共有ポートは変更しない。`NodeSmtpMailer` は Nodemailer 公式 SMTPConnection / MailComposer を使い、送信ごとに一つの connection を所有する。implicit TLS または必須 STARTTLS、証明書検証、既定30秒の有限 deadline、native socket close、自動再送なしを実装する。DATA 後の ACK 不明を受理成功とみなさない。concrete `stop()` は所有する送信を中断・close し、公開 Mailer へ lifecycle を追加しない。runtime は注入優先、次に明示 smtp、次に既存 local を選ぶ。起動時の設定読込は通信しない。

設定は既存 Node 鍵と同じ絶対 path / private file 600 / parent 700 / 所有者 / 非 symlink / サイズ境界で検証する。秘密値・SMTP 応答を公開エラーに含めない。production dependency `nodemailer@10.0.16`、fixture dependency `smtp-server@3.19.18` と `@types/smtp-server@3.5.13` は exact 固定。通常 suite の SMTP は専用 CA / synthetic 認証 / loopback fixture だけを使う。

公式 API 根拠: [SMTPConnection](https://nodemailer.com/extras/smtp-connection/)、[MailComposer](https://nodemailer.com/extras/mailcomposer/)、[SMTPServer](https://nodemailer.com/extras/smtp-server/)。
