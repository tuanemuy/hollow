### 入出力と所有

最大同時 source は 1。元 file handle を 4096 B ずつ読む async iterable を `Readable.from` に渡し、source 実 close と entry 処理の後にだけ次を open。sink は file handle に逐次 write、1 ms の各 write 遅延と短い部分 write の loop を持ち、fsync 後も close 完了を別に待つ。全量 buffer は検証用小 fixture の作成 / reader 照合だけで、writer 内にはない。

close-held 対は明示 stage に到達後、未 settle・owner 保持・公開 path 不在を assert してから gate を解放する。close 失敗は `ZipCloseUnprovenError` として owner を残し、probe が持つその handle だけを明示 close する。失敗を実回収済みに見せず、元 partial は残す。これは製品 worker の stopping / capacity / recovery 接続そのものではない。

`abort()` は source を drain しない公開仕様であり、それだけで close と数えない。archive / bridge close と自分の source / sink close を待つ。[Archiver API](https://www.archiverjs.com/docs/archiver/)。highWaterMark は厳密な RAM 上限ではない。[Node 22 streams](https://nodejs.org/download/release/v22.22.3/docs/api/stream.html)

### サイズと名前

同一 `ByteBudget` による manifest UTF-8 込み 1,000,000,000 B の -1 / 等号 / +1 pure 判定と、実 stream の小上限超過が成功。短読・過読・SHA 不一致は全体失敗で、partial ZIP を成功へ繰り入れない。全 1 GB は生成していない。

固定依存の stream STORE、通常 file、comment/extra なし、501 entry 以下・各 UTF-8 name 65535 B 以下・合計 payload 1 GB 以下に限る予約式は `payload + Σ(92 + 2 * UTF8(name)) + 22`。小 forceZip64 は末尾 76 B 追加。65535 B は ZIP field の表現境界であり、新たな note 業務上限ではない。今回の実 ZIP で式と実 byte が一致。解決版 compress-commons 7.0.1 の header / descriptor / empty extra source を照合した。

名前 allocator は NFC 表示、flat 禁止文字、重複と元 suffix の予約を確認。初回の manifest.json 予約は採用名と違っていたため、最終は `hollow-export-report.txt` / `HOLLOW-EXPORT-REPORT.TXT` を予約して末尾の実 report を保持する対に訂正した。manifest.json は普通の入力名の大小文字衝突対としてだけ残した。衝突 key は probe の NFC + lowercase であり、製品候補の Unicode full fold / 幅 mapping・全安全化規則の完成を主張しない。正式名前処理の共通化・表示名最大長への接続は次の製品 phase に残る。
