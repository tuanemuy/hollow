## F1: SQL が terminal local の origin 消去を許す

対象は `packages/core/src/adapters/libsql/migrations/0042_regeneration_source.sql:216`、`:258`、`:300` の 3 source_update trigger。変更例外の OLD 条件が `OLD.source_origin!='redacted'` なので、Drive だけでなく `local-original` も含む。

具体的な通過条件は旧 local/binding NULL、合法 terminal・owner closed（未所有の合法取消なら none/idle）、memory0、version+1 のまま origin を redacted/binding NULL にする更新。旧 binding NULL に対する attempt 検索は 0 件で NOT EXISTS が成立する。source/receipt の他列不変なら旧 identity guard も拒否理由にならない。この判断は公開 SQL の静的評価であり、追加 probe の実測とは称さない。

LLM/PDF repositories は access 変更を Drive→redacted に限定しているが、`repositories/regenerationRepository.ts:261` の machine `replace` は schema parse と version CAS の後、そのまま新 access を保存する。domain の redacted terminal 値は合法なため、machine は正規 repository からも当該 SQL 許可に到達する。通常 local 履歴を誤って「Drive 参照を整理済み」の origin にできる点が、S1-A/C の既採用条件に反する。

最小補正は 3 SQL 例外の OLD origin を `drive-record` に限定すること。新 INSERT redacted 拒否、terminal/consumer owner/memory/全 attempt 安全条件、version CAS、deferred FK の同 Tx 整理は維持する。machine 正規経路にも同じ遷移契約を保つ。local→Drive、Drive→別 binding、redacted→実行 source を許す変更は不要。

既 app test の local→redacted 負例は queued 行に対して行われるため、terminal 例外の過大許可を検出していない。修正候補では 3 consumer の合法 terminal local に対する直接 SQL 拒否と machine 正規 replace 拒否、合法 Drive redaction 継続を比例確認する。

## F2: consumed Drive preview の合法 source 解除口がない

`repositories/pdfPreviewRepository.ts:240` は新値 `state==='consumed'` を無条件 invalid、`:246` は現在値 consumed を無条件 false にする。既 consume は ready→consumed 専用であり、source/binding を解除する手段ではない。一方 0042 `:256–259` は consumed を安全 redaction 対象に含み、旧 `llm_pdf_preview_identity` は consumed state/jobId を不変にする。このため、正規 repository を通して consumed 履歴を維持したまま Drive binding を安全整理する保存操作が成立しない。

新 app の Drive PDF redaction 成功は cancelled 行であり、consumed の当該分岐を覆わない。実 Drive PDF の提供や full purge は後段だが、今回採用された terminal 保存契約の不足を S2 へ黙って送らない。Manager はこの 2 点を A/C の不合格理由として採用済み。

最小補正は consumed 専用の限定 source 解除 CAS を正規 port/repository に設けること（既 replace 内の狭い例外でもよい）。旧 receipt/result/jobId/owner と state を維持し、Drive→redacted/binding NULL だけ、memory0・実 consumer 終了・全 attempt 安全・期待 version 一致を要求する。正規 version+1 と整理時刻以外の receipt 内容を変更できる一般 consumed update は許さない。attempt→binding の削除を同 Tx で閉じる。旧 trigger の緩和や処理再実行は不要。

修正候補では consumed 合法解放、result/jobId/owner 改変拒否、stale version、memory/unknown/未 ACK 拒否、解除後 FK 整合を比例確認する。今回は追加 gap probe・追加 DB・製品修正を行っていない。
